# 对话 Agent：组合实际结构

`Backend.submit` 在启用 Agent 时将 `/聊` 与点名非业务普通文本交给聊天，保留完整多行；`/查`（兼容 `/问`、`/ask`）固定走本地优先查询，查询模型不开放社交回复工具；查询限制由当前子命令传入执行器，不从整条批量原文再次推断。已识别的直接业务命令、明确翻页／选择及未知斜杠插件命令保持原入口。网关另可把已许可的非点名群消息送入有界观察；后端仅在群服务与平台能力证据均有效时接纳候选，默认关闭，见 [F1](CHAT_AGENT_F1.md)。

`Backend.prepare` 通过当前群的弱引用锁串行提交聊天，锁持有到交付结束；不同群与直接查询仍可独立处理。捕获配置、校验身份、调度器排队后，`ModelRuntime.prepare_chat` 委托 `ChatAgent.run`。新循环使用 `domain/chat.py` 的人格和预算，不读取 legacy 话题卡。每次 `ModelRuntime.attempt` 沿用 UsageLedger 的 reserve/start/settle 与 ModelPermissions；提供方错误或取消仍有独立用量状态，未知 usage 不计作已知零费用。

每轮最多六次模型请求、八个本地工具操作、60 秒，含最后收束；工具顺序执行。Responses 主动路径开始前分别预留最坏输入／输出的 D 决策与 G 正文，其他路径沿用单终轮预留。预留同时受个人、群、每日及服务小时预算约束；后续检索 reserve 失败时直接消费已有终轮预留，不额外重试 HTTP。仅够 D/G 时可直接收束，不能只花掉决策费用再申请正文额度。未用预留作为 released 记录保留，不冒称已调用。最后的 D/G 均不暴露工具；原生联网也不能占掉其调用位置。超出工具额度返回 `budget_exhausted`；工具提前超时而总期限未到时返回 `tool_timeout`，利用剩余时间收束。实际 profile 的输入／输出、频率与每日额度继续生效。

开始函数循环前，还按实际 profile、工具 schema 与图像上界裁剪完整旧交流，保留当前问题及明确引用，给工具／收束留输入空间；不会裁开已开始的函数调用与结果。必要单轮内容仍超限时明确返回输入上限错误。工具结果挤占剩余输入时返回 budget_exhausted 并收束，已有结果保留。

主动候选的替换和 defer 归入同一个 opportunity：从首次候选开始固定 60 秒、最多 3 次评估，模型尝试与在途预留总计不超过 6 次、本地工具总计不超过 8 次，费用上限固定为首次机会的批准预估额。模型次数和费用复用 UsageLedger，已发生及未知费用不会因新消息重置；D/G 仍使用其中两个预留。排队消耗同一期限。发送继续要求最新观察和当前授权。迟到 ACK 计入真实送达及冷却，只在仍属于当前候选时清空其状态，不能清掉较新的观察／候选。

普通观察等待最后消息后 1.5 秒，或本轮待判断观察累计 8 秒，两者先到者启动判断；后端返回剩余等待给网关，复用现有单群定时器。每次启动后重新计等待，新消息仍取消旧候选。冷却、权限、排队及机会额度不因等待到期而绕过，因此持续刷屏仍可能没有回复。机会内后续候选按剩余费用预估，不重复申请整轮最坏费用。

同一机会内最多暂存两份已批准知识 lease，仅在检索词、知识范围、批准集合版本及能力授权代际相同且重新通过来源校验时复用。每次重新准备证据并绑定本次生成依赖；不复用决策、生成正文、网页结果、图片解释或群历史。缓存只在内存中，机会过期清理，清空观察及变更服务策略也清理；工具调用仍计入机会工具额度。

`AttemptResult.output_items` 拥有一次 Responses 输出；消息级回放一次完整 reasoning/function 序列。`ToolCall` 只表示可执行调用，新核心不按工具复制整份响应。旧单工具路径保留 `response_items` 兼容。重复 call_id 同参数不再执行、同 ID 不同参数终止；重复 provider item ID 只接受完全相同项。原始／加密 reasoning 只存在当前工具循环，不写日志或历史。

新路径复用能力查询、字段、榜单、目录、站内搜索／读取和审核知识检索，移除聊天／澄清伪工具。站内搜索可改写词，检索仍只在既有已登记来源内；区服／版本／日期和直接业务筛选校验继续执行。KnowledgeService 不可用或某个来源读取失败以局部工具结果返回，不擦掉此前有效材料。精确来源租约在生成和交付继续复核。

普通卡片、歌曲、技能与玩法资料默认使用日服，聊天中的国际服背景不再触发普通资料硬拒绝。排行榜、活动、当前卡池、公告及用户明确要求的服务器／服间比较保留实际范围；直接查询入口的既有范围校验不变。知识检索有结果但缺少回答所需字段时，Agent 可继续通过 Haneoka 的 `site_search`、`site_read` 查详情与关联，把数据和已审核规则合起来分析；缺失的知识服务也返回继续站内查证的指引。工具依据仍带来源与版本，答案附本轮实际使用的 Haneoka 来源，不把临时分析写入正式百科。

`chat_tasks.py` 提供按群与用户隔离的 `TaskContexts`。`research_task` 保存当前目标、最多两个对象的顺序、最多六项字段／知识要求与谱面难度；对象来自宿主词法解析确认的当前用户明确名称／ID、成功详情读取签发的 `entity_ref` 或有效的上一轮任务。宿主提供的 `current_entities` 只证明身份，不证明字段，已确认身份无需重复搜索详情。`read_entity_fields` 复用 `QuerySpec/QueryResult` 批量读取歌曲、卡片和 SNAP 的结构化字段，并提供两对象同名数值的差值。宿主按实际返回字段记录覆盖，缺失技能索引、Note 数据缺项或不同谱面难度不会算已完成；提前收束且仍缺项目时在本轮预算内做一次覆盖检查，继续查或明确缺项。

任务只在成功 ACK 后进入后续上下文，保存 15 分钟、最多 1024 个用户任务；每次继续只复用对象和要求，事实重新读取。更晚的轮次、清空、撤回或来源失效使旧 ACK 不能覆盖当前状态。任务累计 40 条来源后开始新记录，避免越过参与记忆的读取上限；任务不跨重启恢复。`tasks.status(scope)` 返回 waiting／partial／completed 数量和 900 秒期限，`tasks.clear(scope,user_id=None)` 清理用户或群任务。这里的 completed 表示已取得要求的证据，交付仍以独立 ACK 为准。任务建立、取消、收束和研究工具耗时写入 ChatStore 与请求诊断，仅记录动作、状态、对象／项目数量与缺项数量，不记录目标、工具参数或隐藏推理。

字段研究绑定 `current_query_view()` 实际读取的完整版本，同时捕获读取前的已发布目录版本。当前查询视图不会自行发布主目录，因此不能把“当前资料已更新、主目录尚未发布”当作同轮数据变化。后续工具仍须使用相同读取版本；主目录发布到其他完整版本时撤销本轮。版本包含记录和完整元数据，不仅是 release ID。

知识范围仅在模型判断为追问时继承：限当前发言者最近一次已送达、模型收到成功证据的知识回复，且回复仍在近期上下文、未被删除，证据租约仍有效。追问的首次知识工具调用按需返回已验证范围候选并绑定来源，模型结合候选再调用检索；即使回复正文因输入预算裁剪也可判断关联。新话题不读取候选或绑定旧证据。多范围无法确定唯一范围时不缓存。新问题独立确定范围，明确条件优先；切服时由模型结合语境判断是否比较相同日期或版本，省略的条件不自动继承。范围缺失时工具返回局部结果，由模型判断独立查询或澄清。范围缓存为进程内状态，重启后不恢复。

已送达澄清后的受限同人无 @ 接续，如成功送达且其检索证据、来源和接续许可仍有效，可更新该发言者的范围；更新前核对本轮开始时的范围未被其他轮次改变。普通主动参与、失败回执及未取得有效证据的回复不更新范围。

已取用范围后若本轮只澄清或预算耗尽，成功回执可保留原候选供下轮使用，但不延长原回复的近期窗口。当前发言者在该轮明确提出的待澄清区服与原消息一同绑定，后续省略区服时可用于校验，新明确区服优先；模型不能凭参数创建目标。原消息删除、过期或来源撤回后不可继承，并发的新范围或已清除状态不会被旧回执覆盖。

成功 site_read 的歌曲／卡／SNAP 详情可由宿主登记 EntityEvidence，供本轮后续工具继续查已读 ID；搜索候选、未读关联和模型自报证据不授予该能力。原问的明确实体、难度、条件与历史范围约束不放宽，legacy 默认空证据保持原行为；固定资料版本在后续查询、生成及发送复核。旧图可按本轮消息 ID 调用 image_read，仍受同群缓存／原作者／时效与总图数限制。

`ChatContext` 只记录本实例参与的触发消息和成功 ACK 回复。作用域是 instance/app/platform/kind/conversation；保留 message_id、可信 speaker_id、可选显示名、时间、reply_to 和 role。用户正文与名称中的 system／assistant 标签不改变 role。每群最多 48 条、24 KiB 文本、15 分钟，实例最多 1024 群／8 MiB，旧交流从头裁剪；重启从有效参与记忆恢复。月度检索和派生摘要按来源删除／到期，不建立跨群个人画像，见 [C3](CHAT_MEMORY_C3.md)。

明确换题会在当前回合过滤换题前的自动摘要和近期旧对话，显式引用仍可使用。成功 ACK 后，在同一会话和发言者的进程内续接窗口保持边界，明确回题可恢复原上下文。显式群记忆工具仍按作用域和来源权限读取，使用的原文继续参与删除传播。

`ChatStore` 在后端 state-dir 下独占 `chat-v1.sqlite3`，schema `chat/1` 且绑定实例／应用。`runs` 保存参与上下文、可见生成正文、触发类型、人格版本、模型配置版本和最终状态；`events` 保存 attempt 引用、用量状态、耗时、工具名称／结果状态／来源元数据及逐段交付。无工具参数、完整 provider JSON、密钥、隐藏推理或网页全文。普通未参与消息不进入这条链路。启动与每次触发清理 30 日到期记录，整个片段以最早源消息时间到期，重复引用不续期；SQLite secure_delete 开启。提供方费用事实仍由独立 UsageLedger 拥有。

审计库后续写入失败以有限错误日志和进程内 audit_failures 计数诊断，不中断已经结算的模型结果、ACK、许可撤销或交付收尾；实例绑定／schema 错误仍在启动时明确失败。业务查询引用从锚点的冻结展示页读取，兼容 QueryContext 与 DeliveryCursor。

最终正文恢复由 `chat_recovery.py` 单独负责：候选成功暂存后才能发布 prepared，intent 前再次确认候选存在；首回执与待投影状态原子落 Ledger，正文与依赖及投影完成标记原子落 ChatStore。审计容错不能绕过候选写入失败。重复 ACK、启动与维护可补历史但不会重发，也不复活旧接续。删除／撤权清理派生正文，投影未知保持可诊断缺口。存储版本、批准代际、期限及回退限制见 [运行说明](CHAT_AGENT_RUNBOOK.md#a0-回执恢复与批准代际)。

`Backend.apply_event` 在现有 ledger 接受 ACK 后记录逐段交付，只有当前有效、允许上下文且 success 的文本加入 ChatContext。uncertain/failure/aborted 与未发送段不进入“已说过”。发送、顺序、去重、平台被动回复槽位及现有 progress hint 均复用原链路。关闭 Agent 后旧候选不再获得发送许可。

## 协议与制品

网关／后端成对使用协议 **2.2**。`sender_name` 只作不可信显示数据；可选 attachments 保留原附件身份，原始媒体仅在短期内存。observation 不进发送账，proactive 的独立 proactive_id 区分暂缓评估，同一 HTTP 重试保持身份不变。当前能力档案为 `qq-query-chat-v6`，两端必须成对升级。`/v1/classify` 增加 `direct_chat`；接收器在权限检查后把正文叫“立希”或独立英文 taki、以及 `/聊` 的非 @消息提交为直接请求，不进入主动观察候选。查询命令优先，未知斜杠命令不接管。请求新增可选 `quoted_text`，仅携带 QQ `message_type=103` 第一段 `msg_elements.content` 的有界文字预览（4 KiB）。引用预览作为当前用户提供的材料进入聊天，不创建可信原作者、原消息身份、图片句柄或事实租约。`Plan.reply_mention` 为必需布尔值，整轮固定查询 @发送者、聊天不 @；提示、图片及文字回退共用该策略。Python 拒绝未知字段／旧协议，网关精确比较版本与能力，六次许可上限一致。组合检查器接受已知 2.2 并保留旧配对验证，未更新已安装控制器或生产策略。

引用继续使用已有 `quoted_reply` 与 reference profile 白名单合同。离线从认证协议验证了引用已参与人类消息与已 ACK 回复；QQ 实际引用字段和 profile 尚未实机核验，生产默认没有获准的 reference profile，不能把离线引用描述成已接通真实 QQ 引用。查询自动续查仅考虑查询快照；聊天历史继续按群与可信发言者保存，显式引用保持现有合同。聊天回复只去掉整条正文最后的句号，中间断句、数字、URL 与代码保留；发送前格式与 ACK 参与记忆一致。聊天工具选错区服时该读取被拒绝并以有限工具结果返回，由同一轮基于已确认材料回应或澄清；查询入口仍保留区服错误终止行为。新模块和人格源码登记到 backend_sources 摘要清单，随 Python 包发布；真实日志和开工包合成资料不入发布包。

## 可选能力接口

K1 的 `story_search(query, filters)` 返回场景 handle、片段、source_kind、source_revision、出处与可继续读取标识；`story_read(handle, before, after)` 返回同发布版本的日文交流片段、发言者、前后场景和截断状态。未知时间保持空，原文／翻译／玩家分析分层。工具由 ChatAgent 的受限 registry 注册，宿主注入范围；没有配置故事库时不注册，不宣称已有剧情全集。

运行人格只接受经独立人工确认的版本，研究稿与运行稿分离，实际版本写入审计。v0 不自动吸收群友偏好或模型推断。C2 原生联网、V1 图片与 G1 主动参与分别受绑定模型的能力证据控制；群级摘要／主动参与另用合法群服务主体及预算。费用、发送和正文生命周期分别归原账本、交付账及 ChatStore，详见 [组合入口与验证边界](CHAT_AGENT_F1.md)。

聊天首轮从查询共用的 `query_aliases.json`（或 `OURNOTES_ALIAS_FILE`）读取乐队别名快照，携带版本与 current/stale/unavailable 状态，作为仅用于理解称呼的有界参考，不另建词表副本、不改写用户原话。单字/单字母须结合乐队或活动语境；映射不证明游戏收录、活动安排、剧情或强度。未知项继续使用现有 catalog_info abbreviation 工具或澄清。下一轮刷新读取；损坏时沿用既有最后有效快照，超出 8 KiB 时只提示按需查缩写，不把过大词表塞满模型输入。
