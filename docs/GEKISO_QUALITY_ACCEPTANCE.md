改前（success）：

> 在多人激奏中可创建房间，用房间ID或好友邀请一起玩；选同一首歌后各自选难度。

## 验收边界与待确认内容

真实评测使用原 r2 的 71 篇已批准正文、同一 BGE 版本和 DeepSeek Flash（非思考模式，32768 输入／768 输出上限）。执行实际 Backend、ModelRuntime、取证、许可与账务路径；歌曲目录、身份、许可和发送 ACK 是隔离夹具，不能等同 QQ 送达验收。所有模型调用使用现有进程环境变量中的授权密钥；用量库、知识库与正式环境隔离。

`success` 只表示流程返回结果。本次逐题检查了区间排序、分数口径、主题／区服承接及缺资料处理；它不证明任意未来问法都正确。两轮入门与简化、三次 COMBO 满连问题用于观察输出稳定性。

入门正文仍有两组待确认：选曲／おまかせ／新人建议，以及 JUST 操作含义和 LUCK 抽选槽／RUSH 流程。见 [待确认正文](GEKISO_CONTENT_PENDING.md)。现有批准内容已支持建房、好友邀请、各自选难度及区间比较，不能把新增稿中的完整流程算作已上线能力；新增稿未进入本次索引。房间 SS 与个人任务的例子已在原库，不重复改写。

调试中发现并保留了召回退步、错误区服参数、零工具中断及 COMBO 自由解释偏差，分别通过词法／片段分配、受限工具选择和证据表格模板修复。改写请求另明确最近实质问题，并排除无关旧话题。

最终验收还修正了夹具：此前模拟 ACK 的消息 ID 重复，防重复门禁拒绝发布新话题，相关连续对话成绩已作废。最终前后两组均使用独立消息 ID 重跑；每次成功回复都断言发布的是本次快照，LUCK 连续简化的 focus 和跨服追问的 intl 范围也单独断言。早期 `*-model-after-results.json` 只保留作诊断，不能作为最终质量通过证据。

## 保留的门禁与兼容性

- 未批准内容不索引；内容哈希、批准修订、撤销阻断、适用区服／日期／版本、完整片段一致性仍逐次核验。两服共通要求文稿同时适用两服。
- 最多 6 段／6,000 字证据，单段仍不超过 360 字；实际新索引编码输入在 512 Token 内。标题和表格变换不修改原文及批准记录。
- 每次 HTTP 单独获取当前许可、预占／结算额度；无新增重试、提供方切换、超时放宽或额度重置。
- 只有成功 ACK 发布主题；10 分钟绝对期限、最早到期继承、内存预算、撤审后停止生成与停止上下文发布均保留。直接查询仍不调用模型。
- 只改变可重建索引和易失上下文，不变更配置／账本／批准库结构。原文件哈希与回退权威记录的比对结果保存在本地 `summary.json` 和 `rollback-revoked/*.json`。
