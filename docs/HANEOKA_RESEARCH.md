# Haneoka 迁移待研究与验收清单

范围：五批迁移 PR #48–#52。此清单区分上游合同缺口、覆盖验证和运维验收；合并可选适配器不等于启用新来源。默认仍为 Yume 主资料、Moenotes 谱面／分数表和 tracker 榜线。不得用同号 ID、相同歌曲数量或固定队伍得分代替正式关联和等价统计。

## 需要研究或向数据提供方确认

| 编号 | 问题与影响 | 需要取得的证据／完成标准 |
|---|---|---|
| R1 主资料标签 | `bestMusicTagIds` 尚无正式名称映射，得意乐曲筛选不可完整提供 | 固定 JP release 的标签 ID→实体／多语言名称合同；验证完整标签集合及引用，不猜同号乐队。完整、缺失、变更三种输入均有对拍 |
| R2 技能与成长覆盖 | 当前模板及成长转换有样本依据，尚未逐条覆盖全部卡牌和未来模板；样本相等不能概括所有效果 | 固定版本全量成员／SNAP，独立对拍 Lv.5 中日文、多效果顺序、条件／目标、累计与次数、明确空槽、最大数值与 Lv.1 取整／单位；缺第二技能不得静默漏筛。未知模板明确不完整，不补造机制 |
| R3 中文关联 | JP／intl 实体、日文原文与技能机制核对后才补文本，中文覆盖仍需完整核验 | 每项缺失或不匹配的清单及对应回退文本；验证不同服务器发布时间差异、角色／乐队／目标名称、版本变化。中文不覆盖 JP 数值，不自动翻译 |
| R4 装饰素材与版本 | CardType 图标仍访问 Yume，激奏任务图标虽在 Haneoka 但使用未固定版本路径 | Haneoka 正式素材路径和版本保证、对应身份与许可；相同输入比较布局和图像预算，缺图／坏缓存／重取均验证。不能靠删图标达成零旧源 |
| R5 四服静态映射 | 实时 `jp/tw/kr/en` 与静态 `jp/intl` 的正式关联未确认，榜线名称／图片仍为占位 | 逐服 `server→event→challenge→music→素材` 的正式映射及发布时间规则；固定静态 release，覆盖跨期、同曲多挑战、活动切换，不凭几个相同 ID 样本推断 |
| R6 原始挑战序号 | 上游当前活动 DTO 可能过滤无效项，未提供完整原序号证明；歌曲 N 暂拒绝 | 上游保留原位置／空槽或明确的原始序号与完整性合同；对拍过滤、禁用、缺项、重复歌曲和顺序变化，恢复既有歌曲 N 语义 |
| R7 分数整数精度 | 当前只接受 `0..2**53-1`；样本未越界不能证明全部未来分数安全 | 上游声明安全范围；若可越界，须提供无精度损失的十进制字符串合同，再验证解析、缓存、历史和展示。越界不能取整、截断或补零 |
| R8 榜线时间与可用性 | 既有 4 秒单次／12 秒查询预算下曾超时；长预算取样不代表运行稳定 | 四服在实际预算内的冷／热缓存、源限流、陈旧／迟到响应、时钟偏差、切期和断线恢复记录。确认 fetchedAtMs、serverTimeMs、stale 的正式含义；不以放大预算掩盖交付耗时 |
| R9 TW 分数表等价输入 | 尚无保持现行 TW 比较池及自由／激奏双榜模型的已确认合同；第4批没有新运行适配 | 按 [最小输入需求](HANEOKA_META_CONTRACT.md) 提供完整版本化统计：seeds/offSeeds、五位置 weights、三段 ranges/rangeWeights、时长／阈值／可用性、真实算法指纹、TW 集合及独立参照。固定队伍结果和原生引擎指纹不能替代；需求尚未发给开发组 |

R9 是分数表接入阻塞，不应阻塞已能独立验收的谱面。若上游明确不能提供等价输入，继续保留现有分数表来源；更换模型或移植模拟器需要另行确定产品范围。

## 不属于上游研究，但发布前仍要完成

1. **谱面覆盖与联动**：已验证样本之外继续覆盖歌曲／四难度、变速、长条、连接和边界节点；固定相同输入核对解析与图片，并检查来源署名、缺图、图片预算及失败回退。真实素材联动与 QQ 手机显示不能由离线占位图证明。
2. **按模块切换验收**：确认实际运行版本、配置选择及缓存路径，分别授权切换主资料／谱面／榜线；验证命令、筛选、分页、版本／来源变化后的续查失效。当前合并授权不代表修改生产来源配置，也不代表实际 QQ 验收已执行。
3. **更新器与旧数据兼容**：新缓存／v3 历史保持独立，旧主缓存与 v1/v2 历史不迁移。受管更新器若要求 `compatibility_review_required`，应核对关键文件指纹与正向／回退读取证据后另行完成策略审查，不能绕过保护。自动更新状态与 GitHub 合并状态分开记录。
4. **最终联网退役**：解决上述依赖并完成实际切换后，再检查冷／热缓存、详情补全、图片重取、后台刷新、四服采样、异常回退及重定向链。解除共享模块引用后才能删适配；保留数据读取兼容和上游血缘／许可。详见 [出口与退役门槛](HANEOKA_RETIREMENT.md)。

## 建议研究顺序与回传格式

先处理 R1／R4，以及 R5／R6；R2／R3 可结合固定版本全量对拍同步完成。R7／R8 向榜线提供方集中确认，R9 按现成最小输入表单独询问。谱面独立验收可并行推进，不等待统计合同。

每项回传请附：正式来源链接或数据提供方答复、固定 release／schema／内容摘要、实体与字段语义、完整样本及独立预期结果、缺失和边界行为、许可、已确认与仍未知事项。只给新结论或接口名称不足以宣布完成；需据此补代码、测试及实际验收。本文件没有替用户发送上游消息或创建上游 issue。
