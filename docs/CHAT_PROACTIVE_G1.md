# 主动参与控制器

`application/proactive_chat.py` 提供群内有界观察、候选版本、合并、取消、暂缓与本地预算。它不调用模型、发送消息、写入数据库或建立用户画像。网关／后端接线、群服务主体授权、实际费用账与平台能力验收由宿主负责。

## 宿主合同

1. 管理员批准群服务主体后，调用 `configure(scope, ProactivePolicy(...))`。`scope` 是宿主注入的群作用域 tuple；`service_subject_id` 和 `approval_ref` 必须来自真实管理配置。控制器检查字段完整，不替代宿主授权。没有启用开关、主体、批准记录或正费用上限时，不暂存消息、不发起候选。
2. 将规范化 `ChatMessage` 交给 `observe(scope, message, addressed=False, is_bot=False)`。宿主可用 `turn` 标明同话题补充、插话或已收束。明确点名时使用 `addressed=True`；显式对话从开始直到最终交付回执，须用 `set_addressed(scope, True/False)` 括住，阻止主动任务争抢。
3. 连续消息静止 1.5 秒后，调用 `candidate(scope, reserve_cost_micro=整轮已预留最坏费用)`。返回不可变 `ProactiveCandidate`，包含原发言者、冻结消息、版本、批准的群服务主体，以及 `deferred/evaluation`。同群同时只有一个活动候选。宿主通过既有总预算账本预留和结算，不将费用挂到最近发言者名下；预算无法确认时不启动。返回 `None` 时释放尚未消耗的宿主预留，不产生模型请求。
4. 同一模型读取现场，自行选择 `reply`、`skip` 或 `defer`，然后 `decide(candidate, decision, actual_cost_micro=...)`。每次候选占一次 `max_calls_per_hour` 的**参与评估次数**，包括该次的工具循环；通用 `TurnBudget` 另行限制每轮真实模型请求数量（当前至多 6 次）。传入费用必须覆盖本次所有真实请求和额外工具费用。费用未知传 `None`，保留整笔预占；后续可 `settle(candidate, actual_cost_micro=...)` 补齐。超出预占的真实费用仍记录，超过群上限后不能发送。
5. 发起调用前／工具步骤间检查 `valid(candidate)`，发送前紧接着检查 `can_send(candidate)` 及既有平台／实例策略。改变当前回答的消息、显式对话、关闭开关、变更服务主体、删除观察、到期或全局淘汰都会使旧候选失效。每份草稿绑定其候选的触发消息。
6. 只有成功平台 ACK 才调用 `delivered(candidate)`，由该回执启动群策略 `cooldown_seconds` 指定的冷却并计入每小时成功发言次数。宿主将同一群配置传给内存控制器和持久回执预算检查，普通主动参与等待也使用该值；设为 0 不追加冷却，仍保留消息合并、候选取消和各项预算。独立使用控制器时，未指定的策略值默认为 60 秒。网络发送后策略改变但随后收到成功 ACK，仍记录真实发言；此方法不是发送授权。失败／不确定发送不调用它、不自动重发。

`reply` 不要求 @ 人、问号或固定句式；`skip` 不重评同一现场；`defer` 在同版本内等待 1～5 秒，最多重评两次，每次照常占评估和费用预算。活动机会默认有效期 60 秒，明确补充触发的重评沿用原期限、费用和次数上限。`cancel(scope)` 使候选失效；`clear(scope)` 还删除观察正文，但不清空真实预算消耗。

`OURNOTES_PROACTIVE_ONE_PASS_GROUPS` 是轻量试点的可选群白名单，未设置时仅采用已配置的紧凑 Hermes 试点群，显式置空则使用两阶段，取与 `OURNOTES_PROACTIVE_LIGHTWEIGHT_GROUPS` 的交集。组内已批准的普通纯文字候选使用同一 Responses 模型一次提交决定和短正文。宿主核验目标 ID、至多两个可见前文 ID、回复方向与不超过 90 字的正文。解析失败记录模型协议错误，本轮静默结束。清空该变量并经既有流程加载环境即可恢复两阶段。显式点名、免 @ 续聊及现有受限求证路径沿用各自入口。

免点名续聊按说话内容判断。Taki 问卡名后，原发言者只补卡名也可以接着答。第三位群友直接承接公开答复时，仍使用群主动额度和冷却；在单次回复试点群，紧接已送达答复的机制或跨服追问可以查资料。检索使用本句指定的区服和从公开上下文辨认出的机制。只有附和、两人互答、已转题时退场。

普通纯文字分享可以围绕具体成果、遭遇或笑点简短接话。别人先道过喜也可以加入。两人互答、问题已经答全、自己刚说完无人接话、话题已经转走时退场。冷却和每小时上限沿用群配置。

试点群遇到可识别的公开游戏机制、技能、版本或术语，先判断群友是否在向大家开题。沿用已有专项查询，其余候选先查已审核知识；资料不足且当前模型获准联网时，只用公开关键词检索一次。区服和版本须与问题相符。网页依据在对应说法旁标注，消息末尾不列链接。对象无法从前文确定时，只在对方确实求助时问一句。搜索和最终回答继续占用本轮时间、费用和调用额度。

一次调用预留使用现有轻量正文的输入和输出上限，且不超过批准模型配置。既有机会费用上限、日内放量、调用许可和 ACK 后写入规则继续适用；暂缓由网关既有 5 秒重评触发，仍受机会剩余时间和额度约束。请求记录中 `lightweight_one_pass` 标记一次通过校验的结构化返回，最终动作以 `decision` 为准，实际发送以平台回执为准。

一次调用可以依据群友已经描述的听感或体验回应开放讨论，也可以表达自己的偏好。需要核实机制、数值或依赖未读取的素材时，仍按既有取证与观察规则处理。

单独报成绩、记进度或比较前后结果时，回复只能重复数字或高低就保持静默。群友明确分享感受、报喜或邀请大家交流时，按当前话题接话。

轻量闲聊后收到明确事实补问时，如果该机会的先前费用已结清，可以在群小时额度、日额度与放量规则允许时补足一次资料核对的预留。补问沿用原机会的期限、评估次数和模型调用次数上限。

## 内存与记录边界

启用联网时，宿主仍预留完整模型轮次上界，但搜索费用预留以本群剩余小时费用为上限，不要求整轮六次模型调用都能各做一次搜索。剩余额度不足以覆盖模型轮次时不启动；每次实际模型／搜索请求继续通过持久费用检查，不会提高群小时上限。未知费用和在途预留计入已占额度，不能靠进程重启或更换群服务主体释放。

默认每群保留最近接收的 120 条／15 分钟／256 KiB，实例观察正文总计 8 MiB；完整序列化消息大小计入字节限制。去重只保留每群最近 480 个消息标识／15 分钟。最多配置 1024 个群，不用淘汰预算状态换取新群容量。过大新消息清除不完整现场并取消旧回复。全局内存淘汰、15 分钟清扫只取消候选，不凭旧现场自动发起重评。

候选冻结快照由宿主正在执行的任务持有；宿主必须在候选失效／到期时取消任务并释放快照。控制器保留的费用票据只有 ID、作用域、版本、时间、费用和状态，没有正文，按一小时滚动窗口清扫。它不替代持久费用账：进程重启后的实例／群预算仍须由宿主账本执行。

普通主动评估将本群最近 15 分钟已保存的参与对话与本次冻结观察合并，按消息 ID 去重，合计最多 48 条／24 KiB。自己的回复只来自成功送达记录，并保留 assistant 角色；当前观察固定在末尾，通过消息 ID 和发言者 ID 定位。模型输入压缩保留最近一条已送达回复及其原消息，避免重复接旧话题；旧观察只提供背景。当前引用预览单独标为未核验材料，不能据此认领作者。已保存来源继续绑定删除校验；自然续聊携带原问题、已送达回复及窗口内有限观察。

观察、略过、暂缓和被取消候选均不得把正文写入月度记忆或触发日志。只有成功参与的 ACK 才由宿主将直接相关上下文交给 C3；未知费用和 skipped 判断照常入费用账，不能写成零。`status(scope)` 只返回计数、字节、版本、费用及开关状态，不返回观察正文。

普通主动判断还会合入同群最近 15 分钟已成功送达的 Taki 回复及其对应原话，按原消息 ID 去重，合并后仍限 48 条／24 KiB 正文。已送达回复保留 assistant 角色，当前触发消息放在最后；尚未送达的生成文本不参与合并。读取的既有材料绑定删除校验，删除后不能继续发送依赖它的回复。短时问题接续仍只使用其限定的三段材料。近期图片的自动选择范围见 [图片合同](CHAT_IMAGES_V1.md#引用与保存)。

## 主动判断诊断日志

受现有诊断开关控制，`diagnostics-v1.sqlite3` 的 `chat_events` 按请求 ID 记录上下文条数／assistant 条数、图片标记数／实际图像输入数、识图批准、图片加载结果、只读工具名称／状态、reply／skip／defer、模型调用次数、结束及送达状态。略过、失败和取消也可追踪，不依赖成功 ACK 才建立的聊天记忆。请求详情和诊断导出的 `chat_events` 提供按时间排列的记录；结合原有片段回执区分生成和实际送达。

日志只接受固定元数据字段，不保存群聊正文、附件 URL、图片字节或工具参数。沿用诊断存储的 24 小时／4096 请求上限，每请求最多 32 条聊天诊断，超限或存储失败在诊断健康状态中报告，不改变回复许可和费用账。后端已有维护循环每 60 秒检查过期请求，连同其 spans、结果及聊天诊断级联清理，无新消息时仍执行；关闭服务后在下一次启动维护时清理。

未进入正式请求的控制决定写入独立 `conversation_events`，例如名单排除、续聊关闭、窗口到期及设置保存；不为这些记录创建发送任务。该表同样保留 24 小时，实例最多 4096 条。`Diagnostics.group_events` 将其与本群请求诊断按时间合并，默认最近 50 条。控制台「交流设置」展示这些记录，请求详情展示任务设置／取消／完成数量、工具耗时及知识不足后的站内补查标记。固定状态码、计数、时长和关联 ID 便于排查，不记录模型思考过程。

## 验证范围

`tests/test_continuation.py::ProactiveControllerTests` 使用合成消息和可控时钟，覆盖多发言者、消息合并、取消、点名优先、有限暂缓、成功回执冷却、关闭后晚回执、群隔离、费用未知、超额费用、小时预算及内存／到期边界。

控制器测试不证明真实 QQ 可观察非 @ 消息或可主动发送，也不证明 Terra 判断时机与文风。

## 已接入的宿主与协议

Koishi 的原 Session 经当前平台／管理许可后向 `/v1/chat/observations` 发送协议 2.2 观察。网关收到新普通群消息时先暂停旧稿的发送资格，等待已鉴权的观察结果；@ 消息仍即时接管。`X-Taki-Turn: observation-v1` 请求附加的 `preserve` 标记，表示这次观察保留现有触发消息。旧后端省略标记时，网关按原接收代次规则处理。合并后 `/v1/chat/candidates` 带独立 proactive_id；相同 HTTP 重试幂等，暂缓重评用新 ID、同原消息及 ingress_seq，由后端观察版本再次核验。

后端依据明确的补充措辞、发言者、简短插话、收束措辞和引用预览识别可直接处理的变化。引用预览仅作话题线索。明确插话保留冻结候选，收束撤销旧候选并结束本次评估，其他有实质内容的新消息交由新候选判断。后端确认替换或收束后，立即撤回仍在等待同群准备锁或模型槽的普通旧候选。初判或生成已经发起时，旧调用结算后退出，新候选等待旧任务结清；发送授权已经授予时，受打断的机会停止换稿。迟到的成功 ACK 仍计入送达预算，失效候选的正文不进入参与历史。

轻量试点的短句点名聊天可使用入站序号连续的同群近邻纯文字，最多两条、距请求不足 60 秒。转场、缺口、收束、媒体和未记录的点名正文会截断取材。实际调用的主聊天模型须有该群的独立平台能力批准，观察服务也须处于有效批准内。当前正文和原有工具受输入硬上限约束，附加前文仍需留有容量。旁观原话仅入本轮模型请求。成功回执保存的答复携带来源标识和时间，来源删除或相关批准撤销后按依赖清理。

申请发送授权前和授权返回后，若同群新消息尚未完成分类，网关最多等 2.5 秒再复核发送资格。模型授权也等待同群分类，等待时间同时受挑战剩余有效期约束。分类完成后重新读取平台权限。成功回执与待分类消息重叠时按同一窗口判断是否写入参与历史，回执本身照常记录。

`chat_proactive_runtime.py` 组合控制器、模型绑定能力证据、群服务批准与持久费用／成功发送事实。直接业务指令不进入主动模型评估。单一 Agent 可先用只读工具，最终输出内部 reply／skip／defer 结构，正文仍由原交付链处理；略过、暂缓和故障不在群里发占位提示。网关最多再评两次，每次等待五秒，尊重模型允许的 2～5 秒暂缓。

主动观察的生成提示要求模型对照最近群友与自己已送达的发言；只把别人说过的事实、数字或观点换种说法时选择 skip，也不为接话编造情节。简短而自然的情绪反应、看法或贴合话题的交流仍可回复；用尽工具或额度进入收束时仍保留 reply／skip／defer 的选择。这是对模型的指导，实际文风和是否恰当地参与仍需真实对话验收。

每个模型请求仍单独取得原消息、实例、用户平台权限与当前群策略绑定的许可，费用使用独立群服务主体。Intent 前还复核候选版本和当前策略；成功段才建立参与记忆。真实服务 ACK 元数据约束重启后的预算，正文删除不会删费用或发送事实，见 [服务任务](CHAT_SERVICE_JOBS.md)。离线接线与当前未验证项见 [F1](CHAT_AGENT_F1.md)。

## 纯文本轻量主动接话

后端启动时读取 `OURNOTES_PROACTIVE_LIGHTWEIGHT_GROUPS`。留空时各群使用原路径，填逗号分隔的群 ID 时只选择对应群。群仍需已有主动聊天批准、有美元日上限且当前主动模型是 `gpt-6.1-terra` Responses。显式聊天、续聊和查询沿用各自入口。控制台「模型与额度 → 主动参与模型 → 主动参与限额」展示所选群的轻量状态和符合条件时的本轮预留上界，生效名单由后端启动配置管理。

轻量候选从同群最近 5 分钟的冻结观察构造至多 6 条消息，保留网关接收顺序、原消息 ID 和原发言者，当前目标固定在最后。保留相邻发言，并可用一条较早且文字关联更强的原话替换最早的相邻消息。有与该原话配对的已送达答复时，原话与答复一起占用窗口中的两条。跨发言者拉回旧原话需要两处相互分离的文字匹配。已送达的 Taki 回复须有可见来源。初判和正文共用同一批消息，输入预算裁掉原话时，对应的答复也一起移出。关联依赖可见文字，省略或改称所指时可能找不到前文。

当前消息的附件、引用、链接与明显的查证需求在候选入口跳过。明确的游戏体验可以进入初判，具体规则或卡片需求的求证仍由显式聊天处理。图片观察建立文字边界，图片缓存过期也保留该边界。初判和正文使用其后的文字，当前明显依赖图片或未核验引用时静默。图片之后独立可读的发言可以照常进入初判。正文最多 90 字，原样复读当前消息按 skip 处理。

轻量组遇到排除名单发言、未核验引用、可见入站序号跳号、网关代次变更或显式转场时建立断点。断点后的初判、正文及省略主语的事实问题只使用断点后观察及能关联到其原话的已送达回复。断点在内存保留 5 分钟，不因迟到消息或 ACK 回读较早的现场。对断点后独立出现的简短纠正或依赖「我们／你们／他们人数」的倍数比较，直接静默并记录 `proactive_context_gap`。内容完整的新发言仍可进入初判。

网关共用同群的观察和点名聊天入站序号。相邻且符合轻量文字范围的已接纳点名聊天只临时登记原消息位置，待原话和成功送达的答复在既有记忆中可读时，才按入站顺序纳入后续轻量场景。仍有未知序号时继续建立断点。

弱插话保留旧目标。其他群友单发常见笑脸或围观表情时也保留，单独出现且没有待回复话题时不启动评估。表情加正文仍按新消息处理。明显的同人补充重新取材，明确已答或收尾撤销旧目标。「等我补一句」等明确等待用语留到补充出现再评估，明确转场按新目标评估。网关继续通过 `preserve` 与 `observed` 协调，保留发送意图之前的观察版本、当前权限及来源删除检查。发送意图已开始时，迟到成功 ACK 照常记账，旧稿不会覆盖新现场；不确定发送沿用原交付处理。

脱敏诊断中的 `proactive_context_anchor`／`proactive_context_recent` 是构造的上下文条数，`lightweight_initial` 是实际初判动作，`proactive_candidate_stale` 表示申请时目标已失效。图片或引用依赖记录 `lightweight_context_required`，入站断点记录 `proactive_ingress_gap`。结合 observation、control 和 finished 事件区分上下文缺口、未完成初判及初判后失效。

判断与正文分别以实际完整出站体预检，硬输入上限分别为 16000／20000，供应商输出上限分别为 768／1024，均受已批准模型原上限约束。输入按紧凑 JSON 的 UTF-8 字节数加 4096 计算，输出包含推理用量。两份预留先落现有账本再申请第一个调用许可。正文使用独立上下文和独立许可，判断结果只选择后续动作。失败或过期时按既有规则回收未开始的预留，已开始阶段照常结算。两段调用共同受当日可用额度、发送权限和 ACK 约束。跨日待核费用归原计费日，仍在途的请求继续占用准入额度。群交流记录可查看预算检查时的日内余量。

## 用户发起交流后的免 @ 续聊

群交流设置默认开启续聊，窗口为 180 秒，可在 60～600 秒内调整。显式 @、点名或 `/聊` 的聊天成功送达后，为同群同发言者建立窗口；成功接续继续刷新窗口。回复不必以问号结尾，也不限定下一条消息，其他发言者插话不删除机会。当前轮使用普通近期聊天上下文，由模型判断新消息是否继续向 Taki 提问或交流；无关、指向别人或无法确定时跳过。

续聊使用当前用户的普通聊天模型、额度和上下文，独立于群主动参与服务开关；非 @ 观察及发送仍要求对应平台能力批准与当前消息许可。短消息使用群设置的 1～2 秒合并窗口。窗口和任务仅在内存中，重启后清空；过期、关闭续聊或相关来源删除会撤销接续。主动发言本身不建立用户发起的窗口。

已开始的用户续聊按当前发言者的接收序号保持有效，其他人的普通群消息不替换这一候选；同人新补充会撤销旧轮次并释放群锁，合并后的输入保留原句。网关通过 `X-Taki-Observation: continuation-v1` 请求观察响应中的 `continuation` 布尔标记；未协商的客户端继续接收原响应，新网关连接未提供该标记的后端时按普通观察处理。发送仍须通过平台、模型和当前群策略检查。

群「不主动搭话的用户」名单由 ModelAdmin 持久保存，按平台用户 ID 生效，备注只供管理显示。名单中的普通消息不触发主动候选、不进入主动观察材料；显式请求和已发起交流的免 @ 接续继续可用。设置更新使在途主动候选失效，用户发起的合法聊天保持独立。控制台提供最近用户选择、手动 ID 和保存后回读，修改使用版本保护以识别并发编辑。

## 网关入站元数据诊断

受鉴权管理概览的 `activity.observation_diagnostics` 保存最多 64 条、15 分钟的进程内记录，重启即清空。仅非 @ Taki 的已解码群消息产生 `decoded`；同一临时关联码的 `backend_response` 表示既有观察接口已返回协议有效的结果，`observed=false` 也能证明请求到达后端。传输或协议失败记录 `backend_error`，保留原错误处理。仅有 decoded 不能证明通过权限或已转发；没有记录也可能是没有样本、解码前过滤、到期或容量淘汰。

字段只有时间、固定事件类型／触发类型、进程随机盐生成的关联码、阶段和 observed 布尔值，不保存正文、附件、真实消息／用户／群标识或错误原文，不写日志或数据库。读取返回副本。诊断不会启用主动观察、取得模型许可或发送消息；原批准门禁完整保留。多群记录不含群标识，应在已知样本窗口核对，不据此推断具体群的流量。

非 Responses 单阶段主动决策允许完整 JSON 代码块包装和不参与执行的额外说明字段；仍须显式给出 reply/skip/defer 及对应正文／延迟，正文类型与延迟边界保持校验。解析失败记录固定诊断码，不保存失败正文。控制台请求列表和详情按已有阶段记录显示初判前跳过、暂缓、生成阶段撤回、过期、额度拦截、许可失败或 QQ 失败回执。缺少阶段记录时使用已有的通用状态。未受理的门禁仍在群交流记录查看。

OpenAI Responses 主动决策使用 strict JSON Schema，包含 participation、text、delay_seconds 三个字段；普通回复和联网搜索工具自身的回答不套用该结构。决策 text 固定为空，非 defer 的延迟为 null。主机继续校验决策协议、回复正文和延迟范围，并保留全部批准、额度和发送前检查。协议错误进入既有错误诊断，不记录失败正文。

OpenAI 主动参与分两步：结构化决策的 text 固定为空，reply 再用独立自然正文请求完成；skip/defer 不生成正文。正文请求保留批准人格、消息定位、发言者、图片与工具结果，移除决策协议。两步共用原每轮调用数、时限、群服务限额和 token 上限；工具循环为最后决策和正文留出调用位置。

进入本轮上下文的图片与其来源消息、图片读取失败状态均受裁剪保护。上下文预算紧张时先裁剪其他旧消息，不把已选图片静默丢弃后继续作答；必要内容自身超过输入上限时返回既有 `model_input_too_large` 错误，在模型调用前结束。此约束不扩大图片选择范围、授权或缓存期限。

Responses 主动聊天采用决策 D／正文 G 两阶段。D 在本地无副作用解析后才继续：仅允许 participation、text、delay_seconds 三个字段，text 必须为空，defer 延迟为 2～5 的整数，其余延迟为 null；不接受代码围栏、额外字段或决策中夹带正文。只有合法 reply 才调用 G，G 无工具且正文去空白后为 1～4000 字符时才提交参与决定；失败不发布回复。单阶段兼容格式保持原约定。

显式聊天、D 和 G 共用聊天语义规则：避免复述与无依据附和，质疑不自动成为反转事实结论的证据，不编造纠错原因，被批评后简短处理具体问题。主动选择是否参与由 D 初判，G 可在正文阶段撤回参与，显式请求仍须回答；规则不禁止自然玩笑、关心或不同观点，不增加后置评分或改写模型。离线测试验证规则接线和协议边界，实际效果另以真实模型对照验收。

## 主动加入与退场

决策与正文共享参与规则：先判断对话对象及是否存在自然加入的位置；图片、感叹、安静和冷却结束不构成开口理由。允许简短共鸣、祝贺与玩笑；不懂梗时略过。同段讨论主动加入后无人明确接话则退场；同人或同话题继续不视为回应，任何群友明确接话都可继续。该判断依赖有界近期上下文和模型语义判断，不是程序保证的逐话题次数限制，也不建立用户喜好画像。

一次调用试点判断当前发言有什么新增内容。沿用同一对象时，面向全群的新问题、新取舍或具体进展也可以接话，只回应新增的一点。已送达答复帮助识别原问题的复述、相同卡点和确认。

Responses 正文阶段仍可单独返回内部标记 `<TAKI_SKIP>` 撤回参与。宿主将其转换为既有 skip 决定，不发送标记、不计成功发言或建立参与记忆；实际模型调用费用照常结算。空白正文仍是协议错误。普通显式聊天不解释该标记。未改变原决策 JSON 合同、调用预算或模型调用次数。

主动发起时，单阶段和两阶段正文都与触发消息比较。比较前统一 Unicode 兼容形式和大小写、折叠连续空白，并去掉末尾常见句末标点。匹配时按 skip 结算，诊断使用原因码 echo。换词后的风格效果以真实模型对照验收。

主动请求的 `attempt_timing` 按尝试 ID 记录从本次调用开始到申请和取得 Hermes 工作进程、申请和取得网关许可、进入和完成 HTTP 客户端调用、尝试结束的毫秒偏移。结合相同尝试的 `transport` 查看连接与读写耗时，其中 `request_sent_ms` 是从传输开始到请求体发出的偏移。按请求 ID 对照 `reply_ready` 和网关回执可量出正文就绪到送达的时间。
