# 主动参与控制器

`application/proactive_chat.py` 提供群内有界观察、候选版本、合并、取消、暂缓与本地预算。它不调用模型、发送消息、写入数据库或建立用户画像。网关／后端接线、群服务主体授权、实际费用账与平台能力验收由宿主负责。

## 宿主合同

1. 管理员批准群服务主体后，调用 `configure(scope, ProactivePolicy(...))`。`scope` 是宿主注入的群作用域 tuple；`service_subject_id` 和 `approval_ref` 必须来自真实管理配置。控制器检查字段完整，不替代宿主授权。没有启用开关、主体、批准记录或正费用上限时，不暂存消息、不发起候选。
2. 将规范化 `ChatMessage` 交给 `observe(scope, message, addressed=False, is_bot=False)`。规则只处理去重、机器人过滤和资源约束，不筛话题或情绪。明确点名时使用 `addressed=True`；显式对话从开始直到最终交付回执，须用 `set_addressed(scope, True/False)` 括住，阻止主动任务争抢。
3. 连续消息静止 1.5 秒后，调用 `candidate(scope, reserve_cost_micro=整轮已预留最坏费用)`。返回不可变 `ProactiveCandidate`，包含原发言者、冻结消息、版本、批准的群服务主体，以及 `deferred/evaluation`。同群同时只有一个活动候选。宿主通过既有总预算账本预留和结算，不将费用挂到最近发言者名下；预算无法确认时不启动。返回 `None` 时释放尚未消耗的宿主预留，不产生模型请求。
4. 同一模型读取现场，自行选择 `reply`、`skip` 或 `defer`，然后 `decide(candidate, decision, actual_cost_micro=...)`。每次候选占一次 `max_calls_per_hour` 的**参与评估次数**，包括该次的工具循环；通用 `TurnBudget` 另行限制每轮真实模型请求数量（当前至多 6 次）。传入费用必须覆盖本次所有真实请求和额外工具费用。费用未知传 `None`，保留整笔预占；后续可 `settle(candidate, actual_cost_micro=...)` 补齐。超出预占的真实费用仍记录，超过群上限后不能发送。
5. 发起调用前／工具步骤间检查 `valid(candidate)`，发送前紧接着检查 `can_send(candidate)` 及既有平台／实例策略。新消息、显式对话、关闭开关、变更服务主体、删除观察、到期或全局淘汰都会使旧候选失效。不要把取消后的旧回复改绑到新消息发送。
6. 只有成功平台 ACK 才调用 `delivered(candidate)`，由该回执启动群策略 `cooldown_seconds` 指定的冷却并计入每小时成功发言次数。宿主将同一群配置传给内存控制器和持久回执预算检查，追问接续等待也使用该值；设为 0 不追加冷却，仍保留消息合并、候选取消和各项预算。独立使用控制器时，未指定的策略值默认为 60 秒。网络发送后策略改变但随后收到成功 ACK，仍记录真实发言；此方法不是发送授权。失败／不确定发送不调用它、不自动重发。

`reply` 不要求 @ 人、问号或固定句式；`skip` 不重评同一现场；`defer` 在同版本内等待 1～5 秒，最多重评两次，每次照常占评估和费用预算。新消息立即撤销旧版本，新的候选从新现场开始，仍受小时总预算限制。活动候选默认有效期 60 秒。`cancel(scope)` 使候选失效；`clear(scope)` 还删除观察正文，但不清空真实预算消耗。

## 内存与记录边界

启用联网时，宿主仍预留完整模型轮次上界，但搜索费用预留以本群剩余小时费用为上限，不要求整轮六次模型调用都能各做一次搜索。剩余额度不足以覆盖模型轮次时不启动；每次实际模型／搜索请求继续通过持久费用检查，不会提高群小时上限。未知费用和在途预留计入已占额度，不能靠进程重启或更换群服务主体释放。

默认每群保留最近接收的 120 条／15 分钟／256 KiB，实例观察正文总计 8 MiB；完整序列化消息大小计入字节限制。去重只保留每群最近 480 个消息标识／15 分钟。最多配置 1024 个群，不用淘汰预算状态换取新群容量。过大新消息清除不完整现场并取消旧回复。全局内存淘汰、15 分钟清扫只取消候选，不凭旧现场自动发起重评。

候选冻结快照由宿主正在执行的任务持有；宿主必须在候选失效／到期时取消任务并释放快照。控制器保留的费用票据只有 ID、作用域、版本、时间、费用和状态，没有正文，按一小时滚动窗口清扫。它不替代持久费用账：进程重启后的实例／群预算仍须由宿主账本执行。

普通主动评估将本群最近 15 分钟已保存的参与对话与本次冻结观察合并，按消息 ID 去重，合计最多 48 条／24 KiB。自己的回复只来自成功送达记录，并保留 assistant 角色；当前观察固定在末尾，通过消息 ID 和发言者 ID 定位。模型输入压缩保留最近一条已送达回复及其原消息，避免重复接旧话题；旧观察只提供背景。当前引用预览单独标为未核验材料，不能据此认领作者。已保存来源继续绑定删除校验；特殊短时追问仍只携带原提问、已送达问题和当前回答。

观察、略过、暂缓和被取消候选均不得把正文写入月度记忆或触发日志。只有成功参与的 ACK 才由宿主将直接相关上下文交给 C3；未知费用和 skipped 判断照常入费用账，不能写成零。`status(scope)` 只返回计数、字节、版本、费用及开关状态，不返回观察正文。

普通主动判断还会合入同群最近 15 分钟已成功送达的 Taki 回复及其对应原话，按原消息 ID 去重，合并后仍限 48 条／24 KiB 正文。已送达回复保留 assistant 角色，当前触发消息放在最后；尚未送达的生成文本不参与合并。读取的既有材料绑定删除校验，删除后不能继续发送依赖它的回复。短时问题接续仍只使用其限定的三段材料。近期图片的自动选择范围见 [图片合同](CHAT_IMAGES_V1.md#引用与保存)。

## 主动判断诊断日志

受现有诊断开关控制，`diagnostics-v1.sqlite3` 的 `chat_events` 按请求 ID 记录上下文条数／assistant 条数、图片标记数／实际图像输入数、识图批准、图片加载结果、只读工具名称／状态、reply／skip／defer、模型调用次数、结束及送达状态。略过、失败和取消也可追踪，不依赖成功 ACK 才建立的聊天记忆。请求详情和诊断导出的 `chat_events` 提供按时间排列的记录；结合原有片段回执区分生成和实际送达。

日志只接受固定元数据字段，不保存群聊正文、附件 URL、图片字节或工具参数。沿用诊断存储的 24 小时／4096 请求上限，每请求最多 32 条聊天诊断，超限或存储失败在诊断健康状态中报告，不改变回复许可和费用账。后端已有维护循环每 60 秒检查过期请求，连同其 spans、结果及聊天诊断级联清理，无新消息时仍执行；关闭服务后在下一次启动维护时清理。

## 验证范围

`tests/test_continuation.py::ProactiveControllerTests` 使用合成消息和可控时钟，覆盖多发言者、消息合并、取消、点名优先、有限暂缓、成功回执冷却、关闭后晚回执、群隔离、费用未知、超额费用、小时预算及内存／到期边界。

控制器测试不证明真实 QQ 可观察非 @ 消息或可主动发送，也不证明 Terra 判断时机与文风。

## 已接入的宿主与协议

Koishi 的原 Session 经当前平台／管理许可后向 `/v1/chat/observations` 发送协议 2.2 观察；后端未批准时返回 observed=false。网关只保留每群最新的有界候选定时器，新原始消息到达即撤销旧发送代次。合并后 `/v1/chat/candidates` 带独立 proactive_id；相同 HTTP 重试幂等，暂缓重评用新 ID、同原消息及 ingress_seq，由后端观察版本再次核验。

`chat_proactive_runtime.py` 组合控制器、模型绑定能力证据、群服务批准与持久费用／成功发送事实。直接业务指令不进入主动模型评估。单一 Agent 可先用只读工具，最终输出内部 reply／skip／defer 结构，正文仍由原交付链处理；略过、暂缓和故障不在群里发占位提示。网关最多再评两次，每次等待五秒，尊重模型允许的 2～5 秒暂缓。

主动观察的生成提示要求模型对照最近群友与自己已送达的发言；只把别人说过的事实、数字或观点换种说法时选择 skip，也不为接话编造情节。简短而自然的情绪反应、看法或贴合话题的交流仍可回复；用尽工具或额度进入收束时仍保留 reply／skip／defer 的选择。这是对模型的指导，实际文风和是否恰当地参与仍需真实对话验收。

每个模型请求仍单独取得原消息、实例、用户平台权限与当前群策略绑定的许可，费用使用独立群服务主体。Intent 前还复核候选版本和当前策略；成功段才建立参与记忆。真实服务 ACK 元数据约束重启后的预算，正文删除不会删费用或发送事实，见 [服务任务](CHAT_SERVICE_JOBS.md)。离线接线与当前未验证项见 [F1](CHAT_AGENT_F1.md)。

## 已送达问题的短时接续

在主动参与能力和群服务已批准时，单段点名聊天以问号结束且成功 ACK 后，在内存中保留最多 120 秒的接续机会。网关在收到发送回执时记录同群接收序号；只有该时没有插话、随后同群原发言者的第一条已许可观察才可能匹配。对比两个 QQ 消息时间时要求回答严格晚于原始提问，秒精度下同秒消息会保守跳过；不比较 QQ 时间与后端时钟。其他群和私聊不改变同群序号。其他消息、直接请求、过期或来源删除使机会失效。

仅原始提问、已送达问题和候选回答进入本轮上下文，模型判断关联不明确时跳过；发送仍受现有主动参与审批、冷却、预算、候选版本和平台权限约束。如果现有冷却能在窗口内结束，网关保持有界定时器并在冷却结束后重新检查；冷却过长则放弃，不能保证每条回答都会接续。候选略过不写入对话记忆；成功送达只保存本次参与材料，不持久保存观察窗口。计时器主动清除闲置机会，后端发现服务或能力禁用时及删除对话时也会清除；重启丢弃机会。网关本地开关或平台权限关闭不会立即通知后端清除，其正文至多留到 120 秒计时到期，但发送前仍会重新检查权限。主动发言和多段回复不创建机会。送达可见但发送回执尚未到达时的回答也可能保守跳过；真实 QQ 非点名接收、发送、回执时序和模型判断仍须单独验收。

## 网关入站元数据诊断

受鉴权管理概览的 `activity.observation_diagnostics` 保存最多 64 条、15 分钟的进程内记录，重启即清空。仅非 @ Taki 的已解码群消息产生 `decoded`；同一临时关联码的 `backend_response` 表示既有观察接口已返回协议有效的结果，`observed=false` 也能证明请求到达后端。传输或协议失败记录 `backend_error`，保留原错误处理。仅有 decoded 不能证明通过权限或已转发；没有记录也可能是没有样本、解码前过滤、到期或容量淘汰。

字段只有时间、固定事件类型／触发类型、进程随机盐生成的关联码、阶段和 observed 布尔值，不保存正文、附件、真实消息／用户／群标识或错误原文，不写日志或数据库。读取返回副本。诊断不会启用主动观察、取得模型许可或发送消息；原批准门禁完整保留。多群记录不含群标识，应在已知样本窗口核对，不据此推断具体群的流量。

主动决策允许完整 JSON 代码块包装和不参与执行的额外说明字段；仍须显式给出 reply/skip/defer 及对应正文／延迟，正文类型与延迟边界保持校验。解析失败记录固定诊断码，不保存失败正文。控制台将有错误诊断的零输出请求标为“主动评估失败”，与正常无输出分开。

OpenAI Responses 主动决策使用 strict JSON Schema，包含 participation、text、delay_seconds 三个字段；普通回复和联网搜索工具自身的回答不套用该结构。text 只承载发给群友的自然正文；skip 可用空字符串，非 defer 的延迟为 null。主机继续校验回复正文和延迟范围，并保留全部批准、额度和发送前检查。解析失败额外记录固定形态分类（fenced/object/other）和语法错误类型，不记录正文。

OpenAI 主动参与分两步：结构化决策的 text 固定为空，reply 再用独立自然正文请求完成；skip/defer 不生成正文。正文请求保留批准人格、消息定位、发言者、图片与工具结果，移除决策协议。两步共用原每轮调用数、时限、群服务限额和 token 上限；工具循环为最后决策和正文留出调用位置。
