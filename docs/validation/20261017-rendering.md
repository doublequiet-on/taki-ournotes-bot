## 基线与完整性

现有画廊扩展至 130 个样例，另有只读旧快照的原素材对照。观察旧 `_bytes` 与新编码入口，记录原画布、编码尝试、实际输出页、文字位置、记录顺序、重复展示位置、布局范围和来源状态。记录输入、Python/Pillow、实际绘制字体与素材哈希，不另行分发字体。

视觉取证与性能运行分开。130 例各三次独立进程，共 390 次基线测量；采用 c467ca2 的冻结源码归档，以文件哈希追溯，未将父 checkout 的后续 HEAD 记作归档版本。初版全画廊 manifest 早于观察辅助文件哈希字段；最终冻结基准与原素材对照 manifest 已包含该字段，初版缺项在 JSON 中明确保留为空。

## 同画布编码

两例原素材 PNG 解码后与原画布逐像素一致。谱面 JPEG 2,705,577 bytes → PNG 914,825 bytes；歌曲详情 JPEG 328,300 → PNG 331,688 bytes。PNG 超预算后使用原 JPEG 序列的回归，输出与直接旧策略字节相同。模拟上传保留原字节及原请求字段，没有新增 MIME 请求字段。

Windows / Python 3.12.0 / Pillow 12.3.0；每例独立进程三次，计时不保存原画布。峰值为操作系统 PeakWorkingSetSize。

| 策略／固定样例 | 总秒中位数（范围） | 编码秒中位数 | 峰值 MiB 中位数（范围） |
|---|---:|---:|---:|
| JPEG 谱面 | 0.8816（0.8381–0.9526） | 0.1820 | 306.69（306.65–307.42） |
| PNG 谱面 | 1.1655（1.1512–1.1660） | 0.4301 | 267.46（267.38–267.84） |
| JPEG 歌曲详情 | 0.3722（0.3711–0.3762） | 0.0236 | 106.52（106.21–106.62） |
| PNG 歌曲详情 | 0.3813（0.3714–0.4030） | 0.0498 | 106.05（106.02–106.26） |

PNG 对谱面节省字节，但本机编码更慢；歌曲详情略大，因此不设为默认。

## 唯一热点：同次歌曲列表的重复素材

分阶段记录与 cProfile 指向素材准备的重复读取。仅在同次绘制内按 URL／尺寸复用重复封面和属性图；唯一素材仍立即释放，复用素材在成功／失败退出时释放。没有跨请求整图缓存或缓存格式变化。

固定输入为 17 个合成显示位置（ID 0–16、完整编号），共享本地已有的同一原封面，标题／乐队为声明的边界文字。基准经过现有 `load_visual_asset` 入口调用只读素材夹具并禁网；每次独立进程，按旧／新、新／旧交错五组；原画布取证另跑。实现源文件哈希与测量候选哈希一致。

- 素材加载 17 → 1 次。
- 总耗时中位数 0.4476 → 0.2414 秒（该输入约改善 46%）；旧范围 0.4349–0.4665，新范围 0.2299–0.2632 秒。
- 素材准备中位数 0.3443 → 0.1451 秒。
- 进程峰值中位数 95,793,152 → 95,297,536 bytes；最大值 95,973,376 → 95,371,264 bytes，未增加。
- 五组输出字节一致；另跑原画布摘要一致。测试覆盖跨查询不复用、唯一素材及时释放、缺素材、预算重试复用与失败释放。

此比例仅对应固定重复素材输入。目标服务器资源、真实 QQ PNG 格式兼容、缺素材模板正式验收仍待独立验证。
