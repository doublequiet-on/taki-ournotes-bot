# 聊天取证离线基线

基线为 `e72eb9cbe1557966e8121034c6aca870d1f5cf2d`。开发题及判据见 [cases.json](cases.json) 和 [probes.py](probes.py)。独立保留题由评测方在本地冻结。代码评测与资料整理使用不同题集，保留题仅由本地模拟模型驱动读取，Git、PR 和资料维护方只收到汇总。

## 来源、预算与预期

每个版本运行同一份 20 条开发案例和独立的 8 条保留案例，各一次。三项需真实材料或模型的开发题登记为无法判定。每次都从空的临时状态开始。相同问题与脚本应答、场景、批准记录、异常注入点及判据保持固定。外部模型、QQ、网络检索总预算均为零。显式聊天沿用基线的单轮上限（6 次模拟模型调用、8 个工具操作、60 秒含最后 5 秒收束），多轮合同按其既定轮数运行。模拟 profile 默认输入 32,768、输出 768 token；已有曲目对比夹具将输入设为 65,536。规则探针每题检索一次，上限 6 块、6,000 字符。真实短样本一次检索（最多 3 个候选）和一次读回。脚本模型的用量值只供账本流程使用。

## 复跑与对照

在本评测工作树中，以项目现有 Python 环境执行。评测脚本始终从自身工作树加载冻结夹具，`--repo` 只切换被测源码。输出文件应保存在对应评测方的目录。

```powershell
$driver = 'docs/validation/rag-routing/run.py'
python -I -B $driver --repo . --official-sample runtime/official-summary.json --output runtime/dev-A.json
python -I -B $driver --repo ../candidate --official-sample runtime/official-summary.json --compare runtime/dev-A.json --output runtime/dev-B.json
```

A 的源码需为基线或仅含本评测产物的提交。真实样本使用项目已有的 `runtime/story-real-sample.json` 本地副本，可把参数指向原文件。省略该参数时 D16 记为无法判定。保留题用同一脚本另加 `--cases <本地题集>`，输出和差异均仅留在评测方本地。每份报告记录被测提交、评测器及题集指纹和逐题结果。断言不满足记为失败，缺材料、运行错误或明确留待实测的项目记为无法判定。命令写完报告即成功退出；各项行为见 `cases`，计划内的基线失败也要保留。

本机复跑使用工作树内的 `runtime/eval-venv/Scripts/python.exe`，从两个已有 Taki 开发环境只读加载项目依赖。实际 Python 与依赖版本见报告的 `conditions`。Windows 上 asyncio 的内部 socketpair 需要本机回环；驱动允许标准库创建该通道，阻止评测中的外部网络请求。首次验证因沙箱回环受阻、默认环境缺少 httpx 未能运行聊天夹具，修正环境后使用相同题目与判据重新执行。正式记录见[结果与迁移边界](RESULTS.md)。
