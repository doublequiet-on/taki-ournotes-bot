# 查询规格与入口差异

原始规格基线为 `86075410adf75c65ecece7b7a946dab51571d5a1`；自然语言扩展在 `941de15` 基础上更新，详见 [ON 词法与模型字段](ON_LANGUAGE.md)，面向维护者和后续查询开发。描述代码能力，不表示生产已部署、来源此刻完整或真实模型准确率。固定样例使用合成数据或仓库夹具，不把样例 ID、等级和颜色当成游戏事实。

## 入口、结果与证据

直接命令由 `commands.resolve_command` 捕获 `CommandResult`，`handle_command` 及绘图消费同份选择。`/问` 经 `AIQueryParser` → `QueryAgent.run`，依次处理本地榜线、字段短答、缓存、明确命令和本地语法；剩余问题才可能交给模型路由、参数校验与 `structured_query.resolve_query`。`QuerySpec` 是执行条件，`QueryResult` 保留完整集合及专项结果。分页不是筛选，统计数量不得使用当前页长度。

下表“本地”指有固定语法支持，不承诺任意同义句。“命令转交”指 `/问 查卡 …` 等被 `_DIRECT_COMMAND` 接受的明确命令；不等于自然语言已开放。模型列只描述 `query_capabilities.CAPABILITIES`、`query_validation` 实际暴露的参数，不能把 `card_query` / `song_query` 本地通道当成模型自由字符串入口。

| 业务 | 直接入口 | 本地 `/问` | 模型辅助 `/问` | 源码 / 现有测试 |
|---|---|---|---|---|
| 歌曲 | `/查曲`，兼容别名见 `commands.ALIASES` | 名称/乐队、等级比较；颜色/激奏专用语法 | `song.search`：单一对象、等级等值/单边界、难度、颜色、激奏组合、页码 | `query/song_query.py`、`song_conditions.py`、`test_song_traits.py` |
| 谱面 | `/查谱面 歌曲 [难度]` | 歌曲谱面问法及字段短答 | `chart.get`：歌曲、难度 | `structured_query.chart_for`、`test_query_correctness.py`、`test_chart_data.py` |
| 成员卡 | `/查卡`、`/查角色卡`、`/查卡面 ID` | 角色/乐队/卡、稀有度、技能；显式颜色、分类、多选及 BD | `member_card.search`：对象、多选稀有度/颜色、LIVE/击奏分类、得意标签、技能词/类型、页码 | `query/card_catalog.py`、`test_card_catalog.py`、`test_natural_query_eval.py` |
| SNAP | `/查留影卡`、`/查支援卡`、`/查snap`、`/查留影卡面 ID` | 角色、稀有度；显式颜色、分类、多选及 EX | `support_card.search`：对象、多选稀有度/颜色、LIVE/击奏分类、页码；不开放任意技能关键词 | 同上，另见 `test_support_data.py` |
| 活动 | `/查活动`、`event`、`イベント` | 当前/历史/列表/详情固定口语和明确命令转交 | 未注册 | `query/activity_query.py`、`test_info_queries.py` |
| 卡池 | `/查卡池` | 当前/历史/详情固定口语和中文命令转交；英文 `gacha` 仍非入口 | 未注册 | `query/gacha_query.py`、`test_info_command_pipeline.py` |
| 人物 | `/查角色` | 人物资料/生日/乐队成员固定口语和明确命令转交 | 未注册 | `query/character_query.py`、`test_info_queries.py` |
| 歌曲榜线 | `/查榜线`、`/榜线` | `parse_natural_cutoff`，含服别/活动/歌曲/排名 | 保持本地，不调用模型 | `query/event_cutoff_query.py`、`test_cutoff_query_v2.py`、`test_cutoff_archive.py` |
| 短答/数量 | 相应命令显示资料；短答入口是 `/问` | `parse_field_question` | 无 `field` 模型参数 | `query/field_query.py`、`test_field_queries.py` |
| 别名 | `/查缩写` | 实体解析使用同一词库；不等于反查别名功能 | 只允许已核实对象 | `query/entity_lexicon.py`、`test_ai_lexicon.py` |
| 续查 | `/继续`、选择和详情语法 | 平台持有已发送上下文；脱离上下文时代理拒绝 | 不开放自由修改条件 | `query/continuation.py`、`test_continuation.py` |

状态不是跨层同名枚举：信息查询 `InfoAnswer` 可以返回 `no_results`，`QueryAgent` 在信息转交边界映射为 `empty`；代理使用 `OutcomeCode`。合法空集、未知实体、歧义、缺资料和无效参数须分别记录。卡牌解析错误当前统一进入 `invalid_arguments`，不能宣称每个入口都已细分未知实体。

## 歌曲与谱面字段

默认来源为 Haneoka JP；多语言名称来自同一来源快照的 JP/intl 文档，intl 文本不把日服歌曲变成其他服记录。显式旧来源配置的能力以实际记录为准。歌曲条件由 `SongFilter` 表达；普通名称查询另有兼容路径，不能假定所有入口使用同一语法。

| 用户字段 → 内部字段 | 类型、默认与组合 | 展示 / 筛选 / 排序 | 可复现写法与边界 |
|---|---|---|---|
| 名称/ID → `term`，旧结构化 `subject` | 文本；可用原名、多语言名、已确认别名及 ID；空表示全部。名称匹配由 `song_identity`、`_song_name_matches` 决定；歧义谱面必须选择 | 是 / 是 / 无用户排序参数 | `/查曲 迷星叫`；名称本身含 EX、数字时先保护完整实体 |
| 乐队 → `band` / `subject(kind=band)` | 单乐队；跨维度 AND。显式 `乐队=`须核实，未知不能忽略 | 是 / 是 / 无 | `/查曲 乐队=MyGO` |
| 颜色 → `colors` | 红/蓝/绿/黄/紫，对应来源颜色码；默认不限；同条件 `/`、`,`、`或` 为 OR，多个独立颜色条件拒绝 | 是 / 是 / 无 | `/查曲 颜色=蓝/绿`；黑色不支持 |
| 激奏 → `mode`、`missions` | JUST/COMBO/LUCK；默认不限。单类型 contains、纯 pure、混合 mixed、包含全部 all、斜杠 exact | 是 / 是 / 无 | `激奏=JUST` 包含；`纯JUST` 全为 JUST；`混合` 至少两种；`包含全部JUST/COMBO` 不要求顺序；`JUST/JUST/COMBO` 严格保留顺序与重复 |
| 难度 → `difficulty` | EASY/NORMAL/HARD/EXPERT，兼容 EZ/NM/HD/EX；歌曲筛选另支持 ALL/全难度。默认未指定 | 是 / 是 / 无 | `/查曲 蓝色 EX lv<=25`；EX 在此为 EXPERT |
| 等级 → `comparison`、`level`、`integer_level` | 数值 1～40；一次一个 `= > >= < <=`；默认无条件。`lv25` 按整级 `Chart.level` 等值，`lv25.0` 按 `display_level` 精确等值 | 是 / 是 / 无 | `lv25` 可含显示 25.5 的整级 25 谱面；`lv25.0` 不含它 |
| 页码 → `page` | 正整数，默认 1；完整结果保留，文字按页输出，超范围提示 | 页码 / 非业务筛选 / 无 | `/查曲 蓝色 页2`；不得因翻页改变筛选条件 |

等级比较：未指定难度或 ALL 的**范围比较**按最难谱面判断；等值是任一适用谱面匹配。显式难度只比较该难度。`song.search` 模型支持 `eq/gte/gt/lte/lt`、四种难度及 ALL、颜色数组、激奏模式和序列、整级标记；不开放双边界或排除，所有条件须由原文词法核实。本地歌曲语法见 `song_query.local_query` 与 `local_query.local_song_filter`，不能把模型目录的限制误写成直接命令限制。

缺颜色/激奏时：部分未知歌曲排除并附覆盖提示；候选全部缺所需字段返回 `data_unavailable`；未知名称返回 `unknown_entity`，完整条件交集为空是 `empty`。带缺失提示的数量是“已确认匹配”，不是完整总量。默认结果顺序沿来源/检索路径，不承诺跨版本稳定排序。

谱面必须唯一歌曲；不填难度保留已收录的全部难度，不默认为 EXPERT。等级/Note 短答读取元数据；完整音符图另外依赖完整谱面来源。缺音符不能从 Note 总数补造。Note 未获取与零严格区分。完整谱面按已有图像预算拆分长图及续发；本轮不改画法。歌曲/谱面没有按 Note 数、作者、上线日期等展示字段筛选或排序的接口。

## 成员卡与 SNAP 字段

`CardRequest` 保存 `support/mode/card_id/page/query/filters`；`CardAnswer.cards` 是完整结果，`visible` 为每页 16 张。默认列表，稀有度降序、ID 升序，用户不能指定其他排序。纯 ID 及明确数字 ID 进详情；卡名或其他条件即使只命中一张仍为列表。独立卡面必须给 ID。

| 用户字段 → `filters` 键 | 值、默认和组合 | 适用与入口差异 |
|---|---|---|
| 角色 → `character` | 已核实角色/昵称；默认不限，同维度 OR | 两类卡均可；SNAP 多人参与关系，不按拼接展示名推断 |
| 乐队 → `band` | 已核实乐队/简称；默认不限，同维度 OR | 两类卡；SNAP 按关联乐队；模型入口仍受能力与实体校验限制 |
| 卡名 → `title_ids` | 精确原名/多语言名/人工别名解析为 ID 集；默认不限 | 各实体类别隔离；不默认拥有角色查询的全部模糊匹配规则 |
| 稀有度 → `rarity` | R=2、SR=3、SSR=4；成员另有 BD=20，SNAP 另有 EX=10；默认不限，多选 OR | 两类不得互换 BD/EX；模型使用 `rarities` 数组多选；旧 `rarity` 参数保留 2/3/4/null |
| 颜色 → `type` | 红1/蓝2/绿3/黄4/紫5；默认不限，多选 OR | 直接、本地口语和模型 `colors` 数组支持 |
| LIVE → `live` | 分数提升 `score`、LIFE回复 `life`、判定强化 `judgement`；SNAP 另有技能延长 `duration`；默认不限，多选 OR | 成员卡拒绝技能延长；SNAP EX 可有两项 LIVE 支援，不合并成一个臆造技能 |
| 激奏/击奏 → `gekisou` | JUST/COMBO/LUCK；默认不限，多选 OR | 依来源分类；SNAP 的 `not_applicable` 是不适用，不是未知或可按 JUST 命中 |
| 得意 → `tags` | 来源标签或核实的乐队标签；多个标签要求**全部包含** | 成员专属；SNAP 明确拒绝；模型使用来源标签 ID 数组并校验原文 |
| 技能词/类型 → `skill_query/skill_kind` | `leader/live/gekisou`，词须来自原句；在技能名称、描述及多语言文案中匹配 | 结构化成员技能查询独立于 `CardRequest` 分类；本地及模型成员能力支持，不能泛化成 SNAP 任意技能反查 |

显式字段接受 `=`、`:`、`：`；值按解析器支持的多选分隔符拆分（`/`、`,`、`，`、`、`、`|`、`或`）。跨字段 AND。未知颜色、角色、分类或不适用维度不得静默丢弃。候选记录缺少相关索引时返回 `data_unavailable`，不能只返回已知子集冒充完整卡牌筛选。卡牌 ID 不当作星级。

名称、颜色、稀有度、LIVE/激奏、得意可展示且可按上述范围筛选；属性数值、技能具体百分比、图片、上线日期等可展示不代表可筛选/排序。SNAP 百分比属性不与成员卡数值混用。

## 活动、卡池与人物

三者通过 `capture_catalog()` 使用同一份资料和关联卡，信息图/文字来自同一 `InfoAnswer.views`。缺某资源的可用标记为 `data_unavailable`；合法无记录为 `no_results`，对外由命令适配。时间显示与数据时间区分，静态日服资料按 UTC+9 显示，测试固定 `now`。

| 业务字段 | 值、默认、组合和边界 | 展示 / 筛选 / 排序 |
|---|---|---|
| 活动 `server` | 首参数 jp/hk/kr/en 及 `SERVER_ALIASES`；默认 jp，hk 内部 tw | 是 / 是 / 否 |
| 活动当前/最近 | 无参数、当前、最近共用来源当前/最近活动接口；不是按本机时间推断“最终活动” | 是 / 选择模式 / 否 |
| 活动列表/历史/名称/ID | JP 支持列表/全部、历史 `[名称]`、ID/名称；历史 `end_at <= now`；其他服拒绝静态历史查询 | 是 / 是 / 固定开始时间倒序、ID倒序，缺时间靠后 |
| 卡池模式/名称/ID | JP；默认、当前、列表均选 `start_at <= now < end_at`；历史选 `end_at <= now`；ID/名称不要求当前开放 | 是 / 是 / 当前结束时间升序，历史结束时间降序，ID随同方向 |
| 人物名称/昵称/ID/乐队 | JP；空为目录，`乐队=…` 限乐队；原名/多语言名/艺名/昵称与已核实别名；ID只按人物实体解析 | 是 / 是 / 目录固定 band_id、order、id |

活动/卡池名称优先 ID或精确多语言名，再子串候选；不支持日期范围、费用、概率、保底筛选。活动奖励、加成、展示卡和卡池 UP 按来源关系分类型、ID 去重；不完整关系标明已确认部分。当前活动只取活动元数据，不因查活动下载玩家榜。JP 静态活动与当前活动关联需 ID 和时间窗口同时匹配。

卡池处于资料时间窗不等于所有账号可抽；缺开始/结束不能补 0。人物目录独立于卡牌，角色无卡仍存在；多人 SNAP 每张计一次，关系不完整显示“至少”，不是确定总量。身高、生日、学校等档案字段可展示，不开放任意筛选或排序。

## 活动挑战歌曲榜线

四服观测来自配置的榜线来源；默认 Haneoka，历史按来源分库。`CutoffRequest` 的所有条件共同约束同次选择；跨服不靠同号/同名合并。当前查询可能取得新观测并写历史；指定活动只读本地已保存观测。最近观测不等于确认终榜，歌曲分数榜不等于活动积分榜。

| 字段 | 类型、默认、边界与示例 | 展示 / 筛选 / 排序 |
|---|---|---|
| `server` | 默认 jp；jp/hk/kr/en，hk→tw；未知服别拒绝 | 是 / 是 / 否 |
| `event_id/event_name` | 默认当前/最近；`id1`、`活动ID=1`、`活动="名称"`；正活动 ID，不从裸数字推断 | 是 / 是 / 否 |
| `query/song_id/song_number` | 默认全部挑战歌曲；歌名、`歌曲ID=100001`、`歌曲1`；按所选活动/服别核实 | 是 / 是 / 来源歌曲编号顺序 |
| `mode/target_rank/range_bounds/ranks` | 不填为五档 1/2/3/10/100 趋势；`50` 为 40～60 附近排名；`20-40` 包含两端；`50-50` 单排名；离散用 `T1 T10 T37`，最多 5 个不同排名 | 是 / 是 / 固定排名升序 |
| `numeric_only` | 默认 false；`仅数值`改投影，不改变选择 | 是 / 否 / 否 |

排名只接受 1～100 整数；附近范围截断至边界；反向区间拒绝。`/查榜线 hk id1 歌曲ID=100001 20-40` 中三类数字不得混淆。玩家分数、数字 ID 和用户名来自同一行；缺玩家 ID/缺名次不能虚构。自然语言走 `parse_natural_cutoff`，不消耗模型额度。现有趋势、玩家记录及缺资料语义见 [榜线专题](EVENT_CUTOFFS.md)、[历史说明](CUTOFF_HISTORY.md) 和 `test_cutoff_player_ids.py`。

## 字段、数量、别名与续查

- `field` 支持等级、Note、颜色、激奏、已收录难度、数量和明确卡牌 ID 的技能。歌曲短答要求唯一实体；难度未填返回相应已收录信息，不偷偷选最高难度。`None` 是未获取，零是确知的零；无该难度与歌曲不存在分开处理。
- 数量语法如 `/问 蓝色的歌曲有多少首`、`/问 SSR成员卡有多少张`，沿用确定性筛选、按实体 ID 去重并使用完整集合。空集合返回零及 `empty`；不完整索引不能伪装为确定零。
- 别名来源：来源多语言名称；`data.CHARACTER_ALIASES` 内置角色简称及艺名等价；`query_aliases.json` 人工映射。`OURNOTES_ALIAS_FILE` 指定替代文件，并非自动覆盖合并。当前人工组为 song、band、character、card、support_card、outside_catalog；song/card/support_card 为空不等于没有自动名称。
- `resolve_exact_alias`、`known_alias_names` 和 `/查缩写` 覆盖歌曲、乐队、角色、成员卡与 SNAP；成员卡和 SNAP 的同名别名须消歧。正式名/ID 优先于人工别名。这里只提供别名到目标的查询，不提供完整的目标反查别名。
- 词库按路径保留本进程最后有效快照；坏 JSON、重复键、未知分类、空目标、无效 ID、同分类规范化名称冲突或读取失败保留旧快照。跨分类同名保留为查询时歧义。目标在当前实体资料中核实，未收录或重名目标不成为有效匹配；不因资料不完整拒绝整份词库。`/数据状态` 显示加载状态及当前资料未确认的字符串目标数量，多服 song ID 列表由服别目录另行核实。
- `alias_version` 取路径和有效内容的 SHA-256；即使 mtime 不变也能让查询缓存和续查版本失效，失败期间保持旧版本，修复后自动恢复。最后有效快照不落盘，进程重启时若文件仍坏则无人工词库；切换路径不借用另一文件的快照。
- 实体解析按意图范围和已收录事实核实；歧义不默认选首个。当前精确来源名、人工别名、模糊搜索的优先级分布在各调用方，尚不能宣称全入口已实现统一优先级。条件词（颜色、EX、比较词）不作为全局实体替换。
- 续查语法由 `parse_operation` 定义：`/继续`、`/问 下一页`、`/问 上一页`、`/问 选2`、`/问 第二个`、`/问 详情`和已有的难度切换；直接命令可用显式页码。绑定平台、会话、用户、TTL（10 分钟）、容量和数据版本。仅发送确认后的结果提交上下文；失败/过期/跨用户不能沿用。改颜色、移除等级等任意条件修改尚未实现。
- `/帮助 [主题]`、`/数据状态`、语言设置及调试/额度入口属于发现和诊断；兼容英文/日文命令见 `commands`，不要把 `UNAVAILABLE_COMMANDS`（预测、英文 gacha 等）列成业务已支持功能。多命令按换行拆分；平台权限、排队和发送结果属于交付层。

## 固定样例、缺口和后续顺序

新增 `tests/test_query_spec.py` 使用确定性的合成快照 `query-spec-v1` 和临时空人工词库；复用现有资料构造器/夹具。它比较规范化字段、完整 ID 集、结果状态，并验证本地零模型请求/零额度。模型固定动作验证参数契约和执行语义，不是提供方准确率测量。
