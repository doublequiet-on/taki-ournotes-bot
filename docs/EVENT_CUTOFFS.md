# 活动挑战歌曲榜线

可选正式来源已实现：`OURNOTES_CUTOFF_SOURCE=open`使用最低rankings权限的开放平台challenge-ranking，默认仍tracker。公开发现／地区metadata／素材保留，图像、参数、Top100本地裁切及采样节奏不调整。正式时间为原成功上游获取，和下文tracker观测质量不能等同；缺时间头／可信参考时钟隐藏当前值及身份，结束只称最后获取，不确认终榜。两库来源段断线、认证门槛、分钟与429恢复见[META_OPEN](META_OPEN.md)。本轮未做认证读取、部署或真实QQ，不以每日额度延期或降频。

这是已实现的能力说明。用户用法见 [README](../README.md)，测试结果与发布状态见 [当前交接](../交接文档.md)。本功能只读 MoeNotes 的活动挑战歌曲 Top 100；不查询活动积分榜、永久歌曲最高分，不预测或推荐配队。

## 数据与结果

`commands.resolve_command` 或 `QueryAgent.run` 的本地分支 → `event_cutoff_query.execute_cutoff` → `SongRepository.event_cutoffs` → `CutoffAnswer`。同一次捕获供文字和图片消费；绘图失败、上传失败都使用捕获的文字，不重新请求榜单。该能力不进入模型能力目录，也不使用自然语言计划／终态缓存或 AI 额度。

身份固定为 `server → eventId → challengeMusicId → musicId`。活动身份与挑战 ID 唯一性在缓存发布和旧缓存读取时校验，坏响应保留可用旧快照并在退避结束后重取。四服命名空间独立，省略服务器每次都取 JP。名字从同服 MasterText 与 MasterLiveMusic 解析，消歧与部分匹配只使用本期挑战歌曲，别名也只保留本期目标；名称与参数的优先规则及显式入口见下文。完整的非本期歌名仍明确说明不在本期。未知名称不丢条件、不变成全曲查询。元数据不可用时总览仍保留歌曲 ID 与分数；名称查询明确说无法核对。

用户名称与命令代码统一为日服（jp）、国服（hk）、韩服（kr）、英服（en）。国服输入 `hk`／`国服`／`國服` 在查询入口映射到上游 `tw`；内部结果、API、元数据、素材和缓存继续使用上游身份 `tw`，命令标签输出 `hk`。旧 `tw`／`台服`／`臺服` 及 `国际服`／`國際服` 仅作为输入兼容别名，图文和帮助均使用新的四服名称。

接口和素材证据见 [THIRD_PARTY](../THIRD_PARTY.md)。活动积分榜关闭不关闭歌曲榜；每曲使用自身 `rankingEnabled` 与 `collectStatus`。`feature/nowOn/aggregation/result/end` 分别显示未开始、进行中、结算中、结束公示、结束。`lastSeen` 和归档仅表示最后观测，不宣称确认终榜。

服务器、歌曲选择、排名及 `仅数值` 按语义识别，顺序不限。`/查榜线 歌曲1 hk 100` 与 `/查榜线 100 hk 歌曲一` 等价。省略歌曲选择时取全部挑战歌曲；省略排名时取 T1／2／3／10／100 的当前值及趋势。参数同值重复去重，不同服务器、歌曲或排名条件冲突时明确报错，不猜测或取并集。

`歌曲N` 的编号来自选定服务器本期完整 `event.songs` 顺序，即上游 `challengeRankings` 顺序。支持阿拉伯／中文数字，以及 `歌1`、`第1首`、`第一首`；不写死三首。筛选、曲目关闭、缺元数据／分数／封面均不重编号。结果同时显示歌曲编号和真实名称；名称未获取时保留曲目身份。不存在的编号明确拒绝。同一曲目有多个挑战榜时，编号只选对应挑战条目；仅凭名称或曲目 ID 无法区分时，提示使用歌曲编号。

裸数字永远表示排名。保留本期完整歌名、部分匹配及别名；含空格或末尾数字的完整名称先核对。名称与服务器／排名参数冲突时用 `歌名="完整名称"`，例如 `歌名="123"`；曲目 ID 使用 `歌曲ID=103`，不把裸数字猜成 ID。多个等价歌曲选择须确认同一活动歌曲身份后才合并。

| 排名输入 | 实际视图与范围 |
|---|---|
| 无排名 | 五档当前值和真实历史趋势；当前三曲横排一张图 |
| `50`／`T50`／`t50` | 40～60 名分数表，高亮 T50；不画曲线 |
| `1`、`5`、`95`、`100` | 分别 1～11、1～15、85～100、90～100；边界裁切，不补足 21 行 |
| `20-40`／`20—40` | 含两端的 21 行分数表，不扩展端点、不设置目标高亮 |
| `50-50` | 精确一行，与 `50` 附近查询不同 |
| `1-100` | 完整 100 行，按排名连续分页，每页保留全部选定歌曲 |
| `T1 T10 T37`／`T1,T10，T37` | 旧离散模式，按排名升序去重，不扩展每个点，最多五个不同排名 |

区间也接受 `20～40`、`20到40`、分隔符周围空格及全角数字。0、101、负数、小数、越界区间和倒序区间拒绝；倒序提示改正，不静默交换。单区间不能与另一排名条件混用。裸离散列表 `1,10,37` 不支持，提示使用旧多 T 写法；五排名上限仅用于离散模式。

`players` 原始响应位置就是名次；当前快照保存前100个位置的非负分数整数或null，以及同一行 `playerData.id` 数字ID和 `playerData.name` 用户名，不排序、去重或前移。ID只接受1～20位ASCII数字字符串或正整数，保留字符串前导零和大整数，不用用户名、profileId或其他行填补；用户名独立接收最多80字符的字符串，清除控制／双向文本指令并将换行合为空格，不伪造或截断超限名字。缺值、布尔值、数字字符串、负分数均不当成有效分数，整数零保留。源位置未知、过期或分数冲突时停止展示当前分数、数字ID及用户名。当前缓存新增可选 `player_ids`／`player_names` 等长数组，兼容旧分数缓存及仅有数字ID的缓存，正常TTL刷新后取得缺失字段；SQLite历史仍只存分数，当前缓存不保留队伍、卡组和完整profile数据。

指定排名仍生成图片，只跳过本次历史曲线读取／计算；`仅数值` 主动选择纯文字，跳过历史读取和图片生成。两者均保留 `source.boards` 的正常历史写入，既有后台采样、去重及故障保护不变。历史来自独立本地 SQLite，配置与保留策略见 [历史采样](CUTOFF_HISTORY.md)。无历史时保留趋势布局并说明；零点／单点不伪造曲线。

曲线仅连接连续的真实观测，失采、空值或超过 15 分钟间隔断线，保留下降、持平和重叠。时间横轴使用源采集时刻，当前值和历史末值分别标注。普通纵轴为完整整数；超长整数使用明确标注的完整整数基准加差值，坐标计算全程整数运算，不舍入原值。图片和上传回退只消费已捕获快照。整批回复先预算，容量不足返回完整数值及原因；发送结果不明不自动重发。

每首歌分别保存源采集时间、来源时钟、本机接收时间。优先用来源两时钟计算接收时的数据年龄，再增加本机单调时钟经过的时间；不会把本机抓取时间冒充源采集时间。来源时钟与本机偏差超过 60 秒会提示。未知时间或异常时钟如实显示，失败回退时没有可核对年龄的旧分数不展示。

展示时区：日服（jp）UTC+09:00、国服（hk）UTC+08:00、韩服（kr）UTC+09:00、英服（en）UTC。Master 的无时区时间按已核实来源配置解析（JP +9，其余 +8），与 API 毫秒时间交叉核对。2026-10-02 的非日服取样相差一小时，冲突字段显示未知并附两项观测；不擅自纠正。结束时间不使用 `displayEndAt`。

每曲保留来源的 `effectiveStartAt/effectiveEndAt`。与活动起止不同或缺失时，图文逐曲展示榜单有效开始／结束，缺失、无效或倒置区间显示未知；与活动共享的边界出现 Master/API 冲突时也显示未知。三种视图与文字回退共用同一份时间字段。

## 缓存与预算

缓存位于主缓存旁 `moenotes-cutoff-v1/`，不修改主 schema、既有缓存或额度；构造仓库时不联网、不创建目录。前台查询只读取指定服务器；是否周期采集四服由既有历史配置与 worker 决定，本轮未调整采样频率或持久格式。

| 项目 | 本地策略 |
|---|---|
| 当前活动 | 正常 300 秒，距开始／结束 10 分钟内 30 秒；故障回退最多 600 秒；404 不复活旧活动 |
| 整榜 | 60 秒，各名次复用一份；活动中源年龄超过 120 秒标陈旧，超过 600 秒不显示当前分数；故障回退上限也检查源年龄 |
| 元数据 | 3600 秒，故障最多 24 小时并标旧；按服／版本／表哈希保存，五表完成后原子发布组合 |
| 失败退避 | 默认 30 秒，无活动 60 秒；遵守同请求 `Retry-After`（秒或 HTTP 日期），本次不重试 |
| 并发／限时 | 同 key 合并，全局网络最多 3 个；单请求总超时最多 4 秒；查询数据总预算 12 秒 |
| 素材 | 独立 6 秒预算；固定白名单路径、无重定向、体积／像素限制；服／活动／元数据版本／素材版本／URL 共同键，1 小时后重新取图；同 URL 请求合并并遵守失败退避与 `Retry-After`，版本变化不绕过退避 |

缓存文件用临时文件加原子替换；损坏缓存不会改写主资料。写盘失败时保留本次成功结果。HTTP 429、5xx、pending、坏 JSON、HTML 页及超时均产生可控状态。各曲并发取样但沿活动原顺序输出；局部失败仍保留对应区块。

## 图片与 QQ

`rendering/event_cutoff_visuals.py` 复用 `visuals` 的字体、布纹、颜色、2 倍绘制和统一编码器。无排名走趋势渲染：三曲在同一画布原生排版，公共活动信息只显示一份，逐曲封面、编号、名称、当前值、曲线、状态及源采集时间独立保留；单曲仍为独立趋势卡。多于三首时按完整歌曲顺序分张，不丢曲或改编号。各曲共用时间范围，纵轴独立并明确标注，不暗示相同采集时间或分数尺度。

指定排名走共享分数表：一列排名加各曲分数列，一行对应同一排名；单曲不混入其他曲。完整整数右对齐、不缩写、不舍入；超长整数分行，说明按从上到下的数字顺序读取。缺值显示“暂无数据”，来源确认的 0 保留为 0。每页都保留各曲原编号、完整名称、封面、状态、采集时间和有效期。

每格分数下方显示用户名和数字ID，两者独立标注缺失。附近表及长区间每页最多25行，必要时因文字／高度预算减少行数。各页包含全部选定歌曲，排名连续、不重不漏，标本页与完整请求区间。文字按共用排名行与同序歌曲列显示“分数/数字ID/用户名”，含分隔符的名字用JSON引号保护；保持每条1800字分块与五条QQ回复预算。三曲完整100名增加用户名后可能产生更多图片页，超出整批预算时退完整文字；文字仍超限则明确要求单曲或缩小区间，不截断身份、分数或行。

所有页与文字回退只消费一次捕获结果，不逐排名请求来源。发送前核算整批已有 5 条被动回复预算，多指令时优先完整文字降级。文字每条最多 1800 字；每张图匹配其排名／歌曲范围的有界文字回退。任何完整结果仍超出剩余容量时明确报告无法完整发送并提示拆开命令或缩小排名区间，不先发一半再截断。图片不能在既有体积／像素预算内保留可读内容时也使用同份捕获结果降级。

上传失败退该张捕获的文字。媒体发送结果不确定时不重发。未提高图片 1.5 MB／8192 边长／1200 万像素预算或 QQ 回复上限；未执行真实 QQ 验收。
