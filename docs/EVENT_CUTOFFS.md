# 活动挑战歌曲榜线

这是已实现的能力说明。用户用法见 [README](../README.md)，测试结果与发布状态见 [当前交接](../交接文档.md)。本功能只读 MoeNotes 的活动挑战歌曲 Top 100；不查询活动积分榜、永久歌曲最高分，不预测或推荐配队。

## 数据与结果

`commands.resolve_command` 或 `QueryAgent.run` 的本地分支 → `event_cutoff_query.execute_cutoff` → `SongRepository.event_cutoffs` → `CutoffAnswer`。同一次捕获供文字和图片消费；绘图失败、上传失败都使用捕获的文字，不重新请求榜单。该能力不进入模型能力目录，也不使用自然语言计划／终态缓存或 AI 额度。

身份固定为 `server → eventId → challengeMusicId → musicId`。活动身份与挑战 ID 唯一性在缓存发布和旧缓存读取时校验，坏响应保留可用旧快照并在退避结束后重取。四服命名空间独立，省略服务器每次都取 JP。名字从同服 MasterText 与 MasterLiveMusic 解析，消歧与部分匹配只使用本期挑战歌曲，别名也只保留本期目标；完整名称优先于末尾数字名次及两字母服务器猜测。完整的非本期歌名仍明确说明不在本期。未知名称不丢条件、不变成全曲查询。元数据不可用时总览仍保留歌曲 ID 与分数；名称查询明确说无法核对。

接口和素材证据见 [THIRD_PARTY](../THIRD_PARTY.md)。活动积分榜关闭不关闭歌曲榜；每曲使用自身 `rankingEnabled` 与 `collectStatus`。`feature/nowOn/aggregation/result/end` 分别显示未开始、进行中、结算中、结束公示、结束。`lastSeen` 和归档仅表示最后观测，不宣称确认终榜。

`players` 原始响应位置就是名次；只保存前 100 个位置的非负整数或 null，不排序、去重或前移。缺值、布尔值、数字字符串、负分数均不当成有效分数，整数零保留。源位置依据未知时停止展示分数。持久缓存不保留玩家 ID、昵称、队伍或卡组。

每首歌分别保存源采集时间、来源时钟、本机接收时间。优先用来源两时钟计算接收时的数据年龄，再增加本机单调时钟经过的时间；不会把本机抓取时间冒充源采集时间。来源时钟与本机偏差超过 60 秒会提示。未知时间或异常时钟如实显示，失败回退时没有可核对年龄的旧分数不展示。

展示时区：JP UTC+09:00、TW UTC+08:00、KR UTC+09:00、EN UTC。Master 的无时区时间按已核实来源配置解析（JP +9，其余 +8），与 API 毫秒时间交叉核对。2026-10-02 的非日服取样相差一小时，冲突字段显示未知并附两项观测；不擅自纠正。结束时间不使用 `displayEndAt`。

每曲保留来源的 `effectiveStartAt/effectiveEndAt`。与活动起止不同或缺失时，图文逐曲展示榜单有效开始／结束，缺失、无效或倒置区间显示未知；与活动共享的边界出现 Master/API 冲突时也显示未知。三种视图与文字回退共用同一份时间字段。

## 缓存与预算

新增缓存位于主缓存旁 `moenotes-cutoff-v1/`，不修改主 schema、既有缓存或额度；构造仓库时不联网、不创建目录。仅在查询时读取指定服务器，没有四服定时轮询。

| 项目 | 本地策略 |
|---|---|
| 当前活动 | 正常 300 秒，距开始／结束 10 分钟内 30 秒；故障回退最多 600 秒；404 不复活旧活动 |
| 整榜 | 60 秒，各名次复用一份；活动中源年龄超过 120 秒标陈旧，超过 600 秒不显示当前分数；故障回退上限也检查源年龄 |
| 元数据 | 3600 秒，故障最多 24 小时并标旧；按服／版本／表哈希保存，五表完成后原子发布组合 |
| 失败退避 | 默认 30 秒，无活动 60 秒；遵守同请求 `Retry-After`（秒或 HTTP 日期），本次不重试 |
| 并发／限时 | 同 key 合并，全局网络最多 3 个；单请求总超时最多 4 秒；查询数据总预算 12 秒 |
| 素材 | 独立 6 秒预算；固定白名单路径、无重定向、体积／像素限制；服／活动／元数据版本／素材版本／URL 共同键，1 小时后重新取图；同 URL 请求合并并遵守失败退避与 `Retry-After`，版本变化不绕过退避 |

缓存文件用临时文件加原子替换；损坏缓存不会改写主资料。写盘失败时保留本次成功结果。HTTP 429、5xx、pending、坏 JSON、HTML 页及超时均产生可控状态。各曲并发取样但沿活动原顺序输出；局部失败仍保留对应区块。

## 图片与 QQ

`rendering/event_cutoff_visuals.py` 复用 `visuals` 的字体、布纹、颜色、2 倍绘制和统一编码器。默认三曲总览一张；单曲显示五节点，精确查询只显示指定节点。每种视图都带活动图、名称、服务器、状态、开始／结束、对应封面、分数和逐曲采集时间。

名称完整换行。数字按可用宽度调整为三列、两列或单列，不缩写、不舍入；无法保留可读字号时退完整文字。长图按整首歌分张，每张匹配同一结果的文字；页面沿用原被动回复序号，先核算已有 5 条回复预算，多指令时优先完整文字降级。文字使用每条 1800 字的本地保守预算；任何完整结果仍超出剩余容量时明确报告无法完整发送，不悄悄截掉歌曲。此极端情况可单独发 `/查榜线` 或指定歌曲；不是正常总览的分页流程。

上传失败退该张捕获的文字。媒体发送结果不确定时不重发。未提高图片 1.5 MB／8192 边长／1200 万像素预算或 QQ 回复上限；未执行真实 QQ 验收。

离线样图命令（`PYTHONPATH=src`）：

```powershell
python -B scripts/preview_event_cutoffs.py --snapshot-dir <脱敏取样目录> --art-dir <已下载公开素材目录> --output-dir runtime/event-cutoff-preview
```

脚本只读本轮脱敏 JSON 格式及本地素材，生成总览、单曲、T37、合成压力分张、430px 宽检查图与哈希清单。真实取样图带日期和“离线预览”；压力样例明确标合成，包含与活动不同的单曲有效区间。样图、素材和取样不提交。不能用这些证据替代即时 API 状态、真实 QQ 送达或生产验收。

代码回退不等于数据回退。本功能新增独立目录，旧版本无需读取它；没有执行回退、发布、启动生产进程或发送 QQ。
