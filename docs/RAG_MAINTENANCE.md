# Taki 检索资料与路由维护规范

个人 Taki 的显式聊天从现有 `/聊` 入口选工具。维护从两个问题开始：这次回答需要哪条证据？在当前群、服务器、作品与版本范围里，哪里有权提供它？用这两个答案决定是补资料、修检索，还是调整模型选择工具的时机。直接查询命令继续使用对应的结构化查询入口。

## 从一次失败定位改动

留下可复现的问法、入口、预期来源和适用范围。旧群聊用虚构群、用户和消息重建场景。固定代码提交和资料版本，在隔离环境重放一次，沿「选了什么工具 → 搜到什么 → 实际读到哪段 → 最后答了什么」找出第一处偏差。线上请求诊断能定位工具、状态及耗时；核对正文和引用用有权读取的测试材料。[聊天运行与诊断](CHAT_AGENT_RUNBOOK.md)

| 观察到的现象 | 去哪里核对 | 如何处理 |
| --- | --- | --- |
| 找不到规则、台词或章节 | 按来源 ID、作品、日服／国际服、版本或日期确认收录与授权。剧情区分日文原作、官方摘要、译文、社区分析 | 原文缺失就登记缺口和获取线索。仅有摘要时，答案和验收均限定在摘要支持的内容 |
| 正文里明明有，换个问法就搜不到 | 在同一版本下对照原词与自然转述，查看实际 query、命中片段和索引状态。规则另查批准记录及编码器；剧情另查别名、章节定位和读取句柄 | 修最先丢失证据的环节。编码器故障时，已具备词法降级的版本只检索仍获批准且范围相符的规则 |
| 搜到资料，答复却漏条件或串章节 | 逐项对照请求、真正进入模型输入的片段、来源 ID 和版本，检查研究任务在哪一步收束 | 对未满足项补读同一适用来源的条件、例外或所需场景；仍无证据的项保留缺口 |
| 忘了群里上次怎么约定，或问活动规则却去翻群聊 | 在有同名干扰消息和空历史两种情况下看工具调用。回忆题再核对群、原消息 ID、发言者和时间 | 回忆用旧消息可能出现的对象名。来源不明的现实活动询问活动名或通知原文。回忆题没有发起检索时查选源；发起后没读回原话时查匹配与排序 |
| 证据和范围均正确，答案仍有误 | 对照最终答复与模型实际看见的原文，检查是否把推断写成事实、是否混淆发言者 | 修解释或证据绑定，保留原资料与检索结果作为回归输入 |

## 更新一篇规则或一段剧情

上游规则变更、剧情新增、来源撤回或用户反馈可复现的知识缺口，都可以启动一批更新。先写清受影响的服务器、章节或条目；若现库已能正确回答，只需保留复现结果。

1. **固定来源。** 记录来源 ID、可核查的定位、适用范围、版本或采集时间，以及使用权限。来源更正或撤回时列出旧 ID 和受影响条目。时效性数值由已有结构化数据提供，规则文章保留机制、单位和适用条件。
2. **准备候选差异。** 在当前已批准快照的副本上编辑。规则把结论、前置条件、例外放在能一起读回的小节；剧情保存日文原文、发言者、顺序与场景定位，译文与分析分别标明。新增别名或主题候选可以帮助找场景，最终引用须读回有效原文。草稿保留待核实项，交内容负责人核定新增事实和有争议的译文。[规则草稿模板](knowledge/knowledge-draft.md) · [剧情数据与审核](STORY_ENGINE.md)
3. **核对全库预览。** 通过现有资料管理入口比较当前库与候选，逐项看新增、修改和移除。只加一篇文章却出现其他删除项时，先从当前完整快照重做候选。控制台校验候选内容的 UTF-8 大小，上限为 18,000 字节；大包走对应资料服务的既有导入流程，把它作为一次完整更新交付。[发布实现](../src/ournotes_bot/application/library_admin.py)
4. **回放后交付。** 隔离验证通过后，把候选版本、完整差异、来源和回放结果交给实际审核者。获准发布时由现有服务使用已核对的预览及版本保护提交。预览过期或基线变化时重新从现库生成差异；因撤回或内容变更已停用的条目，保留其停用记录及重新批准要求。
5. **读回发布结果。** 核对实际版本和索引状态，用自然问法读取新证据，再用已移除来源或错误范围作反例。剧情更新同时检查旧句柄、撤回账和人格状态；出现 `revision_mismatch` 时交人格负责人复核。回退也要按当前撤回账复查。群记忆按本群、源消息、30 天期限和删除依赖独立维护；公开规则、剧情和测试集使用可公开的资料或合成样例。[剧情覆盖记录](STORY_SOURCE_COVERAGE.md) · [群记忆保留与删除](CHAT_MEMORY_C3.md)

## 怎样判断修复有效

先写预期证据及允许得出的结论，再跑改前、改后两版。两版固定同一资料、群范围、模型或模拟器、工具和回合预算。按本次改动选对照；维护资料的人可以看到开发题，独立保留题只反馈汇总。公开评测器可在单独的工作树加载目标源码，例如按第三轮说明用 `--only D15 D20` 复测跨章读取和双条件规则。[公开评测器与复跑命令](https://github.com/doublequiet-on/taki-ournotes-bot/blob/81afa916f3a65d88cd23d4a8f004dc89f85714a3/docs/validation/rag-routing/ROUND3.md)

| 改动 | 应该成功的问法 | 容易误判的对照 |
| --- | --- | --- |
| 规则正文、索引或词法降级 | 直接问与自然转述均读到适用版本的条件、例外 | 错服、过期、撤回或未批准的条目不可用；只有一项证据时只确认该项 |
| 剧情扩充、别名或导航 | 中文转述能定位对应日文场景；跨章问题分别读回所问章节 | 同人物不同作品、资料仅有摘要、导航命中但原文缺失，各自保留真实覆盖状态 |
| 群记忆召回或选源 | 把合成旧消息放在最近上下文之外。自然回忆题从工具读回原消息并答对人或事 | 同名词的外部活动问题分别在有旧消息和空历史时测试；预期群记忆调用数为零。删除、过期和跨群用例均不可读回；当前提问本身不能算命中 |

交付时留下「代码提交／资料版本、问法与范围、预期来源、实际工具与原文定位、结论及待核实项」。路由改动另记工具次数；有新增模型调用时比较耗时和用量。合成回放能验证取证路径，真实模型样例能观察自然选源，QQ 实际送达按平台回执验收。按本次做过的层级报告；涉及付费或生产时沿用该任务的授权。
