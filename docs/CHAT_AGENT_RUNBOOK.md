# 对话 Agent：启用、诊断与回退

## 群交流设置与任务诊断

网页控制台进入群详情「交流设置」，可配置免 @ 续聊开关、60～600 秒窗口（默认 180 秒）、1～2 秒短消息合并等待（默认 1.5 秒），以及最多 200 个不主动搭话用户。选择最近出现的用户或手动填写平台用户 ID；备注不参与匹配。设置独立于模型配置和群主动服务批准，切模型或重启后继续保存。名单不屏蔽用户的显式请求与主动发起后的续聊。

`GET /v1/admin/chat/groups/{gid}/settings` 返回设置、版本 guard、最近用户、任务计数和最近诊断事件；`POST` 使用 `operation_id`、原 guard 和完整 settings 保存。并发版本变化时重新读取再确认草稿。该接口复用现有管理鉴权，不提供公开访问或模型自改设置能力。

研究任务按群及发言者保留 15 分钟。任务摘要展示待补资料、部分完成、已完成的数量；单请求诊断显示工具结果、耗时、知识不足后的站内补查及最终送达状态。未受理的名单过滤、窗口到期等决定也进入群级日志。诊断只保存固定元数据，24 小时后清理；请求记录与群控制事件各上限 4096 条。诊断降级状态保留在健康信息中，费用以 UsageLedger、发送以 Delivery Ledger 为准。主动候选的小时／日费用与预留不足拦截附带 hour_limit_micro、day_limit_micro、hour_cost_micro、day_cost_micro、hour_known_micro、hour_unknown_micro、hour_reserved_micro、unknown_cost_micro、requested_cost_micro、available_cost_micro；预留不足另附 controller_cost_micro（持久账与内存占用的较大值）。unknown_cost_micro 是读入历史已结束记录的未知部分，不包含已知费用或仍在途预留。这些数值以原币种的微单位向上取整，只用于诊断；实际准入继续精确计算，余额按更保守的整数值执行。同群同原因仍按 10 秒限频，不记录正文或密钥。

本批新增 ModelAdmin `chat_settings` 表和 Diagnostics `conversation_events` 表，不改既有表内容。兼容旧代码可读取原有记录，但不会执行新增名单和续聊设置；回退时需关闭旧版主动参与以保留“不主动搭话”的行为。任务及续聊窗口不持久化，重启不会恢复旧任务或发送机会。下述 A0 存储回退门仍适用。

## A0 回执恢复与批准代际

最终聊天文本在完成分段后、Ledger 发布 prepared 前暂存于 ChatStore。只新增精确最终文本与来源身份／哈希，不额外归档人类正文、图片或完整知识证据；候选不能被检索。保留不超过 24 小时，也不延长原来源期限；单条编码上限 256 KiB，全库最多 4096 条、16 MiB。暂存失败不授予发送资格。

实际候选期限取 24 小时与原正文有效期中较早者，因此不承诺崩溃后完整 24 小时都能补正文。已投影正文的清理期限继续受最早来源的 30 天保留期限约束。

旧历史采用删除方案：ChatStore 启动时先导入旧参与记录、应用独立删除日志，再删除没有投影来源证明的 assistant 正文及其派生记录、混合摘要和 FTS 副本。无来源清单或清单引用缺失记录的摘要也删除。未绑定合法候选或已投影正文的旧审计副本一并清理，避免未送达的生成文本残留；独立 Ledger 的送达事实不受影响。可识别的人类原始参与消息和来源完整的新投影保留，仍受原期限及授权检查约束。无法恢复被删除的旧回复，升级前须明确接受这项连续性损失。

清理与 ChatStore 版本升级在同一事务中完成，失败时不开放聊天；重启重试会再次检查，旧审计重新出现也不能复活未经证明的回复。该清理覆盖活动数据库，不等于删除外部备份或日志；恢复旧备份必须经过相同清理和独立删除日志重放。

首回执和待投影状态在 Ledger 同一事务写入。成功且允许保留时，ChatStore 原子写入正文、依赖及完成标记，再标记 Ledger。重复 ACK、启动及维护扫描可补历史，不重发、不恢复 epoch 或接续资格。新消息失效不单独撤销已送达正文的保留权；失败和不确定的首回执不能推断成成功。

恢复先应用独立删除日志，再核对知识／人格来源及能力／群服务批准。撤权清理候选、已投影正文和派生摘要，保留送达回执；暂时无法核实权限时阻止对应群历史进入聊天，不将读取故障当作删除指令。普通显式聊天切换模型本身不撤销已送达纯文本。

管理写入将能力批准升级到 `chat-capabilities/4`、群服务升级到 `taki-chat-services/2`，携带独立 `authority_generation`。管理员库 `capability_authority` 先持久记录新代际及字节摘要，再原子发布文件；重新批准不复活旧候选，恢复旧文件也不能绕过记录。已管理文件必须经管理写入路径更新。旧格式只保留迁移读取兼容，迁移前的手工关闭／恢复不具有新代际保证；上线门须将实际批准全部迁入管理记录，保持既有模型、群、能力与限额范围。

代际按整个批准文件更新，服务证明还包含限额。因此修改同文件的其他能力、群配置或限额，也可能使旧候选失效并清理受该批准约束的已投影正文；本批采用保守撤回，未实现逐项批准代际。

Responses 主动聊天在开始前分别预留 D 决策与 G 正文。预留计入原有个人／群／每日／服务小时限额，消费沿用同一 attempt，跳过或延后时释放未用部分。工具和原生联网留下最后两个调用位置；不够两个位置时不开始。开始后的未知费用不会因取消或撤权被退款，此改动不提高生产预算。

Agent 启动前，`ModelAdmin.migrate_chat_authorities()` 验证并迁移与当前配置匹配的旧批准；无文件不创建批准，已迁移文件不重复改写。换模型后的失配批准、已撤销文件、无有效配置的可选模型及非法批准输入保留禁用状态，记录跳过原因，不阻止基础后端启动，也不自动重新批准。能力与服务分别验证；授权库故障或代际写入失败仍中止启动。迁移保留原业务字段，能力和服务分别落盘；中途失败不绕过已提交的代际记录。部署前的备份必须在首次新版本启动前完成。

### 升级与回滚门

存储升级为 Ledger schema 2、ChatStore user_version 4，管理员库新增代际记录。ChatStore 接受旧 0/2/3 版本并执行来源清理；旧版拒绝新存储版本，不能靠手动改版本号绕过。上线前须在隔离副本验证旧历史、删除日志、未决回执、候选到期和重复 ACK，再经受管流程批准实际兼容指纹，备份数据库及独立删除日志，在单进程所有权下切换。本文不是生产迁移执行记录。

本批只支持回退到理解 schema 4 和来源清理合同的版本，不能直接退到 A0 schema 3 或更早版本继续使用共享数据。故障时先暂停聊天接纳，保留数据并使用支持同一合同的修复版恢复；兼容版本回退也不能回退用量、回执、删除日志或批准代际。若必须退到更早版本，需要单独批准和验证离线迁移：处理待投影状态，清理旧版无法治理的候选及派生正文，保留首回执／删除／撤权事实，停用旧版无法约束的能力。直接覆盖旧数据库备份不是可用回退方案。

离线验收入口：`ChatMemoryStoreTests`、`ChatServiceIntegrationTests`、`ChatImageIntegrationTests`、`ModelAdminTests`。其结果不证明已部署或真实 QQ 已送达。

## C2 热群机会预算

普通主动参与从首次候选启动一个 60 秒机会。新消息仍立即使旧候选失去发送资格，但替换候选和 defer 共用这一期限、最多 3 次评估、6 次模型尝试（含预留）、8 次本地工具及首次机会费用上限。用量从各候选原有账本记录合并计算；已开始、未决和未知用量继续占预算，未开始而释放的预留不冒称已调用。只剩两个调用位置时，Responses 可直接消费 D/G 预留收束；少于两次不能先花决策费用。

到期且没有待处理新消息时不自行重开；有待处理新消息才可开始下一机会。观察窗口仍为有界易失内存，重启不恢复旧候选或观察；小时、每日账本和真实回执继续保留。普通观察按 1.5 秒安静期或累计 8 秒等待先到者启动判断，权限、冷却和额度仍独立生效。更多取消仍可能降低热群召回，不保证持续高频消息一定接话。

同一机会最多复用两份已批准知识 lease，绑定检索词、区服／日期／版本、批准集合及能力授权代际，重用前重新校验来源；撤销或变化不能通过缓存绕过。缓存不落盘，不含旧候选正文、网页结果或图片解释，机会过期、清空观察、服务策略变化时清理。后续候选预检使用机会剩余费用，实际和未知用量仍由原账本约束。

迟到成功回执仍计入冷却和回复次数，但不会清除较新的候选状态；冷却、权限和发送前资格继续独立限制交付。离线验收使用 `ProactiveControllerTests`、`ChatServiceJobsTests`、`ChatServiceIntegrationTests`。本批不新增持久格式；回退代码会失去跨候选机会预算，不能声称仍有该限制，已有用量和回执不能随代码回退。

## 模型配置与密钥诊断

在线优先使用受鉴权控制台的模型设置和群能力状态；这些接口返回 `key_configured` 等元数据，不返回密钥。需要核对磁盘配置时，在服务器本地运行：

```sh
python -B scripts/inspect_model_config.py --config /path/to/model-proactive-v1.json
```

该工具只读一个不超过 128 KiB 的普通 JSON 文件，输出 schema、固定枚举的 provider、模型／版本是否存在、文件指纹、顶层密钥是否内置和绑定数量；不输出自由填写的模型或版本文本。指纹基于完整文件，仍应作为敏感诊断信息处理，不能视为匿名化。拒绝最后一个路径分量为符号链接、特殊文件和过大文件；父目录必须可信，此检查不拒绝父目录中的符号链接。缺少无跟随或非阻塞打开能力时（包括当前 Windows 实现）返回 `safe_open_unsupported`，不读取配置。失败只输出固定错误码，不回显配置、路径或原始异常。不加载 dotenv、不发模型请求、不修改批准或配置。`inline_key_present=false` 不代表服务缺少密钥，schema 1 可以使用运行环境中的密钥。`posix_group_other_mode_clear` 仅检查 group/other 权限位，不验证属主或 ACL，须另行核对。

模型配置 JSON 可能包含顶层 `secret`，不要用 `cat`、`Get-Content`、完整 JSON 序列化或通用异常输出查看这些文件。诊断使用白名单投影；未知字段和嵌套对象也不输出。配置目录限服务属主访问（POSIX `0700`），凭据文件、含密钥模型配置及其备份使用 `0600`；不要把原始配置复制进日志、验收记录或 PR。

主动模型改动会改变配置版本或指纹。群主动服务批准和平台能力证据须分别匹配当前模型，`chat_service_profile_mismatch` 或 `approval_absent_or_profile_changed` 会关闭参与。重新绑定必须有维护者对当前配置的明确批准，保留原群范围、服务主体和限额，并保存不含密钥的批准／恢复记录；既有平台接收和发送证据不等于新模型已完成真实对话验收。

密钥一旦出现在聊天或工具输出中，应在提供方创建替代密钥，通过受保护控制台输入，再撤销旧密钥；不要把替代密钥贴进聊天。密钥轮换后重新核对当前配置指纹及能力／服务批准。收紧文件权限或新增脱敏输出不能撤销已泄露的密钥。

## 启用与运行边界

聊天按话题需要展开：普通闲聊接住话题后可补充想法或理由，认真讨论说明判断、理由及必要例子，追问回应具体疑点，没懂时换种说法。不固定压成一两句，也不为增加长度重复或补造内容；直接讲内容，不加自我免责、能力声明或自我否定式铺垫，事实缺口只在影响当前答案时具体说明。仍自然收尾，保留必要澄清。该策略覆盖 Agent（含主动参与）和 legacy 聊天提示，不调整模型 token 上限、每轮调用／工具次数、超时、费用或发送预算；legacy 人格聊天仍保留原有 300 字限制。

默认 `OURNOTES_CHAT_ENGINE=legacy`。`/查`（兼容 `/问`、`/ask`）查询，`/聊` 聊天；Agent 模式支持非 @正文中的立希或 taki 触发，前提是 QQ 下发该群消息。聊天回复不 @且末尾不加句号，查询继续 @真实发送者。引用消息的有界文字预览可进入聊天作为用户材料；可信引用索引/作者和引用图片仍须 profile 验证。现有自然语言策略仍约束两类模型调用，未增加独立权限开关。Agent 仅用于 Koishi 对应 Python 后端；旧 `bot`／CLI 查询入口沿用旧行为。启用前确认协议 2.2、能力 qq-query-chat-v6 的网关和后端成对、既有 Terra profile 与身份／群准入有效、模型授权覆盖本次试验；生产操作单独授权。组合状态、配置及未验证项见 [F1](CHAT_AGENT_F1.md)。

在后端环境设置 `OURNOTES_CHAT_ENGINE=agent`，经既有部署流程加载配置。继续现有 Terra 的 provider/model/端点/价格/推理设置，不复制另一个项目的配置，不为兼容性切模型；仅按下述每日主模型预算在新轮选择 DeepSeek。无有效身份、当前许可或额度时不调用模型。普通闲聊目标一次调用；六次模型／八次工具／60 秒是资源上限，原 profile 的频率与加权额度可能先到达上限。每个 HTTP 都单独记账，不承诺复杂问题必用满六次。

试点范围继续由现有群管理及模型群准入控制，默认使用同一 v0 人格；版本库中经独立人工批准的人格可替换草稿。关闭群内模型权限后，每次新模型请求仍需当前许可，网关发送前也重验策略。联网、看图、群级摘要和主动参与还须各自的能力／服务批准，缺失时保持关闭，详见 F1 配置表。服务任务记到明确批准的群服务主体，不记到当前发消息者。

中止诊断在 finished 事件中记录固定 reason 与 stage（preparation／decision／generation／model／delivery），保留第一次终态原因。网关可区分新观察替换、候选过期、策略或群权限变化、网关停止、网关异常与未完成交付；旧网关不提供原因时标为 gateway_abort。后端另区分准备任务取消、网关代次切换、设置变化、对话结束、上下文撤销、记忆删除与关闭。错误事件也记录阶段；这些字段不含正文或异常原文。budget_reconciled 群事件中的 controller_before_micro／controller_after_micro 显示准入前按账本校准的变化，单位为整数微币种，旧未知费用仍保留。

诊断先查现有交付账与加权用量账，按 request/attempt ID 区分 reserve、started、settled、released 及 billing_incomplete。聊天库只保存必要可见信息，可据此区分生成、工具失败和逐段交付；不要导出真实正文至公开 CI。实例 state-dir 的 `chat-v1.sqlite3` 独立于 `usage-v1.sqlite3`，不要拿聊天库清理来重置额度。

联网操作次数未知时，已结算记录仍会在 `reserved` 中保留该操作的费用上界，继续计入用户及群额度；服务预算也按未知上界处理。打开旧账本时会依据已有未知操作记录重建缺失的预留，不改变已知费用或次数。若之后收到可核对的实际次数，账本结算实际费用并释放该部分预留。不要将 `billing_incomplete` 当作零费用，也不要为恢复额度删除账本。配置非零日上限的主动服务只让满一小时且已结束的未知调用退出小时统计，原记录及日预算占用继续保留；旧策略无日上限时维持原小时保护。

工具执行前会预留最终收束的加权额度，未用时记录为 `released/final_not_needed`；summary 的记录数包含这种占位，真实调用数按 started_at 非空核对。聊天审计写入故障会记录 `Chat audit unavailable` 与进程内 audit_failures，继续完成已结算结果和 ACK；不能因此忽略必需用量账或交付账故障。

30 日源到期由 ChatStore 在启动及读取时清扫；摘要不延长来源期限。十五分钟／48 条／24 KiB 的参与上下文可在重启后恢复，更早片段通过本群检索。图片字节和签名 URL 仅在短时内存，记忆只保存附件存在及原消息关联。真实 QQ 引用索引关联与撤回仍待 profile 验证，见 [QQ 证据](CHAT_QQ_QUOTE_EVIDENCE.md)。

管理员使用既有 Bearer＋实例鉴权读取 `GET /v1/admin/chat/groups/{gid}/memory` 的无正文统计。`POST` 还须当前 gateway epoch、后端就绪；body 精确为 `{"action":"delete","message_ids":["原消息ID"]}` 或 `{"action":"clear"}`，模型工具无此权限。删除会清来源、派生回复、摘要、FTS、审计正文与内存引用，并取消本群待发送工作，保留额度及服务发送事实。恢复备份须保留 `chat-v1.deletions.json` 并先合并墓碑和到期，不能只恢复旧库。备份本体按保留政策另行销毁，见 [C3](CHAT_MEMORY_C3.md)。

回退后续请求可用 `OURNOTES_CHAT_ENGINE=legacy`，通过既有流程加载。先撤销新调用接纳，让已有调用结算或明确取消，停止旧候选交付，再切换成对网关／后端版本。当前进程内模式检查也会拒绝已关闭 Agent 的晚到正文。不能在失败的同一轮自动双跑 legacy。回退保留新聊天库，旧代码不读取它；额度／发送结果不回滚，不重发 uncertain 消息。

代码版本回退到协议 2.0／2.1 时必须同时回退配对网关；配对兼容不代表存储兼容。旧 C1 不能直接读取本版 schema 4 数据，须先满足上文迁移和来源清理合同，不能恢复未经墓碑清理的备份。源码组合验证器已接受已知 2.2 组合，已安装控制器、trusted policy 和运行路径须在上线前核对；未操作生产配置。真实回退演练、QQ 客户端验收与同 Terra 质量对照仍是独立待项。

未知 token 维度现在保留按原币种／参考单位计算的上界；历史行没有请求输入上限时使用已支持 profile 的最大输入 65536／输出 8192。已知费用与未知预留相加，迟到用量只释放已确定的部分。新增 `expected_actions` 保留请求操作意图；started 请求缺少对应预留，或提供方报告未预留的非零／未知操作时，`unbounded_actions` 保留异常标记并停止该用户／群新预留，不猜造操作价格。可核对实际次数为零时账本结算保留该事实并解除限制；其他异常须核实原提供方账单和价格后修复，不能人工删除标记恢复额度。旧账本如果操作意图和预留记录均已缺失，无法自动推断是否发生联网调用，须核对提供方记录。

崩溃回退必须先用理解新账本的版本打开并调和 started 记录，确认全部真实调用已 settled，保留未知费用预留。未解决 unbounded_actions 时不允许退到不理解该标记的旧版本；旧版本对晚到用量的重新结算也不能覆盖已包含的操作费用。仅证明旧版能打开 SQLite 不构成回退验收。

`expected_actions`、`unbounded_actions` 和删除检测 trigger 是共享用量库的增量 schema；上线前必须按受管流程核对兼容指纹、备份策略及新旧版本隔离恢复，不把源码合并当作控制器或备份合同批准。

主动观察在接纳及发送前核验删除墓碑；重试不能重新带入已删正文。知识引用继承原页租约；ACK 绑定的知识范围用于明确追问，重启后缺少范围须重新说明。联网批准在每次请求前及交付前重验。图片字节与十秒读取期限按整轮累计，覆盖当前图、引用和工具重读。带图的明确斜杠命令仍须通过命令识别。

## 模型传输诊断

每次原生模型 HTTP 在结束或中断时写一条 `transport` 事件，并在 `ournotes_bot.model_transport` 日志中以 request／attempt ID 关联。阶段为 connect、dns、upload、wait_headers、read_body、complete；固定 name 区分 disconnected、timeout、connect、transport、cancelled、response_too_large、interrupted 和正常 none。费用未知仍按原账本上界处理，不因诊断重试请求。

记录总耗时与实际经过的 dns_ms、connect_ms、upload_ms、wait_headers_ms、read_ms，单位毫秒；未发生的阶段不补零。connect 包含客户端 DNS、代理 CONNECT 及 TLS，当前不能单独拆出 CONNECT 和 TLS；代理节点内部 DNS 也不在客户端观测范围。upload 以 aiohttp 提交请求体的事件为界，不证明对端已收到或执行。

headers_received 表明是否收到 HTTP 响应头；收到时记录状态码，以及符合固定格式的 x-request-id。proxied 只表明客户端使用了显式代理，不能证明代理的具体出口。字段白名单不接收正文、URL、凭据、任意响应头或异常原文；诊断库沿用既有容量和保留期限，日志沿用已有 journal 策略。诊断字段校验失败只记录固定警告，不改变已知费用或回复。

排查断连时先看阶段：connect／dns 关注建连；wait_headers 表示客户端已提交请求、尚无响应头；read_body 表示已收到头但响应体未读完。阶段只能缩小范围，不能单凭 wait_headers 判定 OpenAI 或代理哪一端关闭了连接。优先观察自然请求，不重发原问题来补日志。

## 每日主模型预算与 DeepSeek 备用

服务器可设置 `OURNOTES_AI_QUOTA_EXEMPT_SUBJECTS`（逗号分隔的已验证 model subject，默认空）豁免指定账号的个人／群每日加权额度及主模型美元预算。使用受信接收记录核验平台身份，并复用已有跨场景绑定；不能把 QQ 号码、昵称或消息中声明的号码直接当成 subject。环境变更须按部署流程加载。频率、并发、单轮 token／工具预算、权限及未知账单保护继续生效。

豁免账号的费用、群归属、用量及未知状态照常落账；群额度累计与主模型预算累计在读取时排除豁免 subject，包括其已有记录，不删除或改写历史费用。总模型费用仍包含这部分真实支出，管理投影的 `exempt_primary_spent_and_reserved_micro` 单独给出被排除的主模型消费和预留。移除名单后历史记录自动恢复计入额度；回退至旧版不再支持豁免，须按普通限额解释。

整个 Taki 后端共用 `OURNOTES_AI_PRIMARY_DAILY_USD=2.5`，按 UTC+8（香港时间）零点重置。所有非 DeepSeek 调用共用该预算，含普通问答、联网、群摘要、主动参与和明确发起的能力探测；直接业务命令仍零模型。实际 USD 费用、在途预留及未知用量上界从同一用量库累计，跨群、配置版本变化和进程重启均不清零；撤销未开始的请求只释放其预留。用户／群加权额度与频率限制继续生效。

新一轮不足以同时覆盖主模型首轮及最大终轮预留时，选择 DeepSeek。已开始轮次固定模型，先为终轮预留费用，再开展工具读取；后续预算不足时使用已有终轮收束。午夜按实际开始日期重新检查。HTTP 超时、权限拒绝、未知用量或协议错误不会自动重试或切模型。

DeepSeek 使用独立受保护配置 `OURNOTES_AI_FALLBACK_PROFILE_FILE`，未指定时读取后端 state-dir 的 `model-fallback-v1.json`。格式复用 `taki-model-config/1`、`/2` 或 `/3`；namespace 与主配置一致，provider 必须是 `deepseek`，采用已支持的 `deepseek-chat-v1`。填写已核定的模型、能力证据和登记价格，币种与 reference_unit 须和主配置一致（主模型美元预算要求 USD），config_version 使用独立值。密钥可保留在配置的 `secret`，或由 `OURNOTES_FALLBACK_AI_API_KEY` 提供；不要复制主模型密钥。该文件由运维私密保存，不随源码／发行包发布。备用配置里的用户／群额度继续约束 DeepSeek，当前平台身份与准入来自原主配置；备用文件不能扩充群或用户授权。

主／备用配置发生变化会撤销相应在途结果的交付。备用模型的联网、图像、群摘要和主动服务仍要求匹配该模型的原能力／服务批准；缺少批准时不沿用 Terra 的证据。DeepSeek 未配置或配置无效时明确提示并停止主模型调用。其费用不计入 $2.5 主模型预算，仍独立付费并受既有额度约束；本策略不是总 API 账户的硬账单上限，实际费用取决于提供方计数与登记价格，异常用量仍如实记账。

启用需要通过现有部署流程加载环境及受保护备用配置；只修改源码不会改变运行中的生产实例。代码回退到不理解每日美元预算的版本会失去该门禁，须先关闭主模型接纳，不能继续按旧版本运行并声称仍有 $2.5 限额。

首次从旧存储合同升级且不支持双向回退时，使用独立审核安装的[单向迁移入口](../deploy/LINUX_OFFLINE.md#单向存储迁移与向前恢复)。失败停服并保留新库，普通 resume 不得解除暂停；修复须明确指定兼容新数据的提交，不恢复旧数据库。
