# 对话 Agent：启用、诊断与回退

默认 `OURNOTES_CHAT_ENGINE=legacy`。Agent 仅用于 Koishi 对应 Python 后端；旧 `bot`／CLI 查询入口沿用旧行为。启用前确认协议 2.2 的网关和后端成对、既有 Terra profile 与身份／群准入有效、模型授权覆盖本次试验；生产操作单独授权。组合状态、配置及未验证项见 [F1](CHAT_AGENT_F1.md)。

在后端环境设置 `OURNOTES_CHAT_ENGINE=agent`，经既有部署流程加载配置。继续现有 Terra 的 provider/model/端点/价格/推理设置，不复制另一个项目的配置，不为兼容性切模型。无有效身份、当前许可或额度时不调用模型。普通闲聊目标一次调用；六次模型／八次工具／60 秒是资源上限，原 profile 的频率与加权额度可能先到达上限。每个 HTTP 都单独记账，不承诺复杂问题必用满六次。

试点范围继续由现有群管理及模型群准入控制，默认使用同一 v0 人格；版本库中经独立人工批准的人格可替换草稿。关闭群内模型权限后，每次新模型请求仍需当前许可，网关发送前也重验策略。联网、看图、群级摘要和主动参与还须各自的能力／服务批准，缺失时保持关闭，详见 F1 配置表。服务任务记到明确批准的群服务主体，不记到当前发消息者。

诊断先查现有交付账与加权用量账，按 request/attempt ID 区分 reserve、started、settled、released 及 billing_incomplete。聊天库只保存必要可见信息，可据此区分生成、工具失败和逐段交付；不要导出真实正文至公开 CI。实例 state-dir 的 `chat-v1.sqlite3` 独立于 `usage-v1.sqlite3`，不要拿聊天库清理来重置额度。

联网操作次数未知时，已结算记录仍会在 `reserved` 中保留该操作的费用上界，继续计入用户及群额度；服务预算也按未知上界处理。打开旧账本时会依据已有未知操作记录重建缺失的预留，不改变已知费用或次数。若之后收到可核对的实际次数，账本结算实际费用并释放该部分预留。不要将 `billing_incomplete` 当作零费用，也不要为恢复额度删除账本。

工具执行前会预留最终收束的加权额度，未用时记录为 `released/final_not_needed`；summary 的记录数包含这种占位，真实调用数按 started_at 非空核对。聊天审计写入故障会记录 `Chat audit unavailable` 与进程内 audit_failures，继续完成已结算结果和 ACK；不能因此忽略必需用量账或交付账故障。

30 日源到期由 ChatStore 在启动及读取时清扫；摘要不延长来源期限。十五分钟／48 条／24 KiB 的参与上下文可在重启后恢复，更早片段通过本群检索。图片字节和签名 URL 仅在短时内存，记忆只保存附件存在及原消息关联。真实 QQ 引用索引关联与撤回仍待 profile 验证，见 [QQ 证据](CHAT_QQ_QUOTE_EVIDENCE.md)。

管理员使用既有 Bearer＋实例鉴权读取 `GET /v1/admin/chat/groups/{gid}/memory` 的无正文统计。`POST` 还须当前 gateway epoch、后端就绪；body 精确为 `{"action":"delete","message_ids":["原消息ID"]}` 或 `{"action":"clear"}`，模型工具无此权限。删除会清来源、派生回复、摘要、FTS、审计正文与内存引用，并取消本群待发送工作，保留额度及服务发送事实。恢复备份须保留 `chat-v1.deletions.json` 并先合并墓碑和到期，不能只恢复旧库。备份本体按保留政策另行销毁，见 [C3](CHAT_MEMORY_C3.md)。

回退后续请求可用 `OURNOTES_CHAT_ENGINE=legacy`，通过既有流程加载。先撤销新调用接纳，让已有调用结算或明确取消，停止旧候选交付，再切换成对网关／后端版本。当前进程内模式检查也会拒绝已关闭 Agent 的晚到正文。不能在失败的同一轮自动双跑 legacy。回退保留新聊天库，旧代码不读取它；额度／发送结果不回滚，不重发 uncertain 消息。

代码版本回退到协议 2.0／2.1 时必须同时回退配对网关。旧 C1 可读原审计表、忽略增量记忆表，但不能直接恢复未经墓碑清理的备份。源码组合验证器已接受已知 2.2 组合，已安装控制器、trusted policy 和运行路径须在上线前核对；未操作生产配置。真实回退演练、QQ 客户端验收与同 Terra 质量对照仍是独立待项。

未知 token 维度现在保留按原币种／参考单位计算的上界；历史行没有请求输入上限时使用已支持 profile 的最大输入 65536／输出 8192。已知费用与未知预留相加，迟到用量只释放已确定的部分。新增 `expected_actions` 保留请求操作意图；started 请求缺少对应预留，或提供方报告未预留的非零／未知操作时，`unbounded_actions` 保留异常标记并停止该用户／群新预留，不猜造操作价格。可核对实际次数为零时账本结算保留该事实并解除限制；其他异常须核实原提供方账单和价格后修复，不能人工删除标记恢复额度。旧账本如果操作意图和预留记录均已缺失，无法自动推断是否发生联网调用，须核对提供方记录。

崩溃回退必须先用理解新账本的版本打开并调和 started 记录，确认全部真实调用已 settled，保留未知费用预留。未解决 unbounded_actions 时不允许退到不理解该标记的旧版本；旧版本对晚到用量的重新结算也不能覆盖已包含的操作费用。仅证明旧版能打开 SQLite 不构成回退验收。

`expected_actions`、`unbounded_actions` 和删除检测 trigger 是共享用量库的增量 schema；上线前必须按受管流程核对兼容指纹、备份策略及新旧版本隔离恢复，不把源码合并当作控制器或备份合同批准。

主动观察在接纳及发送前核验删除墓碑；重试不能重新带入已删正文。知识引用继承原页租约；ACK 绑定的知识范围用于明确追问，重启后缺少范围须重新说明。联网批准在每次请求前及交付前重验。图片字节与十秒读取期限按整轮累计，覆盖当前图、引用和工具重读。带图的明确斜杠命令仍须通过命令识别。
