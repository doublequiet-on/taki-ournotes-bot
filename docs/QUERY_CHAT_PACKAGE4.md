## 配置、额度与能力测试

浏览器仅调用 authority 5 的 Console RPC。`model/settings`、`model/save`、`model/probe`、`model/group` 转到认证的 `/v1/admin/model`、`/probe`、`/groups/{group_id}`；写操作还要求活跃网关 epoch。后端令牌不会下发浏览器。

`OURNOTES_AI_PROFILE_FILE` 指定管理员预先选定的配置路径。未指定或文件损坏时如实不可编辑，不创建任意配置目录。新文件使用 `taki-model-config/2`，在包 3 字段外增加后端专有 `secret` 和最多 128 项 `groups`；旧 v1＋`OURNOTES_QUERY_AI_API_KEY` 仍可读。已有 v3 文件保留其版本及受保护的 `group_admissions`，网页不能新增或修改群准入。群覆盖只有 `group_daily_limit`、`group_rate_requests`。身份绑定及其证据由后端文件维护，网页保存时原样保留，不能用昵称推导统一身份。

保存使用后端 epoch＋当前文件 SHA-256 比较、完整类型校验、唯一新版本、0600 临时文件、fsync 和原子替换；POSIX 目录不能允许组／其他用户写。Windows 使用部署目录 ACL，不能将 POSIX mode 当作 Windows 权限证明。已有请求继续用原配置快照，旧用量按原价保存。保存回执丢失时保留草稿并回读，不能伪报生效；重复 operation ID 不再次写入。

API 地址按已登记服务商选择固定 HTTPS Chat Completions 地址。当前支持 deepseek、openai、openrouter；不接受任意兼容地址、重定向或内网 URL。密钥输入仅提交到后端，成功、失败或退出后清空；读取接口只返回“已配置”，不返回原文、前后缀或完整配置文件。

频率以业务 request 去重：默认每用户 10 秒 3 次，每群 10 秒 30 次，可配置窗口及数量。第二次生成仍属同一业务请求。用户和群日额度沿用包 3 默认 10 万／100 万加权 Token，当前群覆盖参与实际预占及跨日检查；直接查询／分页不使用这些额度。上述数字是实现默认，不是已经确认的生产参数。

默认价格由管理员登记，UI 单位为“微货币／百万 Token”；首次新建表单的数值只是未保存的示例。已有账本的币种／参考单价禁止修改，避免历史额度口径改变。OpenRouter 报价仍只来自既有官方适配器，显示来源、更新时间和估算标记。参考费用不是结算账单；缺失 usage 保持未知。

“发起一次能力测试”需额外确认可能收费。它提交合成 `capability_echo` 工具请求，不执行游戏工具；与业务共用模型并发上限，最多输出 128 Token，HTTP 15 秒。每次测试使用独立操作 ID、持久意图、usage 和价格快照。检查工具结构、准确参数和完整 usage；是否发送并行禁止参数只记事实，不夸大为完整模型能力认证。无自动重试、修复或切换，未知结果和重启中断不重放。打开页面从不触发该动作。本包验证使用注入的隔离提供方，没有真实付费测试。

新增 `model-admin-v1.sqlite3` 保存配置／探测的有限元数据和输入摘要，不保存密钥或模型响应。它损坏时只关闭模型管理，查询账务仍独立工作。原 usage-v1 表结构不改含义，附加的 `attempt_observations` 表只记类别和耗时。

首轮合法零工具文本的观测类别为 `routing_text`，不把它自动视作已通过寒暄校验；历史 `light_chat` 记录保留原样。attempt 的结算／错误码描述模型调用，查询记录的业务结果描述后续路由与校验；提供方正常返回且用量已结算，仍可能得到 `model_no_evidence` 或条件不匹配，不能据此计算回答成功率。

## 受信动作协议（独立审查面）

实现分为网关 `trusted-actions.cjs`、受信进程中的 `deploy/trusted_actions.py` 协议核心和显式 Unix 服务接线 `create_server()`。默认不启用。只有独立安装、权限审阅后的控制器提供 `/run/taki-actions/control.sock` 时才可连接；Windows 和未安装实例显示不可用，不展示可执行重启／更新按钮。

客户端检查 root 所有且应用不可写的目录、root 所有的 Unix socket，固定路径、2 秒内读取预算、64 KiB 响应上限，无 shell 或任意下载地址。服务接线要求 Linux root、固定 socket 目录、指定应用 UID/GID，按 `SO_PEERCRED` 校验请求进程；应用不能提供命令、路径或目标 URL。

| 方法 | 固定合同 |
|---|---|
| GET `/v1/actions` | `taki-trusted-actions/1`，实例、最多两个待确认 plan、最近 25 项状态；读取不执行动作 |
| POST `/v1/actions/prepare` | 仅 `action=restart/update` 与实例；由受信部署适配器确定版本和验证门禁，生成 120 秒方案 |
| POST `/v1/actions/execute` | `operation_id`、完整 plan、`action:instance:target_sha` 确认；方案必须与控制器当前方案完全一致 |

plan 固定当前／目标完整 SHA、配置摘要、后端模块摘要、原进程 PID、CI／兼容／组合产物门禁及 `drain` 策略。网页先要求持久维护模式，控制器在受理及执行前再次要求维护、在途为 0、未冻结、门禁通过。目标运行版本、后端摘要、更新后的两个 PID 和健康均匹配才记成功。任务已提交、HTTP 回执或控制器记录 SHA 都不能单独证明恢复。

两侧审计意图先于执行落盘；控制器持有独占文件锁。同 ID 不同参数拒绝；结果未知时只读核对，不能换 ID 再次执行。启动时原 intent/running 转为 unknown，阻止后续动作，保留记录等待受信运维核对，不删事务消除阻塞。

**生产依赖**：此包提供协议、服务接线、页面和隔离适配器验证，不安装生产服务或实现绕过现有更新器的执行路径。安装方仍须审查固定部署适配器的 `propose / validate / execute / health`：复用现有更新器的目标获取、CI、组合摘要、兼容审查、备份、事务、启动许可、冻结／恢复保护；锁住实际部署状态，确保配置摘要和在途计数来自受信观测；绝不能以“已核定方案”跳过执行前检查。系统单元、权限授予、生产适配器接线及实际重启／更新须另行授权和验收，不由页面自动完成，也不启用自动更新 timer。

本包同时修复旧启动器只识别单个 `group_policies_v1` 能力、与控制器已支持的 v2 能力组合不一致的问题。两进程启动门禁对齐；网关子进程移除新版查询密钥与配置路径环境变量。
