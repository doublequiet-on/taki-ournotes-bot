# Taki 下一轮更新计划：聊天、主动查资料与群回复提及

状态：2026-10-26，PR #123 已合并为 `8b27ac23e096815073e4a3eaab095e1a16c5d7c9` 并部署，服务端门禁通过；客户端发现普通文本显示提及标签原文，以及“这期活动啥时候结束啊”仍被对象校验拦截。当前修复分支改用 Markdown 群文字载荷、补齐句尾语气词，并为公告和明确请求的歌曲／活动网页补充程序生成的 Haneoka 链接。U4／U5 仍为规划。

两条独立授权 Markdown 探针已取得平台回执，用户确认 @ 和链接都正常；此结论证明客户端能力，不表示修复分支已上线。群图片继续使用原上传链路，图片前复用已计入预算的文字提示位进行提及，慢提示已发送时不再添加。总载荷保持 1800 字符，群正文预留 300 字符，长正文按 1400 字符分块；私聊预算不变。

## 目标与当前基线

让 Taki 能接住普通聊天，理解自然说法，按需去 Haneoka／MoeNotes 找资料，再扩展到受控网页搜索。群内每条指令回复都明确提及本次发起者。

规划起点为 `codex/taki-personality-chat` 的 `f58a082f7ef7cda43dafd0e5185da2ca67e5ef9c`；U2 从 U1 的 `de3874d03e915cd0e338f9d25a339057386b5cff` 继续。[PR #123](https://github.com/doublequiet-on/taki-ournotes-bot/pull/123) 已合并部署，客户端修复状态见上。

规划时核对的基线事实（U1 改动见上）：

- `persona.py` 的六类整句聊天是原型；未命中的句子仍可能被要求选择业务工具。需要语义路由，不能靠不断增加固定句式完成开放聊天。
- `native_tools.execute` 将“这期／本期活动”转换为“当前”时会报 `query_entity_mismatch`；“当前活动”通过。活动接口已经有结束时间，不需要靠搜索绕过此问题。
- `model_runtime.py` 当前为一次工具选择、至多一次事实生成，不是可连续找资料的工具循环。
- Haneoka 主资料、谱面及活动榜线适配已经存在。公开文档还有剧情目录和公告正文能力，但 Taki 尚未完成通用站内搜索、剧情全文提取或自主多步查阅。
- Koishi `delivery.ts` 已携带原始 `msg_id` 和递增 `msg_seq`，入站 `userId` 已核对身份。当前发送代码没有独立的提及处理。旧 Python QQ 入口的注释记录过“显式 @ 标记显示成文字”，不能据此认定当前客户端一定会自动 @。

本轮分为 U1–U5，与已完成的查询聊天 v3 包 0–5 区分。顺序为 **U1 → U2 → U3 → U4 → U5**，每批分别验收和审查，不等全部完成才交付。

## U1：群回复 @ 发起者，修正当前活动问法

这是下一次实施的第一批，先解决群里看得见的归属和明确查询故障。

### 群回复合同

1. 指令触发的群回复，文字消息原生 @ 本次发起者一次，包括直接查询、`/问`、错误提示、慢提示、文字回退和 `/继续`。图片按当前平台验证结果，先以同一请求的一条文字提示提及发起者，再顺序发送图片。同一条消息里不重复叠加 @。
2. 目标只来自当前已核验入站事件的用户身份；不采用模型给出的用户、正文里提到的人、手填 QQ 号或上一个提问者。多人并发时分别绑定各自请求。
3. `/继续` 和新的追问提及本次发起者，并继续执行原用户／群上下文隔离。私聊沿用现有输出；定时公告没有指令发起者，继续走独立通知合同。
4. 提及由 QQ 发送适配层添加，业务答案保持平台无关。提及占用的载荷长度纳入限制；文字提及与正文同条发送；原生图片附文不放提及标签，图片前提示计入消息预算，超出四页的内容保留 `/继续`。
5. 保留原 `msg_id`、递增 `msg_seq`、五条被动回复额度、发送窗口、intent／ACK、防重复及不确定不重发。不能为补 @ 重发已经发送的消息。

协议已核对：[QQ 官方文本交互](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/text-chain.html) 明确群文本、图文与 Markdown 使用 `<qqbot-at-user id="" />`。锁定的 Koishi 适配器会忽略群 `h.at`，因此在现有低层发送链构造官方标记。但普通文本在本次客户端验收中显示原文；[Markdown 消息](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html) 的两条实际探针已验证真实提及与链接。后续修复采用 Markdown 文字及原生图片组合，配套验证消息预算和分页。

验收必须同时有离线载荷／身份检查、平台回执和目标 QQ 客户端可见结果。客户端应显示可识别的正确成员提及，不能只是裸 OpenID、普通 `@昵称` 文本或源码注释；系统通知是否弹出由客户端通知设置决定。原生 @ 未验证就不能把该项标成完成，其他独立工作可以继续。

### 活动查询修复

在活动与卡池等相应语境内规范“这期／本期／这次／现在”的指代，保留明确区服、时间和对象要求。未指定且无有效上下文时按现有日服默认，回答标清区服和时区。有多个真正候选时只问必要区别；“上期／下期”不得硬转为当前。没有进行中活动时区分最近结束与即将开始，不拿最近一条伪装成当前。

主要位置：`koishi/src/ingress.ts`、`delivery.ts`、`scripts/probe.cjs`；`natural_query/native_tools.py`、`query/activity_query.py` 与对应既有测试。以现有 Koishi 发送链为主，不迁移平台、不扩展到独立推特机器人。

## U2：扩大聊天，建立语义路由

当前工程实现：保留六类一次调用快路径，新增 `chat_response` 处理其他日常表达、主观比较和追问；最多两次模型调用，继续各自取得许可与结算。`clarify_term` 只核对原句别名，`unavailable_fact` 标明具体缺资料。追问需匹配成功 ACK 的话题，生成最多 300 字；事实问题及继承的显式事实请求不得误入聊天。未增加站内搜索、网页访问或永久记忆。

本批经授权完成 DeepSeek 固定题 16 轮、修复复测 6 轮及最终比较题 2 轮，累计 39 次调用。真实验收发现并修正了主观比较误判、未知别名猜测和无依据作品评价；知识混合题在已有百科依赖环境通过。最后一次仅重跑两条比较题，其余证据绑定各轮源码，不声称全部题目在最终提示词重跑。仍有偶发多余自我说明；小样本通过不证明任意聊天的事实性与自然度。离线完整回归 1227 项（10 跳过），最终策略回归 99 项（1 跳过），不代表真实 QQ 送达。

覆盖日常闲聊、偏好、夸奖、玩笑、情绪表达、作品／游戏的主观比较和自然追问。保留 Taki 直接、认真、会照顾人的性格。对“哪个牛逼”等口语正常理解，不因措辞就训诫用户，也不默认挑起群体攻击。

让模型在聊天、确定查询、审核知识、站内查证、必要澄清之间选择下一步；程序继续决定哪些操作可以执行。路由选择不是事实证明，也不授予账号、文件、网络或发送权限。

- 明确的主观感受可以直接聊；日期、数值、剧情经历、作品归属等事实继续取证。
- 混合问法分别承接偏好和事实，不把整个问题挤进闲聊，也不因为事实需要查证而丢掉聊天部分。
- 只有缺少对象、候选确实不唯一等情况才澄清。不认识一个别名时只核对那个词，不固定回复“请带名称或引用”。
- 已核实的别名统一解析；未核实的梗不能靠模型猜成两个不同人物或同一人物。
- 追问使用本用户、本群中成功 ACK 的上下文，保留绝对期限、撤审失效和短期文本预算。不读取整群历史，不引入跨会话永久记忆。
- 确定性直接指令继续零模型。每次新增模型调用仍分别预留额度、取执行许可、结算实际用量，失败不抹账。

PR #123 作为人格与聊天原型保留，实施 U2 时沿用其有效代码与证据，改写 PR 范围和验收，不把六类句式的成功当成开放聊天已经通过。采用固定截图题、改写题和未用于调提示词的新题，分别评估意图、事实、自然度及费用。

## U3：Haneoka／MoeNotes 站内自主查证

本批实现 Haneoka 目录候选 → 详情 → 已知关联及公告列表 → 正文。`site_search` 的关键词须来自原句，`site_read` 只能使用本轮返回的短期 handle；每问最多 3 次查证、4 次模型调用，保留 30 秒总预算并为最终生成预留 5 秒。程序追加实际来源、区服、版本／采集时间，不发送模型生成的网页链接。公告附对应区服的 Haneoka 公告页面，读过正文后换为该篇链接；歌曲／活动仅在用户明确索要网页、原文或链接且站内查证成功后附页面。固定域名和路径由已验证资源构造，不采用标题或模型输出中的 URL。已有歌曲、卡片、活动确定查询继续优先返回结果／图片，不以站点首页替代。

静态资料复用现有已验证主快照，先核对 JP 与 intl release，整个请求固定同一快照。支持歌曲、角色卡、留影卡、人物、静态活动、卡池；首批静态资源仅日服。活动奖励／加成／展示卡与关联歌曲保持独立；人物和卡牌按已验证 character ID 关联，不猜别名或挑战歌曲。每页 6 条、关联最多 12 条，部分列表明确标记，下一页也占查证步数。

公告通过固定 Haneoka 匿名接口读取，日服固定日文，国际服固定英文；不把台服／韩服自动当英文服。校验 available、来源时间头、语言和 ID；采集超过 24 小时或未来超过 5 分钟拒绝。列表与详情必须同一采集快照，标题及起止／更新时间也须相同。正文仅抽取文本，HTML 不执行、图片不下载，截断与未读图片明确标记；来源时间不是用户请求时刻，不宣称刚从游戏刷新。当前只读快照最多 100 条公告，不能当完整历史检索。

MoeNotes 暂无新增直接抓取路径，仍沿用已有 Haneoka／MoeNotes 来源关系；不在 Haneoka 失败时换源拼答案。剧情正文、社区内容、任意网页、历史版本和跨服联合搜索不在本批范围。目录版本变化、超时或快照冲突均停止，不增加后台全库刷新；不写百科、批准／撤销记录或永久记忆。

后端普通流程仍限 2 次模型调用，只有已验证站内工具进入 4 次上限；网关硬上限同步为 4，每次继续重查当前权限，第 5 次拒绝。新增模块纳入配对运行摘要，发布与回退必须配套后端／网关；旧网关不能完成第三次许可。现有持久 schema 无变更。

给 Taki 可组合的只读能力：搜索目录候选、按 ID 读取详情、读取关联资源、查当前活动与公告。模型选择关键词和查找步骤；后端根据已准入来源与资源类型构造请求，不执行模型任意拼出的 URL。

Haneoka API 优先，通过现有用户权限检查后，复用连接、缓存和同版本资料；MoeNotes 只补充已核对合同的公开数据或页面。两站来自同一上游的内容不能算两份独立证据。目录、别名与轻量索引承担候选检索，不假设上游已经提供任意全文搜索。

拟定工具循环上限：每个问题最多 **3 次逻辑查证操作、4 次模型调用**；保持现有 **30 秒执行总预算**，其中预留最终回答时间。工具内部复用既有 HTTP 体积、并发和超时限制，所有步骤共同受总截止时间约束。优先取少量候选与相关字段；分页也占查证次数，不能隐式遍历整站。隔离压测后可下调这些上限，不默认放宽总超时。

每步返回有来源、区服、版本／采集时间的证据对象；同一份静态回答固定 release，活动等实时信息保留观测时点和新鲜度。多个候选需明确选择规则，失败或缺字段不得补默认值。当前权限撤销、上下文过期或证据失效立即停止；只根据有效结果回答具体可确认部分，未完成项明确说明。

新工具循环复用现有队列、逐次许可、账本、慢提示及发送准备链。无页面内指令执行、任意浏览器操作、账号登录或生产缓存覆盖。站内数据访问失败不能悄悄换源拼出“完整结果”。

## U4：剧情检索与人格资料扩充

先取得剧情目录、角色／章节关联和可读取正文样本，确认实际覆盖后，再提取带角色名和上下文窗口的台词片段。按作品、区服、语言、章节、release 和片段位置索引；正文缺失、图片文字、只存在音频的内容分别标记，不把播放器目录当完整文本。

剧情回答给出章节出处，区分原文事实、角色当时的态度与回答中的分析。引用短片段并概括，不整章输出；用户未要求的重大剧情转折避免主动展开。游戏数值及规则仍由相应数据／审核知识路径处理，不能从剧情或同人梗推导。

**拟新增证据合同：** 经核定的游戏数据、官方公告和游戏剧情原文可作为当次只读取证依据；社区帖子标为玩家观点，不能升格为官方事实。长期百科的正文新增／改写与批准／撤销继续单独审核。临时查到的材料不自动写入正式百科，也不自动修改 Taki 的长期人格。

人格更新形成单独清单：原作依据、演员解读、助手创作选择分别列出。新台词习惯、关系反应和未确认兴趣先供用户审阅，再纳入固定设定。

## U5：必要时联网搜索

站内资料不足、问题具有时效性或用户要求查证时才搜索；偏好和玩笑不必联网。优先验证已有 DeepSeek 的 Search／Fetch API，账号可用性、费用和响应质量用隔离小样本核定；本计划没有实际调用这些收费接口。

建议首批每问最多一次搜索、至多读取两页，仍受 U3 总执行预算约束，不额外增加隐式循环。先限定官方与已核定站点；网页文本只作材料，不接受其中的指令。原始群消息、QQ 身份、私聊记录和密钥不进入搜索参数。

搜索／读取按请求计费，与模型 Token 分开预留和记录；现有每人每日 50 万、每群 500 万等价 Token 不变。单独的每日搜索费用上限在接线时核定，不能以“还有 Token”代替搜索预算，也不能静默重试产生额外请求。

核对 QQ 消息 URL 准入：来源链接仅发送平台允许的域名，未准入来源先使用站点名、标题和日期说明，并保留短期证据定位；不得编造引用或做任意跳转绕过。涉及扩大平台 URL 配置时列为正式接入项。

## 验收矩阵与发布门禁

| 场景 | 必须满足的结果 |
|---|---|
| 原题“你喜欢 ON 里的哪只乐队”及改写 | 正常表达偏好，不要求名称／ID，不产生网站请求 |
| “原神还是鸣潮牛逼”“邦 grp 还是 ON” | 接住主观比较；谈具体数据时查证，不胡编客观排名 |
| “偷摸零还是高松灯”及未知别名 | 先按已核实别名理解；未知时最小澄清，不编人物关系 |
| “这期／本期活动啥时候结束” | 进入活动查询，保留区服／时区，不触发错误对象拒绝 |
| 当前／历史／跨服／无进行中活动 | 不混服，不把最近活动或历史快照冒充当前 |
| 偏好后追问“为什么／还有呢” | 继承本用户已确认话题；未 ACK、过期和跨用户不继承 |
| 闲聊夹带抽卡概率、剧情或数值 | 主观部分能回答，事实部分有对应证据 |
| 搜索候选 → 详情 → 关联 | 有限步数内找到证据，版本一致，达到预算就停止 |
| 站点超时、空数据、冲突、撤审、恶意页面指令 | 不放宽来源／身份门禁，不把失败写成已核实 |
| 群内两人交错发指令 | 每条回复只 @ 对应发起者，内容／上下文不串人 |
| 图片、图片失败转文字、多段、慢提示、错误、继续 | 每条实际群回复原生提及正确用户；总消息数与序号正确 |
| 发送成功但 ACK 丢失、回执不确定 | 只恢复 ACK，不重发已送达消息来补 @ |
| 私聊、定时公告 | 保持各自发送合同，不误用上一位群用户身份 |
| 无可用搜索预算／权限被撤销 | 没有未获许可的收费请求；已发生费用不抹除 |

每批按实际改动完成定向测试、架构检查、相关完整回归与 CI。真实模型验证绑定提交、输入和资料版本；QQ 客户端验收另记录，不能被 mock 或平台成功回执替代。U1 和 U2 可分别审查交付，不以等待全网搜索为由拖延群回复修复。
