# 单图优先与统一美工

QQ 图片回复使用已确认的 Haneoka 风格：浅底、Noto Sans SC／Roboto、原尺寸字号、紧凑分组和游戏图标。独立卡面保持来源原始像素尺寸，固定彩蛋保留原输出。`/查留影卡` 为正式名称；旧 `/查支援卡`、英文／日文别名继续兼容。群聊文字、图文、续发及上传失败回退统一 @ 指令发出用户；单聊不加 @。

`/查活动`、`/查卡池`、`/查角色` 的列表及详情复用同一主题与预算。角色目录按乐队和来源顺序完整排列；活动／卡池列表逐条纵向展示，每条横幅与名称、时间并排，关联卡紧排在其下方。此结构参考用户提供的活动列表样图，Haneoka 提供素材与事实，不限定版式。详情保留主视觉与状态、起止时间并排。活动详情优先使用同版 1920×1440 主视觉及独立标志；卡池详情使用原始 420×180 横幅，列表横幅缩为 300×129，不放大。人物详情沿用资料图布局。角色目录、搜索候选及人物详情图片不显示查询指令（包括关联卡牌入口），姓名、资料与卡牌数量保留；查询入口仍在对应文字回复中。

关联成员卡使用 3:4 竖图、留影使用 16:9 横图，分别每行最多五张／四张，成员卡文字区为 176 像素、列步长为 196 像素，卡图尺寸不变；图下只保留完整卡名与角色名，不显示加成／奖励／展示／UP标签；长卡名、带英文别名的人名和多人名按原字号换行，同排卡牌按文字区高度对齐，不截断信息，避免末行只剩单字。活动／卡池图片不显示查询指令，查询入口及完整关联标签保留在文字回复。边框按实际等比缩放后的卡图范围绘制，属性及稀有度角标跟随真实卡图，不能给竖图套方框后露出渐变填充。静态活动歌曲只标“关联歌曲”，不附额外的判断说明，也不生成挑战榜查询。

长简介按段落或完整文字行拆图，列表优先保持整条活动／卡池及其卡牌预览同图；单条过长时按完整卡排续图并重复可视身份，文字不重复。图片与回退文字共享同一份 `InfoAnswer`，续发不重新查询。列表来源说明跟随最后条目，避免单独形成只有说明的续图。活动／卡池优先在 2800 像素高内分页，不缩字号；单个完整区块仍以统一传输预算为上限。

活动／卡池图片页脚只显示来源与影响判断的提示；完整资料版本、抓取时间保留在每图对应的文字回退中。旧缓存、未确认关联及账号展示条件仍可见，不将时间窗内直接写成所有账号均可抽。新增活动主视觉纳入部署前的素材下载、解码与摘要校验；无需上线后手动导入。

群图片通过官方素材引用与 @ 组成同一条 Markdown，显式图片尺寸并校验转存结果；接线与素材登记见 [网关说明](../koishi/README.md)。@ 标签按 [QQ 官方文本交互](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/text-chain.html) 使用 `<qqbot-at-user id="…" />`，ID 来自入站群消息作者。远端菜单安装和真实 QQ 送达需单独验收。

## 完整性与发送规则

1. 列表绘制捕获的完整结果，不再按 16 条截取。有效的旧页码语法兼容为完整列表；越界页码仍提示错误。文字 CLI 保持原分页接口。
2. 先测量实际文字、行高与完整内容，再决定画布和分栏。正文不为凑单图而缩小。角色卡保留队／演／激；未知技能显示完整已知说明。
3. 颜色按红、蓝、绿、黄、紫纵向；每种颜色内 SSR、BD／EX、SR、R 紧凑排列，不预留空稀有度列。成员顺序来自 Haneoka。技能起始位置在本排对齐。

角色卡与留影卡列表的原稿版本、哈希、人物左栏、多人头像右置和单图容量规则，见 [列表原稿约定](CARD_LIST_REFERENCE.md)。多人留影在相关人物组重复展示，卡牌总数仍按唯一ID计数，页脚区间表示展示位置。

普通角色卡／留影卡详情保持完整长图，不为缩短显示高度主动分页；只沿用下述编码硬预算。保留原字号和全文，固定 947 彩蛋仍使用原图。

其他出图的初始参考、后续确认及核对范围见 [出图参考检查](VISUAL_REFERENCE_AUDIT.md)。稀有度标识按各图标透明裁切、缩放后的实际宽高对齐卡面右下角，避免R／SR沿用SSR左边缘而偏位；图片列表和榜线不再用额外固定页高提前拆图。
4. 目前项目保守编码预算为 12,000,000 像素、单边 8,192 像素、3,000,000 字节（十进制 3 MB，base64 最多 4 MB；并非 QQ 官方上限）。超过预算只拆完整卡片行／详情区块／排名行／谱面列，保留原字号。单个不可分单元也超限时退完整文字，不裁剪内容。
5. 单次被动回复容量不足时发送可容纳部分，剩余编码结果保存在当前会话，提示 `/继续`。续发不重新筛选或重新生成；编号连续，按 ID 重新查询详情。
6. 图片上传失败，短文字直接回退；长文字分段保留并提示 `/继续`。发送回执不确定时不自动重发，也阻止不确定批次自动续发。
7. 续发沿用上下文时效、容量和身份隔离；重启、新查询或上下文过期后需重新查询。待发图片累计超过 128 MB 时优先淘汰旧上下文；最新单份捕获结果不会因该软上限而丢尾部。不会降低图中文字尺寸换取留存。
8. 角色卡和留影卡详情的图文统一展示满级基础值；留影卡除以 100 后显示百分比，不汇总综合力。绘图失败保留稀有度、类型、满级属性、全部技能等级、关联及来源；列表图文保留旧缓存及资料未获取提示。
9. 未获取的数值、身份、图像、技能和历史明确保留未知状态。历史断点不连线；榜线不推算未来或假定终榜。

## 模块与素材

活动默认总览使用 `activity-overview`：横幅居上，基础字段紧排，相同加成条件的对象横向分组，歌曲和显式关联卡池独立分区。相同奖励、数量及类别的获取条件可合并，积分／名次区间保持配对；关联卡只有在资源类型、ID 和角色均已覆盖时去重。保留完整档位、原素材比例和文字回退，按编码硬预算续图；详情子项继续使用档位表。

- QQ `_render_prepared` 向新 `*_layout.py` 传入同次查询数据及素材回调。`readable_pages.render_parts` 负责完整分段，`encode_image(preserve_size=True)` 禁止降尺寸。
- `info_layout.py` 接收纯 `InfoView`／`InfoRow` 与素材回调，不访问查询仓库。`scripts/preview_info_catalog.py` 可生成三类信息的合成离线样图；相关测试为 `test_info_layout.py` 与 `test_info_command_pipeline.py`。
- `visual_skill_contracts.json` 保存人工确认摘要与机制／日文模板指纹，匹配失败退完整技能；条件增强与等级成长分别展示。
- 等级按对应服务器成长曲线和特训上限（成员卡 `awakeCount`）计算。榜单头像直接使用同一行最爱卡的经验、特训和专精数据，不从最高分队伍补取；成员卡专精角标 `CardRankN` 使用卡组槽位的 `memberRank` 或榜单头像的 `favoriteMemberRank`，留影使用 `supportRank`。头像缺成长数据时保持等级／专精位置并显示未知，不切换成稀有度。渐变框为本项目绘制，稀有度与专精图标为游戏原图。
- 字体按 OFL 随包分发。游戏图标与 note atlas 不打包；`game_assets.json` 固定来源和 SHA-256。受管部署在停旧实例前自动准备 `game-assets` 与 `haneoka-asset-cache`，完整解码资料图片并记录摘要；损坏／缺失素材重取，准备失败阻止切换。榜线读取同一持久图片缓存，具体目录隔离见 [部署协议](../deploy/LINUX_OFFLINE.md#查询素材准备)。自行运行仍支持既有受限按需加载，原版 note 不可用时完整谱面退资料文字。
- 字体、测量和 note 重建使用有界缓存；解码缩略图 LRU 上限 32 MB，调用者拿独立副本。新布局按 URL／尺寸去重并发预取，最多6个工作线程；调用者负责释放自己的图像副本。

### 定稿阅读顺序与参考指标

歌曲列表每张先从上到下读左列，再读右列；查询编号保持原顺序，详情按 ID 查询。拆图按连续结果区间重新排两列，完整保留条目。

谱面优先尝试完整多列图，只收紧横向轨道，保持字号和纵向时间间距；仍超出像素或字节预算时按完整列拆图。

技能覆盖率、倍率、效率读取同 release 的 JP `song-meta`，仅展示 `legacy-normal-theory-relative-v1` 参考口径。效率含 30 秒参考间隔，不代表玩家实际得分或配队结果。来源的音符数不一致警告随图展示。旧缓存无此资源时显示未获取；未知参考模型不套用旧口径。新增资源通过既有响应身份、下载预算和整批刷新校验，不跨版本补值。

### 定稿 3 MB 预算验证（2026-10-14）

文件预算调整为 3,000,000 字节，像素和边长预算不变；上传入口与编码器共用该值。群聊及单聊离线上传模拟验证 3,000,000 字节完整进入 base64 请求，3,000,001 字节在网络前拒绝。此处为当时的预算验证；当前 @ 行为见文首。

使用生产常量重出 17 张定稿样图，全部满足预算。三曲总览为单张 2600 × 4615、2,591,439 字节，与已确认的 3 MB 预览逐字节一致；完整谱面为单张 2364 × 5062、2,130,926 字节。总览包含三曲、每曲五个排名的玩家及卡组、历史走势和页脚；更长内容仍按完整单元分图，不缩字、不删内容。

## 离线编码试验（默认关闭）

`encode_image()` 默认策略仍为原 JPEG 序列，返回 `bytes`；`encode_image_result()` 另提供格式、MIME、尺寸与逐次参数／字节数／失败原因。显式 `strategy="png-first"` 只接受 `preserve_size=True`：同一原画布先编码一次无量化 PNG，超过既有字节预算后按原 JPEG 质量序列尝试；不缩放、不从 JPEG 解码重编码。编码失败保留原异常与 `encoding_attempts`，接管的画布仍释放。普通图和谱面继续分别使用自己的几何／质量预算。

画廊可用 `--encoding-strategy png-first` 显式启用并记录实际格式和扩展名；机器人配置没有启用入口。真实 QQ 格式兼容、目标运行环境资源依据尚未验证，不能标为可上线。

## 单个活动完整视图试验（默认关闭）

`render_info(..., try_full_activity=True)` 仅对 activity 的单个 `InfoView` 尝试完整画布。复用原区块测量与绘制，几何准入后才分配候选；编码预算失败时恢复 `max_height=2800` 的原分页。不合并视图、不重分区块、不拼成品图；只有实际页数改变时，页脚续图提示相应变化。原单图不重复尝试；卡池、人物与卡牌列表不启用。

画廊参数 `--full-activity-view` 可独立或与 `--encoding-strategy png-first` 组合。合成区块像素对照只能证明此固定输入的完整性；缺原素材模板仍不算正式视觉验收，生产配置没有启用入口。

歌曲列表在同次绘制内按 URL／尺寸复用重复封面和属性图；唯一素材仍立即释放，重复素材在成功／失败退出时释放。复用不跨查询，不保存成品图，不改变共享缓存格式；性能范围见 [本次离线验收](validation/20261017-rendering.md)。
