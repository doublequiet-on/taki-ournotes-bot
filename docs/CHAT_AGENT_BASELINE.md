# 对话 Agent：C0 基线与约定替换

本批基线为 `c6028f9547c337fa09a5275eaef738dc84f847a6`。2026-10-29 成功 fetch 后的 `origin/main` 与该版本一致；开始时工作区干净、HEAD detached，随后在同一独立工作区建立 `codex/chat-agent-c1`。没有修改生产目录、排行榜业务或 X 翻译机器人。

依据为用户确认的 2026-10-29 开工包 `00_START_HERE.md`、完整方案和验收矩阵。旧实现继续作为默认 legacy；本批增加显式可选 Agent。下表只替换聊天产品约定，既有权限、来源、额度与发送规则继续执行。

旧行为定位：`application/model_runtime.py::prepare/run/run_site`、`persona.py`、`model_execution.py::ModelPermissions.acquire`、`sources/model_provider.py::decode_attempt` 和 `koishi/src/receiver.ts::authorizeModel`。这些旧限制由源码与保留的 `NativeRuntimeTests` 核对；没有调用真实模型复现文风。

配置复用 `ModelConfiguration` 捕获的同一 `ModelProfile`：provider、model、wire_profile、config_version、capability_evidence、价格、输出额度与 reasoning_effort 均不重写。本批没有读取生产密钥或猜测 Terra 的实际 API model ID。离线使用合成 DeepSeek wire 和 OpenAI Responses wire，后者覆盖 reasoning／多工具续接；不能据此宣称 Terra 实测兼容。

默认人格为 `taki-v0/legacy-derived`，是明确标注的运行初稿。K1 已补来源目录、场景引擎和人格研究草稿，真实人格审核未完成；只有独立人工批准的版本才替换初稿。本文保留 C0 约定，组合现状见 [F1](CHAT_AGENT_F1.md)，不批准新的百科正文。

## 普通聊天的版本上下文

`OURNOTES_KNOWLEDGE_CHAT_VERSION` 可配置资料版本基线（例如 `1.1.0`），日服与国际服默认共用。未指定版本或日期的知识查询同时检索通用资料与该版本资料，共享原有六段/6000字符预算；证据仍分别绑定原作用域和批准记录。配置值不是线上最新版本探测结果，也不改变文档的适用服别或已批准正文。

聊天资料查询未指定区服时默认日服；单独说明“我玩国际服”是用户背景。明确询问某服卡片、歌曲或规则以及比较日服与国际服时保留用户条件，不将资料改为日服。对比时站内查询分别保持各服来源；固定卡曲目录目前只有日服资料，国际服缺项应如实说明，不用日服结果冒充。

明确版本、历史日期及已确认追问范围优先，不自动改写为默认版本。未配置时保持原有通用检索行为。更换游戏版本时应核对资料并更新配置，而不是从库中最大版本号猜测当前版本。

## 主动发起预算与回复后的接续

Responses 主动接话分为判断和正文生成：判断阶段保留身份、来源、批准人格及参与规则，正文阶段使用完整聊天规则，避免把正文写作说明重复挤入判断输入。两阶段仍使用原输入上限、工具与图片预算，不截断必须保留的来源。必需输入超限时，诊断记录输入上界、上限、系统提示与工具字节数和图片数量，不记录聊天正文；这些数字用于定位预算，不代表提供方实际 token 用量。

发送许可在生成后、实际发送意图之前再次检查。普通主动候选继续使用观察版本、期限、来源删除及策略验证；免 @ 续聊若出现未纳入判断的新观察，旧回复不再具备发送许可，保留窗口供后续重新判断。该检查不阻止已经开始生成的回复完成并计费，不丢弃已实际发送后的 ACK；显式点名／查询的普通回复不因其他人的旁聊失效。这是上下文新鲜度保护，不会把新发言的内容自动判成“别人已回答”。

`tests/fixtures/chat_turn_taking_cases.json` 提供八对共十六条合成对照场景，人工标签覆盖引用对象、补充、转述、旁聊、回声、感叹、收尾和媒体缺口。`test_chat_scenario_inputs.py` 导出不含期望标签的输入；这些材料与原研究的十七条留出样本分开。离线测试验证输入、门禁和回执契约，不等于测得模型的语义判断正确率。

主动发起按群分别限制判断次数、实际模型调用、成功回复、小时费用和可选北京时间日费用。`max_cost_micro_per_day=0` 与 `max_evaluations_per_hour=0` 保留旧配置语义；新版控制台可分别设置。日预算是小时预算之外的额外上限，仍计入全局主模型日预算。配置了非零日费用上限的主动服务，已结束但计费不完整的调用在账本 created 满一小时后退出小时统计，仍以保守上界持续占用日预算，跨日、重启或更换服务主体均不清零；仍在预留或执行中的调用继续占用小时及日预算。未配置日费用上限的旧主动策略，以及摘要服务，保留原有未知费用跨小时占用规则。

设置了日上限的主动接话按 UTC+8 日内逐步开放新额度。先从日上限扣除前几天仍未确认的费用和在途预留，再用本日净额度开放至多一次完整判断和回复所需的预留，其余部分在 24 小时内按时间均匀释放。本日已知费用、未确认费用和在途预留共同消耗已开放金额，未用的预留释放后可再用。零点按账本重新计算，未核账占用继续跨日。

候选准入前，宿主会用持久账本校准本群尚未结清的内存费用票据。只处理对应工作已不活跃且所有调用记录均为 settled／released 的候选；在途预留、仍可追加调用的活跃工作、缺失账本记录均不释放。已结束但用量未知时仍保留上界，晚到已知用量再结算；读取失败拒绝新准入。校准不改变候选有效性、送达状态、历史费用或任何费用上限。

机会准入按剩余费用裁剪预算，至少支持判断与正文生成；每次实际调用再按序列化输入上界、输出上限与搜索上限预留。本轮结束后，内存占用与持久账本使用相同的单次调用费用上界；提供方失败且用量未知时，继续保留实际已发起调用的预留，不保留已取消、未发起的后续调用额度，费用状态仍为未核实。取消后仍在途的后台调用在真正结束、释放未发起请求后再次同步内存占用；取消期间保持原预留，晚到结果不恢复发送。工具、续判和末次生成合计仍不能超过该机会额度。门禁诊断区分小时、日费用、预留不足、调用／回复次数与冷却。

主动回复确认送达后可建立有界续聊窗口，原交流对象后续发言由模型判断是否仍在对她说话；其他成员的明确点名或引用沿用既有平台核验的普通对话路由，保留原消息作者。未 ACK、撤回、过期和其他群的消息不能建立或复活窗口。主动发起的间隔不阻止这类续聊；续聊沿用普通交流权限、模型与全局费用限制，不能把同话题旁聊自动认作邀请。

本次确认的目标群限额为：小时费用 600000、北京时间日费用 2000000（均为 USD 微单位），每小时判断 30、主动回复 10、主动发起间隔 60 秒。模型调用与判断次数分开：实际请求技术上限 120，以容纳两阶段正文和工具续接；全局 $3／天保持现值。只能通过受信控制台的限额保存入口、带最新 guard 更新原有已批准群，不能复制配置来扩大批准范围。新字段应在应用上线后保存，旧应用不识别新字段时会禁用该群服务，不自动删除字段或清账来绕过。


## 连续群聊与社区用语

显式点名与主动接话均在输入预算内优先保留最近两轮完整问答，包含原发言者和回复关系；较远背景先裁剪，单轮过大时保留可容纳的完整轮次，不扩大模型输入上限。提问中的省略对象、事件类型及比较维度交给模型结合上下文判断；检索继承当前讨论主题，澄清只补确实缺少的部分。

`domain/chat.py::COMMUNITY_TERMS` 保存维护者在本次讨论中确认的“烤羊／烤猫”语义，用于理解声优讨论中的锐评和指代；明确饮食或动物话题仍按字面理解。社区释义不作为演出、配音或其他具体事件的证据。来源：[Bangumi 社区释义](https://bgm.tv/group/topic/408544)、[B站“烤猫”使用实例](https://www.bilibili.com/video/BV1qw4bzZErF/)。

联网来源已在正文链接时不重复追加；仅忽略 `utm_*` 跟踪参数，保留区分文章的查询参数，补充来源标题最长 64 字符。离线回归验证模型实际收到的历史、用语提示和引用格式，不将桩回复视为真实模型的接梗效果。
