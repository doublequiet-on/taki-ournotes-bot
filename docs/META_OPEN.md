## 配置、启用与回退

| 配置 | 默认／作用 |
|---|---|
| `OURNOTES_META_SOURCE` | `moenotes`；`haneoka`显式恢复旧分数表解析和预计算来源 |
| `OURNOTES_CUTOFF_SOURCE` | `tracker`；正式认证验收通过后维护者才改为 `open` |
| `MOENOTES_OPEN_SECRET`／`BDON_OPENPLATFORM` | 空；二选一，前者非空时优先。由安全配置提供，最低 rankings 权限，Settings repr 隐去 |
| `OURNOTES_OPEN_HISTORY_FILE` | 主缓存旁 `moenotes-open-history-v2.sqlite3`；必须与旧历史路径不同 |
| 原历史／采样开关、服务器、间隔 | 保留原配置；四服及默认300秒，不因日额度调整 |

无 Secret 不影响公开分数表；即使选择 open 但 Secret 缺失，也只返回正式来源认证状态，不自动换源。初始化与 `configure_sources` 不请求数据或启动采样。生产配置、当前运行 SHA 与实际采样开关必须在发布阶段单独核验；本次未读取真实 `.env`。

公开分数表缓存为主缓存旁 `moenotes-music-data-v1.json`，不覆盖 `haneoka-meta-jp.json` 或主资料。公开 tracker 当前缓存和正式当前缓存分别位于 `moenotes-cutoff-v1`、`moenotes-open-cutoff-v1`。分钟／冷却状态为独立 `moenotes-open-admission-v1.json`，无 Secret；回退代码、来源或更换 Secret 不删除该状态。

正式点仅写入独立 schema2 库，记录 source、time_kind、contract_version，仍只保存分数。旧 schema1 文件不迁移、不清空、不补写；旧代码回退继续读旧库并忽略新库。新代码有界读取两库，来源不同的相邻点断线并说明口径。新库未知版本、旧v1路径或含未识别观测的无版本库明确拒绝；空的新库初始化为事务，可恢复尚未有观测的初始化缺口。

## 参数合同

裸命令等价于：

```text
/查分数表 全难度 排行=效率 场景=激奏 激奏排名=1,1,1 Great=0 Just=100 技能=100,100,100,100,100 时长=BGM 额外耗时=30 前沿=否 排序=desc 前30 页1
```

四难度共池，同曲不同难度独立计数，前30指谱面条数。精确单曲未指定难度默认EX；`搜索=`是列表过滤，未指定难度仍混合。`/查效率`保留。直接命令和确定性 `/问` 共用同一规范与求值，不调用模型／额度。

| 参数组 | 有效值、单位及规则 |
|---|---|
| 裸歌名／审核昵称／ID、`歌曲=` | 唯一新源歌曲实体；完整数字歌名先保护，再按既有ID／短ID规则；歧义列候选ID |
| `搜索=` | 标题多语言、ruby、phonetic、词曲编曲、乐队及musicId子串；字符串需有值，不转换成精确选择 |
| 裸乐队、`乐队=` | 确认的唯一乐队，按 bandIds 匹配；含空格名称保护，条件冲突拒绝 |
| EZ/NM/HD/EX／全称、ALL／全难度 | 可逗号多选；固定 EASY→NORMAL→HARD→EXPERT，并集去重，不归一化难度得分 |
| `排行=`及无歧义简称 | 效率／活动／速度／等级／Notes／最长／最短／跳过得分；默认效率 |
| 单局、`指标=score`／`metric=score` | 单局单位综合力分数排序；`指标=eff`映射效率，两个意图冲突不猜 |
| `速度=N/s/BPM/最大BPM` | 自动选速度；密度、主要BPM、最大BPM独立，默认N/s，缺值不互换 |
| `场景=激奏/自由`、裸场景 | 默认激奏；只适用于效率、单局、活动 |
| `激奏排名=` | 一个1–5整数展开三段，或严格三个；默认1,1,1；仅激奏场景 |
| `Great=` | 整数0–100%，可带%；默认0，两个计算场景都可用 |
| `Just=` | 整数0–100%，默认100；仅激奏；与Great没有和为100的约束 |
| `技能=` | 五个0–150%，最多两位小数；全150／全100／无展开五值；默认全100，不补项或钳制 |
| `时长=BGM/谱面` | 默认BGM；所选音乐长度缺失可回退另一长度，逐条标明；两者缺失为未知 |
| `额外耗时=` | 0–600秒、最多两位小数；默认30，以Decimal准确转换毫秒；效率／活动与单局效率辅助值 |
| 前沿、`前沿=是/否` | 默认否，只适用效率／活动；不是散点图Pareto筛选 |
| `目标=` | D/C/B/A/S/SS，活动默认SS；缺所需阈值不补0 |
| `综合力=` | 活动，0或未设不显示机会；正整数最多2³¹−1，仅为输入保护，不称游戏上限 |
| `人数=` | 活动激奏1–5，默认5，假定玩家同分；自由为单人阈值，显式人数拒绝 |
| 前10／20／30、页N | 默认30、页1；页码1–100；完整排序后分页，单曲一页 |
| 颜色／属性 | 红蓝绿黄紫，多选OR；未知所需属性不参与，分别报告首数／谱面数 |
| 激奏／击奏任务 | 包含、纯类型、混合、有序重复序列、包含全部五种旧规则；与计算场景分开 |
| `lv<、<=、>、>=` | 一个1–40的小数等级边界；不同边界冲突，仍不接受`lv=25` |
| `排序=`／`sort=`、最高／最低 | asc／desc；默认方向见下表；不反转并列scoreId规则 |

一致标量可重复、冲突标量拒绝；只有难度、颜色做明确并集。任务顺序不能排序去重。完整参数组可任意移动，NFKC／大小写／中文列表逗号归一化，先保护已确认完整实体、引号和字段值。五技能与三名次不拆成裸数字。余词、未知字段、错误项数、NaN／Infinity、布尔冒充数值及越界全部明确拒绝；网站的四舍五入／钳制不移植。

```text
/查分数表 前10 技能=全150 自由 HD,EX MyGO
/查分数表 乐队=MyGO HD,EX 场景=自由 技能=150,150,150,150,150 前10
```

两条规范查询相同。回显只输出适用条件；内部未显式提供的Just／名次默认值不会让自由场景报错。`自由 Just=80`、`自由 激奏排名=3`明确拒绝。`/下一页`、`/上一页`、`/选 2`、`/详情`、`/难度 EX`保留全部条件、页内号／全榜号／比较池号，选择锁定scoreId；快照或词典变化明确要求重新查询，不悄悄换源。

## 计算与排序

生产仅Python≥3.10和原依赖，不新增Node／Bun／Rust。有限求值器读取许可明确的统计模型；没有运行播放器、复制前端算法或推导实际队伍综合力。

允许普通全队5秒加分kind，验证模型power、五位置权重及必要数组。激奏用seeds，自由用offSeeds；激奏不可玩不拿自由统计补算。改名次移除原奖金并按三段重新trunc，同步范围技能权重；Just按全Just／全Perfect插值后重新取整，Great因子为`1−0.2q`近似。用户技能百分数直接除100，不再走master技能转换。

```text
unit_score = base + mean(skill_factors) × sum(position_weights)
efficiency = unit_score × 60000 / (实际音乐长度ms + 曲外耗时ms)
```

单位分别为分／综合力、分／综合力／分钟。不同谱面都使用同一单位综合力条件；真实同队综合力随属性／标签变化，本功能不推导。

| 模式 | 原始排序值／默认方向 |
|---|---|
| 效率 | 每分钟单位分数／降序 |
| 单局兼容 | 单局单位分数／降序 |
| 活动，无综合力 | 目标阈值／均值单位分数（均值所需综合力）／升序 |
| 活动，有综合力 | 模型达标局数每小时−need×10⁻¹²／降序 |
| 速度 | N/s、主要BPM或最大BPM／降序 |
| 等级 | displayLevel×100000＋judgedNotes／降序；任一缺失不补0 |
| Notes | 判定Note／降序 |
| 最长／最短 | 实际所选音乐长度／降序或升序 |
| 跳过得分 | 默认统计场景下可用的skip单位系数／降序 |

并列scoreId升序，使用原始值排序，显示精度不参与排序或达标判断。0有效，None未知。N/s分母为第一Note到最后判定Note跨度，与BGM和曲外耗时独立。跳过系数乘综合力不等于游戏逐Note取整后的整数得分。

活动自由用requiredScore，激奏n人用`trunc(sqrt(5/n)×battleRequiredScore×n)/n`，前提同分。设置综合力后枚举120个有身份、等概率技能顺序；相同技能不能去重改变权重。机会只代表seed均值系数下技能顺序的达标比例，goal为该比例×局数每小时，均不等于真实活动积分或原生随机种子概率。未设综合力不显示概率；所需综合力显示向上取整并标均值估算。

效率前沿检查技能均值0／1.5的单局分数和无曲外耗时效率，对全部c≥0成立；600秒输入上限不缩小数学定义。活动前沿还需要完整六档阈值和长度；缺必要证明字段排除并报告，不能因没有可比较值而宣称已证明。默认详情给出比较池相对最高效率以及支配数量，不在图片罗列内部scoreId。

固定执行次序：模式能力＋乐队／难度／旧颜色任务等级构成完整有效比较池 → 求值、排序、前沿、最高效率基准 → 搜索／精确歌曲／前沿过滤 → 总数与序号 → 分页。搜索不重算比较池、相对基准或前沿，升序和分页不改变最高效率基准。

显示单位系数三位小数、机会两位小数、长度0.1秒。对拍普通数值容差为`max(1e-9, |参考值|×1e-10)`；候选身份、原始顺序、缺值、前沿集合和达标顺序计数严格一致。容差不参与正式排序。

## 缓存、预算和视觉

快照TTL300秒，ETag／Last-Modified条件重验证；304只更新验证时刻，保留原成功获取时刻。传输8MiB、解压32MiB分别流式限额，gzip截断／拼接／坏JSON拒绝。只保留求值必要投影，丢弃aptitude／SNAP／回放大对象。校验成功后原子写入新命名空间，写盘失败仅内存可用且标未落盘；格式／身份异常保留上次版本。失败退避30→60→120→300秒并加有限抖动，同源旧快照最长24小时，明确旧缓存。

求值LRU至多64组，按完整规范参数、快照SHA与求值器版本隔离，页码作为完整结果投影；缓存状态加锁，计算可在锁外执行。完整求值／前沿预算8秒，种子和前沿循环内检查截止时间，超时不给部分排行。捕获快照超过24小时、版本变化或续查失效均明确终止。

现有画布、布纹背景、主题、字体、圆角、封面裁切、难度标识、列表逻辑宽1500、基础行高112及自动增高规则保留；八模式只更换原时长／系数／效率三个区域的文本和值。精确单曲单难度沿用原900宽文字卡片，多难度对照用原列表表格。条件scope超过四行转入原说明区，不缩字号或截条件。图片仍遵循原1.5MB／8192长边／1200万像素、两倍绘制及JPEG编码。固定旧内容与基线renderer生成的JPEG逐字节一致。

单曲卡片按歌曲／难度、主要结果、条件和来源排列文字，不塞入列表竖线表格或重复分页；新模式使用通用分数表标题。图片条件采用可读摘要，完整可复制命令及续查语义保持；引号内搜索值先保护，不因实体识别或分隔符归一化而增删空格。时长回退在原说明区按本页行号列明实际BGM／谱面口径。正文SHA、模型版本、HTTP发布头存于`MetaAnswer.diagnostics`及来源缓存，图片仅保留来源、覆盖、适用模型说明和明确标注的本机获取时间；基础事实排行不显示无关算分说明。像素冻结比较证明样式原语稳定，不替代实际新内容排版验收；缺失真实封面／任务图标的样图不能证明全部素材等价。

QQ预预算完整捕获文字的1800字分片及其他命令，最多五条；图片成功仍一张，上传失败才发预分配文字。完整文字仍超限则要求前10／拆开，不截数据。部分发送或不明回执不提交上下文，不重新查询或盲重发；真实QQ尚需另外授权。

## 正式榜线合同与认证门槛

```text
GET https://bdon.moe/api/open/v1/moenotes/{region}/event/challenge-ranking?challengeMusicId=<十进制字符串>
Authorization: Bearer <安全配置的Secret>
```

只请求具体challenge operation，不附eventId／musicId／排名区间；一次读取后本地裁切原Top100、附近十名、闭区间、离散点。`hk→tw`和日服默认不变。数字ID保留前导零／长整数，用户名来自同条记录；profileId不替代玩家数字ID。protobuf JSON经过形状校验的对象行可省略score表示0，显式null／非法类型／空洞仍未知；旧tracker缓存不套此解释。

正式源只消费`X-Moenotes-Fetched-At`为源时刻；Unix毫秒合同需认证验证。HTTP Date仅在与接收时钟足够接近时作为可信年龄参考，不代替源时间。当前fresh120秒、过期600秒及同源旧缓存边界保留；时间头缺失或参考时钟不可信隐藏当前分数及附属身份、不写有效历史点；异常观测保留质量和缺口。结束后只称最后获取，非确认终榜或tracker最后观测。切期／映射变化丢弃不可靠结果，原位置不挪动。

认证与匿名请求分开session，固定目标、禁止重定向，Secret不进入URL／repr／CDN／异常正文／缓存／历史／QQ。本地最多3个共享外网槽、总截止时间、有界查询队列和同榜请求合并；正式网关远端缓存命中也按实际合同计调用。

| 故障 | 行为 |
|---|---|
| 401／403 | 安全认证／权限状态，停止重复请求直到Secret配置变化 |
| 404 | 本资源不存在或不支持，保持请求身份，不自动改接口 |
| 429 | 尊重Retry-After，共享冷却，记录失采，不无限积压 |
