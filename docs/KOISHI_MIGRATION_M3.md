# M3：Koishi 查询与续查接线

M3 在 M2 提交 `0a48624ab8e4268e5469b577358b1635895700c2` 上继续，实现原始事件 → 作用域/权限 → Python HTTP → 逐片段 QQDelivery。插件默认关闭。生产切换另行确认；周期刷新、HistorySampler、主动通知和部署就绪改造归 M4。

## 配置与生命周期

先按 [后端协议](KOISHI_BACKEND_V1.md) 使用隔离业务目录启动后端。Koishi 与后端注入同一个至少 32 字符的 `OURNOTES_BACKEND_TOKEN`，令牌不写进插件配置、日志或 URL。以下只是配置示例，不代表已连接真实账号：

```yaml
enabled: false
instanceId: taki-test
appId: APP_ID
selfId: BOT_SELF_ID
backendUrl: http://127.0.0.1:8765
tokenEnv: OURNOTES_BACKEND_TOKEN
permissions: [authority:1]
maxPending: 8
```

身份必须与后端命名空间及 QQ adapter 实际 AppID/selfId 一致。只支持明确的 loopback URL。启用后先检查协议 1.0、候选能力和 `classify`、`gateway_retire`、`ack_context_guard` 特性，再登记随机运行代次；不兼容或初始化失败停止接纳，修复后重新加载插件。后端重启也需要重载插件取得新代次。

QQ adapter 必须使用 `retryWhen: []`，避免在适配器内部重试未知结果的发送。WebSocket discovery 窄修正仅替换旧 `api.sgroup.qq.com` / sandbox 主机，保留实际返回路径、参数与其他字段；显式 gatewayUrl 同样处理。插件在适配器连接前安装才能影响首次 discovery；已经连接的适配器不会因此重连。卸载恢复本插件仍拥有的包装/配置，不停止其他插件。

## 命令、权限与顺序

共享 Python 入口只读识别已有命令、别名、多命令和续查；识别不查数据、不调用模型、不扣额度。实际查询沿用现有准备入口及本地优先 `/问`。Koishi 不复制游戏解析规则。Taki 的 `/帮助` 在本插件作用域内优先；后端正常时，普通聊天和不属于 Taki 的命令交给后续中间件。后端不可用时，已定向的候选消息停止处理并记录脱敏错误，不绕过账本直接回复。

root 原始事件钩子先捕获消息身份和到达序号，避免 legacy 字段在默认适配中丢失。标准化后重新检查插件作用域；有数据库时使用 Koishi 实际用户/频道观察、ignore/assignee 检查和 permission 服务。权限不通过不会登记业务查询。相同消息的冲突原始事件不能替换首次捕获正文。

识别、权限和轻量 HTTP 接纳串行；接纳后准备和发送异步进行。后端保留 M2 已实现的唯一 ReplySequencer 及既有超时退化语义，网关不另开一套发送排序器。原始序号的高水位仍拒绝适配器或网络造成的迟到旧接纳，不能把迟到旧请求作为新一代上下文。此处沿用 M2 排序所有权，是方案建议位置的实现差异，不改变全局排序的配置语义。

同一原消息只拥有一个 QQDelivery。每片段遵循落盘 intent → 一次实际发送 → ACK 确认 → 下一片段。intent 响应丢失不重发，ACK 可有界重试；每次 ACK 重试重新检查卸载状态。图片上传失败只使用后端同次捕获的备用文字；媒体发送结果不明停止后续片段。长备用文字与超过五张的余图由 `/继续` 消费已捕获游标，选项、翻页、详情与难度沿用既有上下文。

卸载立即禁止本地后续发送，撤销后端代次后等待在途发送。即使撤销 HTTP 失败，卸载后发起的 ACK 带 `allow_context: false`，只补记平台事实；已经在卸载前提交的 ACK 不可被回溯撤销。新代次、租约、generation 仍由后端校验。

## 有界运输

原始事件缓存最多 512 条、每条 JSON 32 KiB、正文 16 KiB，保留至候选窗口 298 秒；超过容量停止接纳。网关在途容量最多 8（包含等待准入），每批最多 5 片段，逐张获取图片。JSON 响应最多 128 KiB，图片最多 3 MB；后端 HTTP 单次含读流超时 10 秒、幂等调用最多三次，QQ 单次运输 15 秒。图片 MIME/资源归属受校验，禁止重定向和任意 URL。此处不是进程 RSS 实测上限，真实 QQ 窗口/额度仍待实机验收。
