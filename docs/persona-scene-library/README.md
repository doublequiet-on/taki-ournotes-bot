# 立希场景库与群聊回放

开发基线为 `428a62b1582c116f46e97f88b3bfaff2ec449a04`。这里的材料供 Taki 人格内容审核和独立回放使用。

- [场景资料](scenes.md) 覆盖三部作品的 26 段对白。每行记录对象、触发、反应和收束，并标注字幕存档或游戏文本镜像的证据状态。
- [原创范例](examples.json) 从参考场景提取交流动作，改写成独立的中文群聊。原有关系和剧情信息留在场景资料里。
- [留出题](cases.json) 有 18 道非群梗题和 6 道合成语用题。非群梗题按不同集／话划分来源，输入使用新话题和措辞。六道合成题覆盖局部外号、字面反例、反话、待补背景、未知词旁的可回应部分和跨群纠正。
- [回放脚本](replay.py) 提供选择规则、本地请求检查、公开资料代理回放及匿名样卷生成。模型对照见 [回放结果](RESULTS.md)。

## 审阅立希的回应尺度

| 交流动作 | 依据 | 审阅问题 |
| --- | --- | --- |
| 先落到目标或下一步 | M03、O01、O10、O11 | 有具体选择、约束或动作吗？群友需要的如果只是意见，能否说完观点就停？ |
| 听见修正就更新 | M04、A02、O04、O06 | 证据够时接修正后的内容。证据只够动摇旧话时收回确定语气，别编记忆或道歉缘由 |
| 关心落在已经看见的处境 | M04、A06、O05 | 先接当下能做的一步。对方独立处理时留余地 |
| 熟人可以轻轻回嘴 | M06、O03、O08 | 只跟已出现的调侃强度。对象从行为滑到人格或身体时停下 |
| 情绪转折允许停顿 | O05、O07、O13、O14 | 肯定或关心可以含蓄，收到回应可继续做事。内心独白留给角色证据，群聊只回应当前可见信息 |
| 压力剧情提供力度边界 | M02、M05、A01、A03、A05 | 排练和团史的高强度反应跟特定关系和情景绑定。新群友的普通失误只需要纠正那件事 |

可审阅的人格补充稿如下。

> 先说你对眼前这件事的判断，给一个具体理由或当下能做的动作。对认真在做事的人指出哪一处可以再好点，也看得到他们已经做好了哪一步。听到足够明确的纠正就接新信息。遇到熟人明摆着在玩笑，可以顺着那个笑点回一拍。对方已经收尾、在和别人说话，或只是等人补完整时，就把话留给他们。普通话题可以是短评、具体关心或一个直接的选择。认真讨论按需要说理由。

稿中是从场景归纳出的表达建议。申请人格更新时，先由内容所有者审阅每项场景及其使用范围，按 [StoryService 批准流程](../STORY_ENGINE.md) 将采用的内容登记为分析 claim，关联合法收录的对应来源和场景。字幕经过翻译或镜像承载的证据如实记录，不能用于把分析升成原作事实。当前场景表是索引与释义，`Scene.utterances` 需要由维护者从获准原始材料另行填写。将建议稿放入新版本的 `PersonaRelease` 草稿，人工 review 后由 operator 绑定当前 revision 独立批准。当前审阅稿无批准记录。

## 选择与集成

固定组每题给 e01 和 e09。选择组用同一份库，读取从当前目标及已绑定上下文抽出的 cues，每种类别至多取一条，最多取两条。优先承接纠正、关心和情绪，再处理排练、普通意见和熟人玩笑。纠正、关心或情绪场景的玩笑线索不进入选择。同类按文件的既定顺序选首条，额外条目留给后续轮换实验。没有足够线索时给零条。

本轮对题目标注 cues，测的是**条件标签已知时**选例的效果。它不会因为「别逗」或一个词命中就假定熟悉关系。线上若集成，宿主应从当前回应目标、说话者和有证据的关系决定是否传 cue。缺失、低置信、请求事实或纯工具查询保持零条。选中的内容仅在已经进入闲聊正文的请求里作为用户看不到的示意，来源和撤回随批准的人格版本绑定。将来实现自动标注时另用留出输入验 cue 精度，尤其是多人、反话和转题。无需为选例增加一次模型调用。

## 群梗

先根据眼前对话找对象、反话和当场说明。词义未定而周围有清楚可回应的内容时，可以只回这部分。依赖那个词才能理解、群友正在补充、已有他人回应时，主动场景给群友留空间。

长期记录只用于群内反复出现、当场缺上下文就容易误读的用法。建议每条最少保存群范围、词／别名、适用情形、反例或字面含义、脱敏确认材料与确认时间、有效期和状态。群管理员可补反例、缩小范围、纠正或撤回。每次使用重新核对所属群、活动期和当前话题，当前可见的纠正优先；撤回、确认材料被删或到期时不再提供。只留最小必要的脱敏依据，禁止用用户的任意一句话自动定为长期释义。

本线没有获得可用于建立近期真实词条的新批准样例，因此真实条目留空。合成「烤年糕」同时有重连和食物两个情形，只用来核对解释选择。真实新词进入审阅时需要同群的明确确认、可用于本任务的脱敏片段，以及至少能判断何时不适用的上下文。原作资料、群内语用与事实查询沿各自现有入口审核。

## 复跑

从 checkout 根目录执行 `python -X utf8 -B docs/persona-scene-library/replay.py --check`，检查引用、留出和选择。`--capture <固定合成捕获文件> --story-root <已批准的隔离档案根>` 在本地核查批准指纹、版本及三组构造。这个入口仅保留请求数量，捕获文件和人格原文留在可信本地。

用新的输出目录运行 `python -X utf8 -B docs/persona-scene-library/replay.py --public-proxy --out <输出目录>`。通过已有环境变量提供 API 密钥。此入口只使用公开角色资料独立撰写的提示和本目录原创题、范例，由 gpt-6.1-terra medium 写正文，gpt-6-astra low 匿名打分。固定同一题的上下文，其余各组仅改变是否及如何注入范例。采样一次，逐题随机候选牌面。盲评样卷可直接交给群友评阅，发放时只给样卷。 [公开角色资料](https://anime.bang-dream.com/mygo/character/taki/)

输出包含固定输入与脚本的指纹、API 请求摘要账、提供方用量、盲评样卷和独立牌面对照。发放样卷前保留映射用于回收，汇总以三列齐全且已判分的题为准。`<TAKI_SKIP>` 与普通文字都交评审判断。整体统计含静默题，评估正文时另看非群梗题中的应答场景，避免静默通过抬高口吻均值。
