# 借用子域名接入 Taki 控制台

状态：配置准备，尚未绑定真实域名、签发生产证书或发布公网入口。基线 `be8817f`。

## 合作范围

采用“对方提供子域名 DNS，你的服务器运行 HTTPS 入口和 Taki”的方式。对方无需提供服务器账号、主域 DNS API 密钥或机器人凭据。子域名不代表共享管理权，也不会让对方自动成为控制台管理员。

需对方确认：完整子域名、允许用途、使用期限、变更／收回联系人。域名和服务器 IP 均以实施时核验结果为准。模板使用 `console.example.invalid`，不是已获授权的 Haneoka 地址。

可直接转发：

> 想借用一个子域名作为 Taki 私人管理控制台入口。机器人和数据仍在我自己的服务器，我负责 HTTPS、密码登录、更新与备份，你们只需协助添加 DNS 记录。请确认可用子域名、使用约定及后续变更联系人；地址确认后我再提供记录值和验证步骤，不需要你们提供主域密钥或服务器权限。

## 待填写项

| 项目 | 要填写／核对的内容 |
|---|---|
| 完整域名 | 对方明确同意的独立子域名；本方案不使用主站路径 `/taki` 挂载 |
| DNS | A 记录指向你的已核验公网 IPv4；建议初始 TTL 300；无可用 IPv6 时不添加 AAAA |
| 接入方式 | 初期只做 DNS 解析，不启用第三方 CDN／代理；若需代理，另验 WebSocket、TLS 和真实客户端地址 |
| 服务器条件 | 地域、云厂商公网网站接入要求、80/443 占用、安全组／防火墙；不可覆盖现有网站 |
| 证书 | HTTP-01 webroot 自动签发／续期；核对继承的 CAA 是否允许所选 CA |
| 管理入口 | `https://<完整域名>/taki`；保持现有独立控制台密码 |
| 回退入口 | 保留 SSH 隧道到 `127.0.0.1:5140` |

使用中国大陆云服务器时，先向接入商核对该管理入口适用的备案／接入要求。借子域名、父域已有备案、使用 CDN 或 IP 均不能自行当作已满足接入条件的证明。若不满足，先确定合适的入口部署位置，不直接开放。

## 配置文件及信任边界

- [HTTP 与证书验证模板](../../deploy/koishi/console-domain-http.conf.example)：80 端口仅提供 ACME 验证目录和到固定 HTTPS 域名的重定向，不代理控制台。
- [HTTPS 与 WebSocket 模板](../../deploy/koishi/console-domain-tls.conf.example)：包含 `map`，必须位于 Nginx `http {}` 内，不能放进另一个 `server {}`。替换所有示例域名，证书路径同步替换。
- `map_hash_bucket_size` 在同一 `http {}` 中只能定义一次；若已有该指令，合并为足够的值并从模板移除重复定义。模板按 128 设置，实际长域名仍以目标机 `nginx -t` 为准。
- 代理与网关必须在同一服务器。网关继续只监听 `127.0.0.1:5140`；不开放 5140、8765、8766，也不改业务环境、群策略或更新器。
- 当前网关只接受本机 Host/Origin。代理先严格校验真实外部 Host 和 Origin，再将合格请求转换为本机地址。禁止直接无条件改写 Origin、通配放行子域名，或信任客户端传来的 `X-Forwarded-*`。
- `/status` 必须有匹配 HTTPS Origin 和 WebSocket Upgrade；缺失／其他来源被拒绝。页面导航可无 Origin。代理不会替代控制台鉴权：未登录 RPC 仍拒绝，登录密码不进入配置、URL或访问日志。
- 当前应用仍是单个管理员密码，30 分钟会话绑定 WebSocket。不要把借用域名当作多管理员／多租户授权机制。第二个定制实例要独立网关、端口、策略、数据和密码，并给代理变量与限流区另取名。
- 模板每个客户端地址最多四条并发 WebSocket，应用全局仍最多十六个。共用 NAT 的管理员可能共享额度；现有登录频率限制仍生效。正式公网启用前需要评估预期管理员数量与外部连接占用。

## 域名确认后的启用顺序

以下是后续上线清单，不是已经执行的操作。生产入口安装／开放单独确认。

1. 核对实际机器人版本、5140 回环监听、自动更新仍暂停、80/443 占用和云厂商接入条件；备份已有 Nginx／防火墙配置。现有 SSH 入口保持可用。
2. 对方添加确认过的 A 记录，核对公共 DNS、AAAA、CAA。不要获取对方主域密钥。若 HTTP-01 不能使用，另协商仅限该子域名的 DNS 验证委派。
3. 在目标机安装受维护的 Nginx 和 ACME 客户端。仅先安装替换好域名的 HTTP 模板，创建 `/var/lib/taki-console-acme/.well-known/acme-challenge/`；Nginx 用户只需读取。不得覆盖全局 `nginx.conf`，先 `nginx -t` 再启动／reload。
4. 使用 HTTP-01 webroot 签发该完整域名的证书；Certbot 对应 `certonly --webroot -w /var/lib/taki-console-acme -d <完整域名>`。邮箱由管理员提供，使用正式 CA 前先验证挑战路径与客户端配置。证书、私钥不入仓库。
5. 签发成功后安装已替换域名的 TLS 模板；检查证书路径／权限，`nginx -t` 后仅 reload 入口服务。不要安装仍有 `.invalid` 或缺少证书的 TLS 模板。无须为这套代理方案改网关环境或重启机器人，但必须用实际部署验收确认。
6. 配置 ACME 自动续期及“配置检查成功后 reload Nginx”的部署钩子，执行续期演练。确认续期定时器只管证书，不启用 `taki-updater.timer`。
7. 在 Edge 和手机完成下列验收，核对原机器人 PID／版本和更新器暂停状态不变，记录实际证书到期时间、续期任务与回退命令。

## 验收与回退

| 验收 | 通过标准 |
|---|---|
| DNS、证书与页面 | 域名解析到目标入口，正常证书链／主机名，HTTP 跳转 HTTPS，`/taki` 与实际模块无 404 |
| 身份与会话 | 未登录读写 RPC 拒绝；错误密码拒绝；登录可只读总览；退出／断线后不能复用旧会话 |
| 请求来源 | 正确 Origin 可握手；无 Origin、其他域名、HTTP Origin、`null`、后缀伪装域名拒绝；错误 Host 拒绝 |
| WebSocket | HTTPS 页面通过 WSS 读实时状态；等待超过代理空闲时间验证心跳与重连；长连接不退化为一次性页面可用 |
| 生产边界 | 未开放网关／后端直连端口；不写管理设置、不主动发 QQ 消息；自动更新仍暂停，机器人 PID 不变 |
| 浏览器 | Edge 桌面和手机登录／总览／查询诊断；不要求 Haneoka 主站登录或 iframe 嵌入 |
| 续期 | ACME 续期演练与部署钩子通过；保留 HTTP 验证入口；到期监测方式明确 |

回退仅撤下本次新增站点配置，`nginx -t` 后 reload；若是本次独立新建的入口服务，可停止该入口。保留其他站点、机器人、数据、证书和日志；关闭仅为本次新增且未共享的安全组规则，通知对方撤销／修改该 DNS。恢复使用 SSH 隧道。借域名结束时同时撤销不再需要的证书续期任务及 DNS 验证委派。
