# L2-2 Deterministic Query

`song_metrics.py` 本地解析 jp/intl 歌曲指标，按 `domain/meta_query.py` 白名单筛选与稳定排序；每个新查询经注入仓库检查当前 release，同一 `execute_many` 的各组按资源服共用一次快照。Meta 续查使用已捕获行值，不转入旧 JP 详情入口。合同和入口见 [包 2A](../../../docs/QUERY_CHAT_PACKAGE2A.md)。

## Purpose

把明确条件转换为可复现的资料选择与文本。实体、分页和专项结果对直接命令与自然语言路径共用，是稳定能力边界；不按歌曲/卡牌各建一个 L2。

## Position inside parent L2

属于 [Query](../../L2-Query.md) 的可信执行面；它拥有跨域消费的查询契约。Natural 解释问题，但实际选择必须回到本子域。

## Inputs

命令文本、`QuerySpec` 或专项请求、`SongRepository`、已核实别名。Data 的详情/效率入口可能惰性获取资料。

## Outputs

`CommandResult/QueryResult`、`SongFilter/SongAnswer`、`CardRequest/CardAnswer` 与确定性文字；结果承载同次请求选择、页脚或表格，供 QQ 交付与 Rendering 消费。

## Core Flow


`continuation.py` 接收已捕获结果，复制实际可见的页内 ID／难度顺序和规范条件；版本变化要求重新查询。`ContextStore` 按普通平台／会话／用户键保存至多 1024 个上下文，创建后绝对 600 秒过期，读取／提交不延期。代次阻止迟到结果覆盖，提交必须由调用方明确确认成功；QQ 负责回执验证及同用户串行。独立翻页、选择和难度指令已移除；按 ID 查询详情，QQ 待发结果使用 `/继续`。`/问` 的有限自然续查词法在本地处理，无上下文不会进入模型。测试见 `test_continuation.py`。

榜线专项 [event_cutoff_query.py](event_cutoff_query.py) 的正式入口是 `/查榜线`，旧 `/榜线` 保留兼容；按独立槽位识别服务器／活动ID简写（id1、id 1、id=1、id:1，兼容活动ID=1）或名称／歌曲编号或名称／排名／输出修饰，允许参数组任意顺序；捕获选定服同一活动后保护完整名称及别名、解析稳定序号，保留趋势／附近／区间／离散模式和目标行。含参数词的名称有显式消歧入口，重复歌曲须按实际身份核对；序号选定具体挑战条目，同曲多挑战榜须用序号消歧。`CutoffAnswer` 与排名页投影共用同份榜单和单曲时间；默认查询沿用当前来源；指定活动时只读本地历史身份和最近一次有效观测及对应时间，趋势再读历史序列，不请求当前榜单；`entity_lexicon.scoped_song_matches` 对本期歌曲目录消歧，同服完整目录仅用于核对非本期歌曲。公共结果对象增加可选 `cutoff`，不改变原资料选择。测试见 [test_event_cutoffs.py](../../../tests/test_event_cutoffs.py)。

直接入口 `resolve_command` 识别并调用对应执行器，`handle_command(resolved=...)` 复用结果生成文字；结构化入口 `resolve_query` 按字段分流。Natural 能力注册表的 `_chart` 直接调用 `chart_for` 并包装 QueryResult，不强制所有能力都经 resolve_query。

榜线用户服名为日服（jp）、国服（hk）、韩服（kr）、英服（en）；查询入口将国服映射到上游 `tw`，保留 API／素材／缓存身份，`QuerySpec.command_label` 转回 `hk`。旧服名仅作输入兼容，显示使用统一名称。
实体身份/别名验证、条件解析 → 选择与完整度检查 → 分页/结果包装。空集合与未知条件均为终态，不拓宽查询。
卡牌完整度按每张卡全部条件判断：有确定不匹配条件的卡不累积缺失提示；仍可能匹配的未知卡继续阻止冒充完整结果，参数顺序不改变结论。
`song_identity.py` 先按完整名称、ID 和已核实别名确认歌曲；唯一对象操作保留全部候选，重名不默认选第一项，返回可复制的 ID 指令。专项结果显式携带 `status`；部分资料缺失的覆盖说明独立于成功／空集合状态。

## Dependencies

榜线 `CutoffAnswer` 共用捕获榜单的分数、数字ID和用户名；趋势当前节点逐条注明，显式排名文字按排名行与歌曲列显示“分数/数字ID/用户名”，页投影保留对应关系，名字含分隔符时引用；失效分数不显示身份；往期读取同次有效观测保存的身份，旧记录缺失不跨时间补人。回归见 [test_cutoff_player_ids.py](../../../tests/test_cutoff_player_ids.py)。

`field_query.py` 在本地识别并回答字段投影及完整集合计数；`QuerySpec.field` 与 `QueryResult.short_text` 贯通 Natural、文字和 QQ 绘图跳过。技能短答要求明确卡牌类型和 ID，只获取相关详情。测试见 `test_field_queries.py`。

Data 记录/仓库和效率/traits 契约，Application 文案叶子。不调用 AIClient、Pillow 或 QQ。
`commands` 诊断命令读 Natural 的 `query_debug`；这是当前跨兄弟子域依赖，不是直接查询运行模型。

## Boundary with sibling L2-2 modules

[Natural](../natural_query/L2-2.md) 管问题解释、模型信任、预算与状态机；共享实体和歌曲条件归此处。Natural 的专用技能占位词 `query_terms` 留在 Natural。
介绍/帮助/状态是直接入口的命令内容；不为这些少量内容另造 Application 子域。

## Files belonging to this subdomain

上述链接直接进入对应源码文件头 L3；词表数据本体为 [query_aliases.json](../../../query_aliases.json)。

- [song_metrics.py](song_metrics.py)：jp/intl 的谱面时长、等级、Note、NPS 和 BPM 筛选与稳定排序；不提供参考得分或激奏效率。
- [activity_query.py](activity_query.py)：四服当前／最近活动与日服静态列表／历史详情，不读玩家排行；静态资料仅在活动身份和时间匹配后补充当前详情。
- [character_query.py](character_query.py)、[gacha_query.py](gacha_query.py)：人物档案、乐队目录及日服卡池资料；[info_query.py](info_query.py) 共享时间、来源与卡牌关联投影。
- [contracts/info.py](contracts/info.py)：三个资料入口的纯展示结果，图文共用；QQ 承接发送和 `/继续`，查询不依赖绘图或平台。
  `InfoRow` 捕获乐队组、事实／简介／卡牌入口类别、图像比例与原生属性图标；活动卡按资源类型和 ID 合并标签。关系不完整时仍投影已确认的奖励／UP 子集，并明确标注缺失，不把部分已知当作完整或空集合。
  活动／卡池另外捕获 `InfoSchedule` 的身份、时间状态、起止时间与时区，供主视觉总览及纵向列表直接消费。列表条目通过 `InfoRow.children` 携带同份快照的卡牌预览及关联不完整提示；成员为3:4竖图，留影为16:9横图，`tags` 保存简短角色标签，完整文字仍保留原名与关系。静态歌曲只标关联，不产生挑战榜查询。活动大图与标志来自同 release 的明确路径；完整诊断页脚和图片中的必要来源提示分别保存，人物档案的展示契约保持兼容。

## 当前实现与边界

专项叶子位于 query/；commands、structured_query 和 bot_info 保留包根。QuerySpec/QueryResult/CommandResult 不复制、不替换。详情、效率及活动榜读取可惰性 I/O，专项结果方法仍可函数内引用根入口。entity_lexicon 查找同一源码或安装别名文件，并保留 OURNOTES_ALIAS_FILE 覆盖。

向上阅读：[仓库 L1](../../../L1.md)。源码文件头提供唯一 L3，具体行为与字段以实现为准。

直接查询入口 `commands.py`，结构化契约 `structured_query.py`；歌曲 `song_query.py`、卡牌 `card_catalog.py`、活动 `activity_query.py`、榜线 `event_cutoff_query.py`，续查 `continuation.py`。歌曲属性回归见 `test_song_traits.py`。分数表专项已移除。

`entity_lexicon.py` 按文件路径保存最后有效人工词库，结构校验失败保留旧快照并报告状态；内容摘要驱动查询缓存与续查失效。SNAP 别名参与枚举和缩写查询，目标身份仍按当前实体集合核实。

后端 2.0 按独立话题隔离并用确认消息锚点定位，原 ContextKey 用户字段承载后端内部话题 ID；QQ 身份仍保存在请求中。全局序号只允许选择已确认展示的行，固定页面由 application/conversation_state.py 提供，参见 [包 1](../../../docs/QUERY_CHAT_PACKAGE1.md)。
## 知识检索入口

[knowledge_retrieval.py](knowledge_retrieval.py) 负责带标题的章节切分、表格列名展开、关键词／语义排序融合、相邻片段补齐与证据预算；编码器、已批准文档及向量缓存由 Application 注入。返回带内容哈希和批准版本的证据，不生成回答或决定批准状态。见 [包 2B](../../../docs/QUERY_CHAT_PACKAGE2B.md)。

`activity_query.py` 的日程分支只使用同次捕获的 jp／intl 活动记录，按活动 end_at 判定进行中、最近结束和下一期；不使用展示截止时间。缺少下一期记录时通过注入的公告来源补充明确预告，输出完整文字与证据到期时间。普通四区当前活动及榜线查询保持原入口。
