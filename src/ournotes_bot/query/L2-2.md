# L2-2 Deterministic Query

## Purpose

把明确条件转换为可复现的资料选择与文本。实体、分页和专项结果对直接命令与自然语言路径共用，是稳定能力边界；不按歌曲/卡牌各建一个 L2。

## Position inside parent L2

属于 [Query](../../L2-Query.md) 的可信执行面；它拥有跨域消费的查询契约。Natural 解释问题，但实际选择必须回到本子域。

## Inputs

命令文本、`QuerySpec` 或专项请求、`SongRepository`、已核实别名。Data 的详情/效率入口可能惰性获取资料。

## Outputs

`CommandResult/QueryResult`、`SongFilter/SongAnswer`、`CardRequest/CardAnswer`、`MetaAnswer` 与确定性文字；结果承载同次请求选择、页脚或表格，供 QQ 交付与 Rendering 消费。

## Core Flow

`continuation.py` 接收已捕获结果，复制实际可见的页内 ID／难度顺序和规范条件；版本变化要求重新查询。`ContextStore` 按普通平台／会话／用户键保存至多 1024 个上下文，成功提交后 600 秒过期。代次阻止迟到结果覆盖，提交必须由调用方明确确认成功；QQ 负责回执验证及同用户串行。有限续查词法在本地处理，无上下文不会进入模型。测试见 `test_continuation.py`。

榜线专项 [event_cutoff_query.py](event_cutoff_query.py) 的正式入口是 `/查榜线`，旧 `/榜线` 保留兼容；将服务器／原名称／可选名次转换为 `CutoffRequest`，先完整名称再拆名次或判定两字母服务器，捕获 `CutoffAnswer` 与单曲有效时间文案供图文共用；`entity_lexicon.scoped_song_matches` 对本期歌曲目录消歧，同服完整目录仅用于核对非本期歌曲。公共结果对象增加可选 `cutoff`，不改变原资料选择。测试见 [test_event_cutoffs.py](../../../tests/test_event_cutoffs.py)。

直接入口 `resolve_command` 识别并调用对应执行器，`handle_command(resolved=...)` 复用结果生成文字；结构化入口 `resolve_query` 按字段分流。Natural 能力注册表的 `_chart` 直接调用 `chart_for` 并包装 QueryResult，不强制所有能力都经 resolve_query。

榜线用户服名为日服（jp）、国服（hk）、韩服（kr）、英服（en）；查询入口将国服映射到上游 `tw`，保留 API／素材／缓存身份，`QuerySpec.command_label` 转回 `hk`。旧服名仅作输入兼容，显示使用统一名称。
实体身份/别名验证、条件解析 → 选择与完整度检查 → 分页/结果包装。空集合与未知条件均为终态，不拓宽查询。
`song_identity.py` 先按完整名称、ID 和已核实别名确认歌曲；唯一对象操作保留全部候选，重名不默认选第一项，返回可复制的 ID 指令。专项结果显式携带 `status`；部分资料缺失的覆盖说明独立于成功／空集合状态。
`song_query.parse_filter/traits_match/serialize_filter` 定义歌曲和分数表共用的歌曲条件。`QuerySpec.song_filter` 保存规范条件；效率执行先检查映射与参考条件，再筛歌曲和每条谱面、排序、分页，捕获来源版本、可见记录与覆盖数。单曲同样筛选；生成的下一页指令从规范状态序列化。测试见 `test_meta_filters.py`。

## Dependencies

`field_query.py` 在本地识别并回答字段投影及完整集合计数；`QuerySpec.field` 与 `QueryResult.short_text` 贯通 Natural、文字和 QQ 绘图跳过。技能短答要求明确卡牌类型和 ID，只获取相关详情。测试见 `test_field_queries.py`。

Data 记录/仓库和效率/traits 契约，Application 文案叶子。不调用 AIClient、Pillow 或 QQ。
`commands` 诊断命令读 Natural 的 `query_debug`；这是当前跨兄弟子域依赖，不是直接查询运行模型。

## Boundary with sibling L2-2 modules

[Natural](../natural_query/L2-2.md) 管问题解释、模型信任、预算与状态机；共享实体和歌曲条件归此处。Natural 的专用技能占位词 `query_terms` 留在 Natural。
介绍/帮助/状态是直接入口的命令内容；不为这些少量内容另造 Application 子域。

## 当前实现与边界

专项叶子位于 query/；commands、structured_query 和 bot_info 保留包根。QuerySpec/QueryResult/CommandResult 不复制、不替换。详情、效率及活动榜读取可惰性 I/O，专项结果方法仍可函数内引用根入口。entity_lexicon 查找同一源码或安装别名文件，并保留 OURNOTES_ALIAS_FILE 覆盖。
