# L2-2 Sources

[model_provider.py](model_provider.py) 提供可取消的原生模型 HTTP 和 OpenRouter 登记取价适配，只访问固定官方 HTTPS 端点；先提取 usage，再验证工具／文本，不重试或跟随重定向。策略和账务在 Application。Catalog 的 `current_with_info` 为新版自然查询核实当前 release，失败不沿用旧缓存回答；传统刷新合同保留。见 [包 3](../../../docs/QUERY_CHAT_PACKAGE3.md)。

独立的 `haneoka/song_metrics.py` 为新 Meta 查询校验当前 identity 和固定 release 的资源；每服一份有界内存缓存，身份失败不回退旧数据，不更改传统查询的缓存策略。见 [包 2A](../../../docs/QUERY_CHAT_PACKAGE2A.md)。

`haneoka/notices.py` 为 U3 提供固定匿名公告列表／详情和有截止时间的主资料 release 核对。公告校验采集时间、区服、语言、ID及响应头，只抽取 HTML 文本，不执行脚本、不下载图片、不写缓存；应用层负责同快照关联与三步预算。MoeNotes 没有新增直接抓取或失败换源通道。

Catalog 的显式版本检查与同步使用原刷新互斥及整体发布；素材校验/原子写入提供公开核心函数供受限运维任务复用。操作契约见 [运维控制台](../../../docs/koishi/OPERATIONS.md)。

## Purpose

将不同外部来源转换为经校验的记录或专项快照，并各自控制可用性和陈旧回退。这是稳定的外部信任边界，不是按文件后缀收集下载器。

[cutoff_history.py](cutoff_history.py) 保存独立 SQLite 挑战榜历史及可选活动元数据，提供只读活动身份索引和最近一次有效观测，跳过异常时间点并保留原因；旧库按已存身份查询，故障不阻断当前值；[cutoff_sampler.py](cutoff_sampler.py) 仅由机器人入口按配置启动一个任务，复用现有来源限流与退避。公开玩家ID／用户名按观测关联保存，不存队伍或完整profile；长期保留，低空间暂停。历史观测和当前值使用各自时间与质量状态；迟到数据不替换较新的当前缓存。运维见 [历史说明](../../../docs/CUTOFF_HISTORY.md)，测试见 `test_cutoff_history.py`。

## Position inside parent L2

属于 [Data](../../L2-Data.md) 的外部资料接入面。Catalog、活动/榜线查询及回复/绘图准备各有直接消费者，不能画成所有来源都只由 Catalog 访问。

## Inputs

允许的资源路径、响应 JSON、旧缓存、时间/刷新请求及本地实体身份。来源证据和素材使用边界以 [THIRD_PARTY](../../../THIRD_PARTY.md) 为准。

## Outputs

Project Yume 领域记录/详情结构；Moenotes 的 `EventSnapshot/BoardSnapshot` 和校验谱面；Haneoka 主资料、关联用 `SongTraits`、成员 `Snapshot` 及活动观测状态。没有统一全来源 snapshot 或共享刷新事务。

## Core Flow

每个适配器限制资源与结构、验证标识，再产出允许消费的数据；有独立缓存者在校验完成后保存。
Haneoka 静态资源各自先取 release identity，再固定该 release 获取关联资源；各适配器的 release、时效与失败状态互不锁定。Game Records 实时榜单独立校验区域／活动／挑战，不将静态 release 套入实时请求。


| 实现簇 | 消费和可信边界 |
|---|---|
| Project Yume | Catalog 调用基础表/详情解析；并发详情与主缓存由 Catalog 管理 |
| Haneoka 主资料 | `OURNOTES_DATA_SOURCE=haneoka` 默认选择；固定 JP 必要资源与独立 intl 文本候选，整体校验发布；独立缓存回退，不跨源补全。属性与成员摘要随主快照捕获；支持时同版捕获 JP song-meta 理论参考指标及来源警告，旧缓存无指标时保持未知 |
| MoeNotes | QQ 的谱面准备按 Song/Chart 映射调用；旧有效谱面可回退，不支持的映射报错 |
| Haneoka 完整谱面 | `OURNOTES_CHART_SOURCE=haneoka` 默认选择；按真实 musicId／难度读取 JP 歌曲实体返回的文件路径，歌曲及素材固定同一 release，核对响应 release/source 身份；失败只使用本来源已验证缓存 |
| Moenotes 开放平台 | `OpenEventCutoffRepository` 仅认证 challenge-ranking；公开活动发现／元数据与素材是明确例外，时间为原成功上游获取，非 tracker 观测 |
| Haneoka traits | Catalog 显式刷新/关联；ID、名称和封面身份一致才附加颜色/序列 |
| Haneoka 成员摘要 | 默认随主资料启动／刷新重建；旧源列表调用 `get_snapshot` 核对卡/角色/技能。同版目标与完整描述匹配时支持已知队长机制的参数化摘要，未知机制拒绝 |

## Dependencies

标准库网络/缓存/并发、Application 路径工具、Catalog 的类型/名称规则。
Haneoka 主资料、活动、谱面和素材共用 `haneoka/transport.py` 的有界 HTTPS 与 `identity.py` 的版本/响应头校验，严格 JSON 来自 `json_validation.py`；公共模块不依赖具体适配器。静态服务器为 JP/intl，实时 DTO 为 jp/tw/kr/en，用户 hk 别名在查询入口转换。旧 traits/members 的独立 urllib 资源合同继续保留，不因公共化修改重定向、超时或 MIME 语义。

## Boundary with sibling L2-2 modules

不拥有主资料聚合状态和全局缓存 schema；这些归 [Catalog](../L2-2-Catalog.md)。
不做用户实体消歧、业务排行或画图。成员摘要是来源投影，`support_summary.py` 则是渲染对已有文本的投影，不能因为都叫 summary 就合并。

## 当前实现与边界

原六个文件位于 sources/，其中 Haneoka 四文件位于 sources/haneoka/。各来源继续使用既有领域类型、名称规则、独立缓存与失败策略，不引入公共 provider 或缓存框架。成员摘要在绘图时读取仍是现有跨域例外。

新增 `moenotes_events.py` 独立提供 `EventSnapshot/EventSong/BoardSnapshot`，不依赖 QQ 或主资料 schema，初始化不联网。[test_event_cutoffs.py](../../../tests/test_event_cutoffs.py) 验证跨服隔离、同 key 合并、限时、退避、时间冲突、原始位置与旧缓存边界。

向上阅读：[仓库 L1](../../../L1.md)。源码文件头提供唯一 L3，具体行为与字段以实现为准。

Haneoka成员摘要支持已核验的新队长目标组合和生日卡双效果；get_snapshot(required_cards) 在缺同版乐队引用或所需卡身份未匹配时提前刷新，保留300秒退避与严格身份核对，不等待24小时TTL才补新卡。

`json_validation.py` 提供成员资料、歌曲属性与 open 榜线共用的重复键／非有限 JSON 校验；不提供业务数据源。

Haneoka 歌曲属性 `haneoka/song_traits.py`、成员资料 `haneoka/haneoka_members.py` 与 `haneoka_member_contracts.py` 保留。主资料／谱面／榜线与素材出口用 `test_source_egress.py` 验证；旧来源只在显式选择时使用。

美工资料由 `haneoka/catalog_records.py` 捕获；`ranking_art.py` 按服务器投影成长和角标资料，`game_assets.py/json` 限定原游戏素材来源／哈希与运行时缓存，并提供固定谱面素材的提前下载／离线校验导入；`visual_skill_contracts.py/json` 优先以机制指纹匹配精修摘要，未匹配时从同版本已解析完整说明自动生成保留全部条件的简写。
Catalog 歌曲同时捕获谱面身份与最小歌曲行，`haneoka/chart_data.py` 直接获取该固定版本的谱面，继续校验响应版本和缓存身份；旧歌曲对象保留 release／歌曲发现流程。游戏 UI 素材按名称合并下载，下载期间不持有全局锁；普通原生素材按 URL 合并加载，失败后短暂退避，已缓存的尺寸仍可立即读取。
`OURNOTES_PUBLIC_HTTP_PROXY` 可显式指定不含凭据的 HTTP(S) 代理，供公开资料和固定游戏素材使用；默认直连，不读取系统／通用代理环境。域名、禁止重定向、TLS、大小、版本头与摘要校验继续生效。
Haneoka 公共资料传输显式接受 gzip，大小预算按解压后的正文累计；保留原总超时和完整资料校验，损坏压缩流视为来源失败。
公共 GET 首次连接及响应头等待最多使用调用方总预算的一半；响应头前超时或连接中断可重试一次，两次尝试与正文读取共用原总预算。证书/TLS 校验失败、HTTP 错误状态以及收到响应头后的正文失败不重试。
`public_http_scope` 在一次同步读取内复用本线程的连接，嵌套作用域共享，退出时关闭会话及事件循环；无 Cookie、无进程常驻连接池。Meta 和主目录读取显式使用作用域，主目录并发资源各自隔离；每次 GET 仍使用调用方本次剩余预算。
`haneoka/song_metrics.py` 在独立检查当前 release 后，经主目录的 `metrics_documents` 捕获同版已发布原始资料，重新校验 Meta 数量、ID、字段和大小。主目录缺少的资源继续固定版本下载，复用资料错误则拒绝；不等待后台刷新、不修改主目录快照或缓存格式。来源合同见 [包 2A](../../../docs/QUERY_CHAT_PACKAGE2A.md)。
Catalog 累计下载预算为 32 MB，包含发现索引与批次封装；单响应仍限 8 MB，持久快照仍限 24 MB，缓存格式及旧版读取边界不变。
榜线的 `read_event_observed/read_board_observed` 以线程局部旁路返回获取路径和实际历史写入结果，不扩展持久 DTO 或缓存格式。手动采样与周期采样共用锁、退避、前台让位和时钟隔离。

[haneoka/prepare_catalog_assets.py](haneoka/prepare_catalog_assets.py) 将已校验 Catalog 中的允许图片 URL 转为完整、带摘要的持久图片缓存。只在显式准备入口调用；同版哈希和完整解码验证通过才复用，所有图片准备成功后原子发布清单。查询沿既有缓存格式读取。
## 本地知识来源

[knowledge_files.py](knowledge_files.py) 校验 JSON frontmatter、批准清单、交付清单和目录路径；[knowledge_embeddings.py](knowledge_embeddings.py) 惰性加载固定哈希的本地 BGE ONNX 模型，仅 CPU 编码，不下载或调用外部 embedding。上层持有批准集合与索引生命周期，见 [包 2B](../../../docs/QUERY_CHAT_PACKAGE2B.md)。

[activity_announcements.py](haneoka/activity_announcements.py) 从同次已校验公告索引与正文提取下一期活动时间：共用八秒预算、最多三篇正文，不执行 HTML、不调用模型、不把发布时间或结算期当活动时间。缺正文、截断、时间／时区不明确、版本变化或改期冲突保留未确认状态与来源入口；已采用预告的 24 小时采集时效传到发送门禁。
