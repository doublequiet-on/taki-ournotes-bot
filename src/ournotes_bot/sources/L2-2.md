# L2-2 Sources

## Purpose

将不同外部来源转换为经校验的记录或专项快照，并各自控制可用性和陈旧回退。这是稳定的外部信任边界，不是按文件后缀收集下载器。

## Position inside parent L2

属于 [Data](../../L2-Data.md) 的外部资料接入面。Catalog、效率执行及回复/绘图准备各有直接消费者，不能画成所有来源都只由 Catalog 访问。

## Inputs

允许的资源路径、响应 JSON、旧缓存、时间/刷新请求及本地实体身份。来源证据和素材使用边界以 [THIRD_PARTY](../../../THIRD_PARTY.md) 为准。

## Outputs

Project Yume 领域记录/详情结构；MoeNotes 校验后的 score 字典；Haneoka 的 `MetaSnapshot`、关联用 `SongTraits`、成员 `Snapshot` 及相应状态。没有统一全来源 snapshot 或共享刷新事务。

## Core Flow

每个适配器限制资源与结构、验证标识，再产出允许消费的数据；有独立缓存者在校验完成后保存。
Haneoka 各自先取 release identity，再固定该 release 获取关联资源，但三个适配器的 release、时效与失败状态互不锁定。

| 实现簇 | 消费和可信边界 |
|---|---|
| Project Yume | Catalog 调用基础表/详情解析；并发详情与主缓存由 Catalog 管理 |
| MoeNotes | QQ 的谱面准备按 Song/Chart 映射调用；旧有效谱面可回退，不支持的映射报错 |
| Haneoka 效率 | Query 经 `repository.song_meta.get` 读取；校验来源/服务区/数值，执行侧再校验本地歌曲对应 |
| Haneoka traits | Catalog 显式刷新/关联；ID、名称和封面身份一致才附加颜色/序列 |
| Haneoka 成员摘要 | 成员列表绘图调用 `get_snapshot`；`for_card` 核对卡/角色/技能证据，机制指纹未知时拒绝猜摘要 |

## Dependencies

标准库网络/缓存/并发、Application 路径工具、Catalog 的类型/名称规则。
Haneoka traits 复用 song_meta 的基址与 JSON 去重工具，members 复用去重工具；这不足以证明已经存在一个公共 Haneoka 服务或统一 repository。

## Boundary with sibling L2-2 modules

不拥有主资料聚合状态和全局缓存 schema；这些归 [Catalog](../L2-2-Catalog.md)。
不做用户实体消歧、业务排行或画图。成员摘要是来源投影，`support_summary.py` 则是渲染对已有文本的投影，不能因为都叫 summary 就合并。

## 当前实现与边界

六个文件位于 sources/，Haneoka 四文件位于 sources/haneoka/。各来源继续使用既有领域类型、名称规则、独立缓存与失败策略，不引入公共 provider 或缓存框架。成员摘要在绘图时读取仍是现有跨域例外。
