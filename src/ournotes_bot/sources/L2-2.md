# L2-2 Sources

## Purpose

将不同外部来源转换为经校验的记录或专项快照，并各自控制可用性和陈旧回退。这是稳定的外部信任边界，不是按文件后缀收集下载器。

[cutoff_history.py](cutoff_history.py) 保存独立 SQLite 挑战榜历史，故障不阻断当前值；[cutoff_sampler.py](cutoff_sampler.py) 仅由机器人入口按配置启动一个任务，复用现有来源限流与退避。无玩家数据，长期保留，低空间暂停。历史观测和当前值使用各自时间与质量状态；迟到数据不替换较新的当前缓存。运维见 [历史说明](../../../docs/CUTOFF_HISTORY.md)，测试见 `test_cutoff_history.py`。

## Position inside parent L2

属于 [Data](../../L2-Data.md) 的外部资料接入面。Catalog、效率执行及回复/绘图准备各有直接消费者，不能画成所有来源都只由 Catalog 访问。

## Inputs

允许的资源路径、响应 JSON、旧缓存、时间/刷新请求及本地实体身份。来源证据和素材使用边界以 [THIRD_PARTY](../../../THIRD_PARTY.md) 为准。

## Outputs

Project Yume 领域记录/详情结构；Moenotes 的 `MusicSnapshot`、`EventSnapshot/BoardSnapshot` 和校验谱面；Haneoka 的 `MetaSnapshot`、关联用 `SongTraits`、成员 `Snapshot` 及相应状态。没有统一全来源 snapshot 或共享刷新事务。

## Core Flow

每个适配器限制资源与结构、验证标识，再产出允许消费的数据；有独立缓存者在校验完成后保存。
Haneoka 静态资源各自先取 release identity，再固定该 release 获取关联资源；各适配器的 release、时效与失败状态互不锁定。Game Records 实时榜单独立校验区域／活动／挑战，不将静态 release 套入实时请求。

[haneoka/event_cutoffs.py](haneoka/event_cutoffs.py) 提供显式 `haneoka` 榜线预览，独立缓存和 schema 3 历史；三来源组合读取、切换断线，旧库不迁移。完整序号与静态关联未核实前不猜测歌名／素材，生产切换门槛见 [榜线说明](../../../docs/HANEOKA_CUTOFFS.md)。

| 实现簇 | 消费和可信边界 |
|---|---|
| Project Yume | Catalog 调用基础表/详情解析；并发详情与主缓存由 Catalog 管理 |
| Haneoka 主资料 | `OURNOTES_DATA_SOURCE=haneoka` 显式选择；固定 JP 必要资源与独立 intl 文本候选，整体校验发布；独立缓存回退，不跨源补全。属性与成员摘要随主快照捕获 |
| MoeNotes | QQ 的谱面准备按 Song/Chart 映射调用；旧有效谱面可回退，不支持的映射报错 |
| Haneoka 完整谱面 | `OURNOTES_CHART_SOURCE=haneoka` 显式选择；按真实 musicId／难度读取 JP 歌曲实体返回的文件路径，歌曲及素材固定同一 release，核对响应 release/source 身份；失败只使用本来源已验证缓存 |
| Moenotes 公开计算快照 | `music_data` 验证 TW 身份、歌曲／scoreId 与有限统计后原子发布；不依赖旧主目录存在性，不拼旧属性或统计；解压和传输分别限额 |
| Moenotes 开放平台 | `OpenEventCutoffRepository` 仅认证 challenge-ranking；公开活动发现／元数据与素材是明确例外，时间为原成功上游获取，非 tracker 观测 |
| Haneoka 效率 | 显式旧源开关时经 `repository.song_meta.get` 读取；校验来源/服务区/数值，执行侧再校验本地歌曲对应 |
| Haneoka traits | Catalog 显式刷新/关联；ID、名称和封面身份一致才附加颜色/序列 |
| Haneoka 成员摘要 | 成员列表绘图调用 `get_snapshot`；`for_card` 核对卡/角色/技能证据，机制指纹未知时拒绝猜摘要 |

## Dependencies

标准库网络/缓存/并发、Application 路径工具、Catalog 的类型/名称规则。
Haneoka traits 复用 song_meta 的基址与 JSON 去重工具，members 复用去重工具；这不足以证明已经存在一个公共 Haneoka 服务或统一 repository。

## Boundary with sibling L2-2 modules

不拥有主资料聚合状态和全局缓存 schema；这些归 [Catalog](../L2-2-Catalog.md)。
不做用户实体消歧、业务排行或画图。成员摘要是来源投影，`support_summary.py` 则是渲染对已有文本的投影，不能因为都叫 summary 就合并。

## Files belonging to this subdomain

- [yatta.py](yatta.py)
- Project Yume JSON 有界重试耗尽后，将明确的 HTTP 传输异常转为 OSError，供主目录和两类详情使用原有缓存回退；结构与身份错误不补造事实。
- [chart_data.py](chart_data.py)
- [haneoka/chart_data.py](haneoka/chart_data.py)：独立 `haneoka-chart-jp-v1/` 缓存，原始谱面、校验和与实体／版本身份一起原子保存；6 小时有效期，刷新失败标记旧缓存，12 秒请求总预算、2 MB 谱面上限、拒绝重定向。复用现有解析器，不截短长条／连接节点。
- [moenotes_music_data.py](moenotes_music_data.py)：分数表事实、统计投影、已验证计算源码指纹及条件重验证缓存；运行时显式启动一个300秒刷新任务，未知模型保留当前事实及独立完整兼容快照。合同见 [分数表与开放平台](../../../docs/META_OPEN.md)。
- [moenotes_open.py](moenotes_open.py)：四服正式挑战榜、最低 rankings 权限、固定认证目标、分钟并发和有限错误恢复；无日总量拒绝，启用仍需真实认证验收。
- [cutoff_history.py](cutoff_history.py)：旧 v1 与正式来源独立 v2 库、来源段断线及组合；旧文件不原位迁移，历史不存玩家身份。
- [moenotes_events.py](moenotes_events.py)：四服当前活动、挑战歌曲与响应位置榜单，先校验活动身份再发布独立当前分数／数字ID／用户名缓存；来自同一条记录，兼容旧分数及数字ID缓存，历史仍无玩家数据。保留单曲有效区间及按服元数据；源时间、来源时钟与本机获取时间分离。策略和取样限制见 [活动歌曲榜线](../../../docs/EVENT_CUTOFFS.md)。
- Haneoka 簇：[song_meta.py](haneoka/song_meta.py)、[song_traits.py](haneoka/song_traits.py)、[haneoka_members.py](haneoka/haneoka_members.py)、[haneoka_member_contracts.py](haneoka/haneoka_member_contracts.py)。

上述源码链接分别进入对应文件头 L3；Haneoka 不单设 L2-2 或更深地图。

主资料实现：[catalog.py](haneoka/catalog.py) 管固定版本下载／缓存，[catalog_records.py](haneoka/catalog_records.py) 转换既有领域记录，[catalog_text.py](haneoka/catalog_text.py) 校验中文并有限展开 Lv.5，[catalog_assets.py](haneoka/catalog_assets.py) 限制图片路径／版本／预算。剩余映射限制见 [主资料说明](../../../docs/HANEOKA_CATALOG.md)，离线测试见 [test_haneoka_catalog.py](../../../tests/test_haneoka_catalog.py)。

## 当前实现与边界

原六个文件位于 sources/，其中 Haneoka 四文件位于 sources/haneoka/。各来源继续使用既有领域类型、名称规则、独立缓存与失败策略，不引入公共 provider 或缓存框架。成员摘要在绘图时读取仍是现有跨域例外。

新增 `moenotes_events.py` 独立提供 `EventSnapshot/EventSong/BoardSnapshot`，不依赖 QQ 或主资料 schema，初始化不联网。[test_event_cutoffs.py](../../../tests/test_event_cutoffs.py) 验证跨服隔离、同 key 合并、限时、退避、时间冲突、原始位置与旧缓存边界。

向上阅读：[仓库 L1](../../../L1.md)。源码文件头提供唯一 L3，具体行为与字段以实现为准。

Haneoka成员摘要支持已核验的新队长目标组合和生日卡双效果；get_snapshot(required_cards) 在所需卡身份未匹配时提前刷新，保留300秒退避与严格身份核对，不等待24小时TTL才补新卡。
