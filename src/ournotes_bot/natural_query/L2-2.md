# L2-2 Natural Query

后端 v3 使用 [native_tools.py](native_tools.py) 的手动原生工具 schema 与原句校验；执行仍复用确定性 Query／Command。`prepare_native_local` 只做本地解析，剩余请求交给 [应用编排](../application/model_runtime.py)，不调用旧路由／自动修复。活动／卡池的这期、本期、这次时间问法由 `on_query.information_command` 整句解析；原生工具复用相同依据规范当前模式，保留明确区服，不把历史日期、上／下期或其他对象转换成当前。旧 SDK 门面的 `run/resume` 合同继续兼容；见 [包 3](../../../docs/QUERY_CHAT_PACKAGE3.md)。

原生校验以有限原因码区分参数结构错误、知识区服范围和条件不匹配；范围来自当前原句或有效 ACK 主题，当前显式条件优先。两服共通仅允许适用范围交集；应用层映射为固定提示，不返回模型参数或用户原文。来源与事实约束保持不变。

## Purpose

把自然语言限制在可验证的查询能力内，管理从本地解析、有限模型请求到明确终态的全过程。多个文件共同实现同一信任/预算边界，足以独立成子域。

## Position inside parent L2

属于 [Query](../../L2-Query.md) 的问题解释面。返回可信结果的事实来源仍为 Deterministic 和 Data；不建立第二套游戏知识库。

## Inputs

原始问题、仓库/别名、能力目录、可选 requester、额度/指标及时间策略。

Koishi 请求额外由 `domain/query_policy.py` 的不可变 ExecutionPolicy 提供 off/local/model 上限；ContextVar 随工作任务及 to_thread 传播，不修改共享 AI 开关。local 不复用 model/unknown 来源缓存且不进入模型或修复路径；off 返回受控说明。直接指令不调用模型。解析结果及续查携带实际来源，受限模式逐项限制混合续查，保留直接指令顺序；协议与管理规则见 [Console 契约](../../../docs/koishi/CONSOLE_V1.md)。

## Outputs

`AIQueryParser.answer_with_plan` 输出 `(text, QueryResult | CommandResult | None)`；
`answer_with_outcome` 输出 `AgentOutcome`，携带结果与状态/终态。模型响应本身不成为游戏答案。

## Core Flow


检查输入与来源指纹 → 命中计划/终态缓存或本地命令/语法 → 必要时选能力 → 受限模型动作 → schema、实体及原文条件校验 → 确定性执行。
活动歌曲榜线在通用缓存与旧拒绝词判断前由 `parse_natural_cutoff` 识别，本地执行且不访问模型／额度／通用终态缓存；预测、配队、账号操作等仍拒绝。`event.cutoff` 仅为本地执行契约，不暴露给模型路由。相关解析与源状态均由 [Deterministic](../query/L2-2.md) 专项结果提供。
仅在规定的可修复错误下再请求一次修复，且受总时间和调用数限制；空结果不触发放宽条件。缓存计划再执行时读取当前数据，不等于永久缓存事实答案。

## 统计口径与回退

`QueryAgent.run` 在返回 `AgentOutcome` 时一次写入 `outcome_<OutcomeCode>` 与 `route_local/cache/model`；不统计为 QQ 送达。`ask_total` 在请求开始时计数，异常退出没有伪造终态，跨日请求的开始/完成可能分属不同日期。各指标按实际记录时间聚合。

- `local_handled`：本地路径结束（包括输入拒绝、未配置模型）；`local_parsed`：本地已形成有效执行条件，空集或缺资料也可计入；`local_success`：本地最终 `success`。未形成有效条件记 `local_terminal_reject`，具体原因以 `outcome_*` 为准。
- `cache_hit_success/terminal`：命中缓存后**本次**执行/返回的状态。命中不重复计入本地解析；缓存计划不是永久答案。
- `ai_<OutcomeCode>`：进入模型处理路径后的最终结果，包括额度阻止调用；`ai_route/parse/repair_requested` 和 Token 为实际请求过程计数。`ai_provider_error` 只计请求提供方异常，不把业务执行异常混入。修复中间结果不再重复记为最终失败。
- 基础路径 `metrics.json` 派生为 `metrics.v2.json`；无扩展名的 `metrics` 派生为 `metrics.v2`。schema 2 从首次使用起累计，不读取、迁移、清空或双写 schema 1 文件；回退时旧版继续使用旧路径，旧版运行期间的次数不进入 v2。两套计数不得直接合并计算覆盖率。
- 仍只记录有界匿名计数，不存问句或身份；损坏/保存失败仅停用本实例统计。额度文件与主缓存格式不变。

`tests/fixtures/query_metrics_v1.py` 是基线 `8607541` 的原始统计模块，供 `test_query_metrics.py` 做旧写入→新运行→旧写入兼容验证。新旧统计路径、并发、缓存重执行、写入失败和最终状态有离线覆盖。

## Dependencies

[Deterministic](../query/L2-2.md) 的契约、执行器、实体和词法；Data 仓库；Application AIClient。
`ai_query.py` 组装客户端、DailyQuota、QueryMetrics 和 QueryAgent，main/QQ 通过它进入。

## Boundary with sibling L2-2 modules

Natural 的 local_query 与 validation 共享自然语言判断；Deterministic 管可执行条件语义。Natural 不复制结果筛选器、不拥有通用 AI 传输。
发布通知虽然同用 AIClient，但不复用本域的配额、指标、问句缓存或提示。

## 当前实现与边界

内部实现位于 natural_query/；ai_query.py 继续作为原入口组装它们。额度与指标各实例的线程锁不代表多进程协调；额度故障关闭模型调用，指标故障停记，debug 仅进程内。校验和本地解析对 commands 私有帮助的现有引用保留，不抽共享契约。

向上阅读：[仓库 L1](../../../L1.md)。源码文件头提供唯一 L3，具体行为与字段以实现为准。

后端 2.0 使用 prepare_local → DeferredModel → resume_model，将模型等待移出 QueryGate；当前许可和独立队列由应用层提供。后端禁用问句计划缓存，状态按请求 scope 隔离，原成功计划／状态均有绝对 600 秒期限及空闲清理。详情见 [包 1](../../../docs/QUERY_CHAT_PACKAGE1.md)。
