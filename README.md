# Taki · Our Notes QQ 查询机器人

Taki 是《BanG Dream! Our Notes》日服的非官方社区 QQ 机器人，提供歌曲颜色／激奏组合、谱面、角色卡和 SNAP 查询，以及日服活动资料、卡池资料和人物档案；也支持四服当前／最近活动与挑战歌曲 Top 100 观测。普通指令直接查询资料；自然语言 `/问` 优先在本地解析，需要模型辅助时也只让模型提取条件，实际结果由程序检索数据生成。群内先 @Taki，发送 `/介绍` 了解机器人，`/帮助` 查看用法。

本项目基于 [NeriWST/ournotes-qq-bot](https://github.com/NeriWST/ournotes-qq-bot) 开发。当前默认通过 [Haneoka](https://haneoka.org/jp/zh-CN/songs/) 读取日服歌曲、卡牌、完整谱面、四服活动与挑战歌曲榜；榜单上游仍为 MoeNotes tracker。Project Yume、MoeNotes 等旧适配器保留供显式选择，失败时只使用有时限的同源已验证缓存。第三方资料的完整性和更新时效不等于官方保证；仓库不包含 QQ 凭据、全量上游数据或可再分发的游戏素材包。

## 现在能做什么

以下是已实现的功能；后文“后续开发方向”单独列出尚未开放的内容。

| 功能 | 当前能力 | 示例 |
|---|---|---|
| 歌曲查询 | 按名称、昵称、乐队、ID、颜色、激奏组合和等级条件搜索，支持指定难度和分页 | `/查曲 蓝色 MyGO EX 激奏=JUST`、`/问 哪些歌是纯COMBO` |
| 谱面查询 | 显示各难度等级、Note 数，以及可获取的完整音符静态图 | `/查谱面 100001 EX` |
| 活动信息 | 四服当前／最近活动详情；日服已收录活动列表、ID／名称详情及来源明确的关联卡 | `/查活动`、`/查活动 hk`、`/查活动 列表`、`/查活动 2` |
| 卡池资料 | 日服当前／历史卡池、ID／名称详情、UP 角色卡与留影卡 | `/查卡池`、`/查卡池 历史`、`/查卡池 12` |
| 人物档案 | 按乐队分组的角色目录、姓名／昵称／ID详情、人物资料与关联卡数量 | `/查角色`、`/查角色 tmr`、`/查角色 MyGO` |
| 活动歌曲榜线 | 当前／最近及已有本地历史；日服（jp）／国服（hk）／韩服（kr）／英服（en）挑战歌曲 Top 100；三曲横排五档趋势、附近排名与完整区间分数表 | `/查榜线`、`/查榜线 100 hk`、`/查榜线 20-40` |
| 本地字段短答 | 等级、Note、颜色、激奏、难度、完整匹配数量与明确卡牌类型／ID的技能 | `/问 迷星叫 EX 多少 Note`、`/问 迷星叫是什么颜色` |
| 成员卡查询 | 多维条件网格列表、精确ID详情、独立卡面；支持 BD 生日卡，保留完整技能与有依据的属性状态 | `/查卡 mygo SSR`、`/查卡 BD`、`/查卡 1` |
| 成员技能反查 | 按技能名、效果关键词、队长／Live／激奏类型筛卡，可组合角色和稀有度 | `/问 SSR得分提升技能的成员卡` |
| 留影卡查询 | SNAP多维条件列表、精确ID详情与独立卡面，保留多人关联和两套支援分类 | `/问 tmr的SR留影卡有哪些`、`/查留影卡 1` |
| 别名与状态 | 查已收录别名、缓存状态、技能索引完整度、同步时间和进程内 AI 调试计数 | `/查缩写 tmr`、`/数据状态`、`/调试数据`、`/帮助` |
| 多条指令 | 一条消息每行一条，默认最多执行 4 条，按书写顺序回复 | 将 `/查卡 1`、`/查留影卡 1` 分两行发送 |
| 连续发送 | 接收尚未发送的完整结果；按 ID 查询详情 | `/继续`、`/查卡 51`、`/查谱面 100001 EX` |
| 自动更新通知 | 受管版本切换成功后，使用已配置的 DeepSeek API 生成简短说明并发送到已记录、允许主动消息的群 | 需要 `AI_API_KEY`；每个版本生成一次，同一群同一版本只尝试发送一次 |

群聊查询需要先 **@Taki**；单聊直接发送指令。支持中、日、英名称及已收录昵称，部分命令可自动识别语言。普通群聊内容不会触发查询回复。

QQ 彩蛋：发送 `/查卡 947` 会直接回复维护者提供的固定图片，独立于普通卡牌查询；其他 ID、筛选条件、`/查卡面` 和自然语言查询沿用正常流程。

### 活动、卡池与人物资料

三个入口使用与歌曲、卡牌相同的图片主题；图文来自同一份查询结果。完整列表和长详情超出图片预算时按完整内容分图，单次发不完用 `/继续`，按图片里的 ID 查询详情。
人物目录按乐队排成五人行，档案立绘与基本资料并排；关联留影卡保留横向比例。同一卡片在活动中的多种身份合并显示；奖励或 UP 关联尚不完整时，保留已确认内容并提示缺失。

- `/查活动 [jp/hk/kr/en]` 保留四服当前／最近活动，显示时间、状态及挑战歌曲，不读取玩家排名。`/查活动 列表`、`/查活动 历史`、`/查活动 ID或名称` 查询日服已收录资料。历史详情不附当前榜线入口；奖励卡、加成卡分别标明，未核实的加成百分比及完整奖励表不展示。
- `/查卡池` 显示日服当前时间窗内的卡池资料；`/查卡池 历史` 查询已结束卡池，也可用 ID 或名称查详情。UP 卡分别提供 `/查卡 ID`、`/查留影卡 ID`。日期缺失、零时间和账户显示条件不会被解释为人人可抽；首版不提供概率、费用或保底说明。
- `/查角色` 按乐队展示角色目录；支持中文／日文／英文姓名、已收录昵称、角色 ID、乐队名或 `乐队=MyGO`。详情包含来源提供的人物图、担当、CV、生日和简介等，缺值保持未获取。成员卡与多人留影卡按角色 ID 关联、按卡片去重，人物档案不会因暂无卡片而消失；底部命令可继续查对应卡牌。

新卡池与人物入口使用中文命令和中文界面；人物／卡池名称保留可核对的来源译文，缺少中文时显示来源原文。资料来自同版本 Haneoka JP 主快照，intl 只提供身份核对后的文本，不表示已支持其他服卡池或人物资料。旧缓存未含对应资料时提示未获取，刷新失败沿用有效缓存并标注状态。

### 活动挑战歌曲榜线

先用 `/查活动 [jp/hk/kr/en]` 查看当前／最近活动、各服时间及挑战歌曲 ID；它不读取玩家排行。活动歌曲榜线用 `/查榜线 [jp/hk/kr/en] [歌名或歌曲ID=完整ID] [50或20-40] [仅数值]`，参数组顺序不限。四服名称为日服（jp）、国服（hk）、韩服（kr）、英服（en），也支持既有中文服名；每次省略均为日服，显式服务器失败不会改查日服。

往期活动使用 `/查榜线 id1` 或 `/查榜线 活动="完整活动名称"`，可组合服务器、歌曲与排名，例如 `/查榜线 hk id1 20-40`。`id1` 表示活动 1，也支持 `ID1`、`id 1`、`id=1`、`id:1`，兼容 `活动ID=1`；裸数字仍表示排名。名称优先完整匹配，部分名称命中多个活动时提示活动 ID；ID 和名称同时指定时须指向同一活动。指定活动只读取本地已保存观测，不联网补抓或回退到当期。分数表显示各曲最近一次有效观测的完整分数和对应时间，默认仍画五档趋势；后续过期、冲突或损坏记录会跳过并注明原因，结果不是确认终榜。历史不保存玩家身份，因此往期图片和文字使用分数表，不画玩家身份占位。全部所选排名没有有效分数时返回简短说明。旧库可按活动 ID 查询；日服还可用已收录活动资料的名称，其他服旧记录缺名称时需使用 ID。

不指定歌曲查本期全部挑战歌曲。默认 Haneoka 来源的原始挑战序号未确认，`歌曲1`、`歌曲一`等序号输入会明确拒绝；请使用歌名或从 `/查活动` 取得的歌曲 ID。裸数字始终是排名：`50`、`T50`、`t50` 都查询 T40～T60，并高亮 T50；靠近1或100时直接裁切。`20-40`、`20—40` 查询区间每一行，不扩展端点；`50-50` 精确一名，`1-100` 完整100名。越界、倒序或冲突条件明确报错。

```text
/查榜线
/查榜线 hk
/查榜线 100 hk
/查榜线 50
/查榜线 20—40 hk
/查榜线 50-50
/查榜线 1-100
/查榜线 hk 夢我夢中 T1,T10,T37
/查榜线 歌名="长歌名 37" 50
/查榜线 歌曲ID=100109 50-50
/查榜线 100 仅数值
/问 查榜线 100 hk
```

上例中的歌名和 ID 须替换为所选服当期活动的实际歌曲。完整名称与收录别名仍可查询，名称歧义会澄清，非本期歌曲明确拒绝。歌名含参数词、服务器缩写或纯数字时使用 `歌名="完整名称"`；曲目 ID 使用 `歌曲ID=完整ID`。重复一致参数去重，不同服务器、歌曲或排名条件冲突不按先后猜测。旧 `T1 T10 T37`／逗号写法保留，只列指定点、最多五个；多个裸数字不作为排名列表。

**无排名才画趋势**：默认当前三曲横排成一张图，保留 T1／2／3／10／100 当前值与各曲历史；选一曲时用单曲视图。零点、单点、缺采、持平、下降及同值重叠均如实标明，不虚构曲线。非常规曲目数量按捕获顺序完整分页，展示顺序不代表已确认上游原始挑战序号。

**有排名生成分数表图片**：共用排名列、各歌曲对齐，每个当前分数同时显示对应玩家的**数字ID和用户名**；趋势图上方的五档当前值也显示两者。ID和用户名来自同一条上游榜单记录，不按分数排序或挪动名次；缺失字段或旧缓存尚未取得时分别显示“未获取”，缺分数时不展示玩家身份。真实0保留，数字不缩写，用户名完整换行。附近表和长区间按排名连续分页，每页最多25行，各页保留所有歌曲和完整请求区间；名称／整数／ID／备注可能减少每页行数，不丢行。文字分数表按列显示“分数/数字ID/用户名”，列顺序与上方歌曲编号一致，含分隔符的用户名用引号包围。三曲完整100名含较多用户名时可能超出五条QQ回复预算，会改用完整文字；文字仍超限时请指定一首歌曲或缩小区间。历史曲线仍只记录分数。

`仅数值` 是主动选择纯文字；它和显式排名表都跳过本次曲线历史读取，正常查询观测写入与后台采样保持原契约。图文与失败回退使用同份捕获结果，不重新查上游。QQ整批先预算，容量不足改用完整且有界的文字；完整结果仍放不下时明确提示拆开命令、指定歌曲或缩小区间，不发送貌似完整的半张表。发送结果不明不自动重发。

默认入口为 Haneoka Game Records，上游为 MoeNotes 活动挑战歌曲榜，不是活动积分榜或预测。各曲源采集时间独立；缺失时间、采集时间明显晚于上游参考时钟、期外或过期数据不显示为可信当前值。单纯上游／本机时钟偏差不阻止当前查询，也不额外提示；偏差超过60秒时，历史仅在同一响应的 HTTP Date 可核实时按来源相对年龄校准并保留原始时间审计；否则留缺口，恢复后断线续记。不声称同步采集或确认终榜。来源与缓存契约见[活动歌曲榜线](docs/EVENT_CUTOFFS.md)。

### 歌曲颜色与激奏组合

```text
/查曲 蓝色
/查曲 颜色=蓝/绿 激奏=JUST EX lv<=25 页2
/查曲 激奏=纯JUST
/查曲 激奏=混合
/查曲 激奏=JUST/JUST/COMBO
/查曲 激奏=包含全部JUST/COMBO
/问 MyGO有哪些带JUST激奏的歌
/问 找激奏顺序是combo/just/luck的歌曲
```

颜色支持红／蓝／绿／黄／紫，同维度任选，跨维度同时满足。单个激奏类型表示“包含”，纯类型表示所有段落同类，混合表示至少两类；斜杠序列精确匹配顺序与次数，`包含全部` 则不限制顺序。歌曲主表的激奏序列按原顺序显示，不从卡牌技能或谱面 Fever 区间推测。QQ 展示完整结果，超限分图并以 `/继续` 续发；文字 CLI 保留页码查询。歌曲列表与谱面详情在歌名前显示游戏内属性图标，歌名下方用紧凑小框显示激奏顺序及 JUST／COMBO／LUCK 三种游戏原生图标，ID／乐队位于左下角。属性图标暂缺时回退颜色文字；激奏图标暂缺时保留类型文字。数据未知明确提示。

默认颜色与激奏组合随 Haneoka 日服主快照一起捕获，并按整点／半点刷新。显式使用旧 Yume 主资料时，仍通过独立的 `haneoka-song-traits-jp.json` 补充已核实关联，有效期24小时、失败5分钟后重试。缺失记录显示未获取、不参与对应条件筛选，刷新失败保留并标记旧缓存；`/数据状态` 可查看覆盖数、版本和本机获取时间。无需 AI 密钥。

### 卡牌稀有度与技能

成员摘要在程序启动读取缓存、主资料同步成功时自动重建，与卡牌同版本发布。已识别的队长属性加成按技能、目标和乐队资料生成，新卡65、66无需逐张登记；数值和条件须与完整描述一致。无需模型或额外配置，刷新失败保留有效旧资料并标旧。未知机制或真正缺失的效果仍保留“未确认”，不会自动猜补。

`/查卡` 查询角色卡，`/查留影卡`（兼容 `/查支援卡`、`/查SNAP`）查询留影卡。条件查询始终返回卡框网格，即使只命中一张；明确 ID 才返回完整详情。先匹配全部结果并按ID去重。QQ 单图优先展示完整列表，超限按完整行分图，单次发不完时使用 `/继续`。

```text
/查卡 SSR 颜色=黄色,蓝色 乐队=MyGO 角色=tmr
/查卡 BD
/查卡 LIVE=分数提升 击奏=JUST
/查卡 得意=MyGO
/查SNAP EX
/查留影卡 角色=tmr,skk 乐队=MyGO LIVE=技能延长
/查SNAP LIVE=LIFE回复 击奏=JUST
/查卡 51
/查SNAP 61
/查卡面 51
/查留影卡面 51
/问 MyGO的红色SSR角色卡有哪些
/问 角色=tmr LIVE=技能延长的SNAP有哪些
```

不同维度同时满足，同维度多选任意满足；多角色任意包含，得意乐曲标签要求全部包含且仅限角色卡。已核实角色卡 R/SR/SSR/BD（生日卡），SNAP另有EX；BD仅适用于角色卡。二/三/四星旧输入只作为R/SR/SSR别名保留。颜色支持红、蓝、绿、黄、紫；这是图标颜色称呼，未宣称为正式属性名称。

LIVE分类与击奏JUST/COMBO/LUCK独立。当前真实成员卡均为分数提升；SNAP另外有技能延长、LIFE回复、判定强化，不能把技能延长冒充加分。EX的两项LIVE支援同时保留，击奏不适用。原成员技能关键词反查继续可用，例如 `/问 SSR得分提升技能的成员卡`。

角色卡与留影卡使用统一字体、浅色背景、分隔线和游戏原生属性／稀有度图标；渐变边框由本项目绘制，不冒充官方卡框。列表按完整卡片行分页，保留技能摘要与 ID。角色卡详情展示卡面、满级基础属性及队长／演出／激奏技能；留影卡保持横向比例，展示多人关联、百分比属性和全部支援技能，EX 的两项演出支援均保留。不显示玩家等级或培养状态，也不把留影卡属性汇总为综合力。

`/查卡面 ID`、`/查留影卡面 ID` 直接输出公开 full 卡面，保持来源原始像素尺寸，暂不选择觉醒前后。详情与列表保持正文字号，超过图片预算时拆分完整内容；新绘制图片采用 4:4:4 编码，查看细节请打开原图。缺资料、未知分类与不适用分别提示。见[图片输出说明](docs/IMAGE_OUTPUT.md)和[字段、素材及缓存说明](docs/更新说明-成员卡与支援卡查询.md)。

已核实的队长技能逐项标明加成对象，不把不同对象的加成合成无条件总值。默认技能与主快照同版；未知或缺失效果明确提示未确认。当前已核实版本中，成员卡64激奏 Lv.5 缺第二项效果，不拿其他等级或旧来源补齐。显式旧主资料模式的独立摘要缓存遇到新卡会提前尝试刷新，失败后至少等待5分钟再试。已知缺失见[统一来源说明](docs/HANEOKA_UNIFIED.md)。

### 谱面怎么看

完整谱面默认 `OURNOTES_CHART_SOURCE=haneoka`，页脚标明 Haneoka JP。旧来源可人工选择，新旧缓存分别保留；这项开关独立于主资料和榜线。

完整谱面从**左侧第一栏底部向上读**，到顶后接右侧下一栏底部，各栏从左向右接续。图中带栏号和阅读说明；左右位置与划键方向保持原数据含义。

当前是静态完整谱面，使用游戏原生音符贴图，长条按节点连线。每列内部按 32 个四分音符拍组织，栏头只显示栏号；歌曲资料在最左侧竖列展示，右侧所有谱面栏横向连续排列，整首谱面合为一张图；保持轨道宽度、音符间距和文字大小。轨道外用纯文字标注 `0:00`、每隔 15 秒及谱面结束时间，位置按 BPM 变化换算，结束取谱面末节点而非音频长度；时间按整秒显示。技能在左侧以紫色 `S1` 编号牌表示，实心开始、空心结束，区间为 5 秒参考窗口；激奏在右侧以粉色三角开始、方块结束，`G1` 对应来源区间的顺序。跨栏双斜线表示延续，不代表真实起止，两类区间线同宽，起止图标移至侧线外并使用局部抗锯齿。谱面专用尺寸上限为 9600 万像素、最长边 30000 像素，单图仍不超过现有 3 MB 上传预算；超限时退文字，不拆成多张或省略谱面内容。手机查看密集段时可打开原图放大。尚无局部放大、播放或变速模拟。JUST／COMBO／LUCK 使用游戏原生轮廓图标、类型文字与顺序箭头；图标在本机按需缓存，缺图仍保留文字。未指定难度时优先预览 EXPERT；音符文件不可获取时保留等级和 Note 信息。图片按查询生成，无需清空已有原始谱面缓存。

歌曲详情的技能点位图显示触发时间、Note 密度、激奏区间，以及每个 5 秒技能窗口内的判定数量、占比和排序；这些统计来自同一份谱面，不能把原始节点数直接当作判定数。独立素材准备覆盖固定谱面贴图及角色、卡牌、封面、活动和卡池图片，受管 Linux 部署在停止旧实例前下载并校验，更新与重启复用本地缓存；控制器安装与失败行为见 [Linux 更新说明](deploy/LINUX_OFFLINE.md#查询素材准备)。首次获取谱面数据或实时活动／榜线仍可能请求公开接口，不代表所有资料都可永久离线使用。

### 连续查询

QQ 列表展示完整结果，未发送完时使用 `/继续`。详情直接发送 `/查卡 ID`、`/查留影卡 ID` 或 `/查谱面 ID 难度`；单项或已选择结果可用 `/详情`。已移除四个旧指令：`/下一页`、`/上一页`、`/选`、`/难度`。`/问 第三个`、`/问 选二`、`/问 看详情`、`/问 换成 HARD` 使用同一套本地操作，不调用模型。多项列表须先选择再看详情或切难度。

上下文按平台、群／单聊、会话和用户隔离；10 分钟没有成功续查或机器人重启后失效。资料或昵称版本更新后需重新查询。只有 QQ 接口确认发送成功才建立或推进上下文；发送失败、不明或请求取消不会推进。同消息多个列表没有默认上下文，依赖上一条结果的自然续查须分开发送。完整新查询使用自己写明的条件；榜线省略服务器始终为日服。

## 快速开始

榜线历史与周期采样配置见 [历史采样运维说明](docs/CUTOFF_HISTORY.md)。默认开启查询历史写入，周期采样需显式启用；四服发布配置为每 300 秒采样、长期保留，磁盘可用空间低于 512 MiB 时暂停。数据从启用后积累，不补造过去。

需要 **Python 3.10 以上**。图片绘制还需要可用的中日韩字体，例如 Windows 微软雅黑或 Noto Sans CJK；缺少字体时会记录原因并退回文字。Noto Sans SC／Roboto 字体按 OFL 随包分发。

以下命令适用于 Windows PowerShell，在项目根目录执行。发布包名为 `taki-ournotes-bot`，兼容命令名 `ournotes-bot` 和模块名 `ournotes_bot`。

### 先在本地查资料

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ournotes_bot.main --help
.\.venv\Scripts\python.exe -m ournotes_bot.main sync
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查曲 迷星叫
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查卡 SSR
.\.venv\Scripts\python.exe -m ournotes_bot.main repl
```

`--help` 不需要 QQ 凭据或缓存；`sync` 下载资料并构建技能索引，首次使用需要网络。`query` 和 `repl` 可在不连接 QQ 的情况下测试文字查询，输入 `exit` 退出交互台。图片及部分卡牌详情按需获取，不意味着所有查询都能完全离线运行。

### 再连接 QQ

首次配置可从模板建立 `.env`，保留已经存在的文件：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

填写 `QQ_APP_ID`、`QQ_APP_SECRET`；也可以使用已有的用户环境变量。不要公开 `.env` 或真实密钥。平台接入和测试步骤见 [LOCAL_QQ_TEST.md](LOCAL_QQ_TEST.md)。

```powershell
.\deploy\start-bot.ps1
```

`start-bot.ps1` 会识别已有自动更新管理状态，避免再启动一个实例。`setup-menu` 可单独安装单聊菜单和单聊／群聊快捷指令面板，两个面板均提供 `/查榜线`；会修改 QQ 配置，内容一致时不重复写入。应在运行版本已支持新指令后更新面板；基础查询无需先安装菜单。

## 自然语言、数据与运行设置

### `/问` 的工作方式

单个字段直接给文字短答，例如 `/问 迷星叫 EX 多少 Note`、`/问 迷星叫是什么颜色`、`/问 迷星叫有哪些难度`、`/问 MyGO 有多少首歌`、`/问 角色卡 1 的 LIVE 技能`。数量按完整筛选集合计算，资料覆盖不足时说明已确认数量；Note 缺失显示暂无资料，源确认的零仍显示 0。成员卡和 SNAP 同号时必须说明类型。列表图文使用相同的页内编号。

旧版完整刷新曾重写的缓存，需要新版重新获取来源后才能确认 Note 的真实零值；来源未恢复时继续显示未知。

常见歌曲等级、实体列表、成员技能、支援卡和稀有度问法在本地解析，**不调用 AI、不消耗 AI 额度**。普通直接指令也不调用大模型。需要模型辅助的受支持问法，才使用可选 AI 配置：

```dotenv
AI_API_KEY=你的API密钥
AI_MODEL=deepseek-chat
AI_BASE_URL=https://api.deepseek.com
AI_DAILY_LIMIT=100
```

模型仅生成受限的结构化动作；实体和技能关键词必须能在用户原问题及本地资料中核对，程序再查询缓存并生成图文。文字和图片使用同一份 `QueryResult`，不会把模型自由文本当作答案。

需要模型时，程序先在本地判断歌曲、谱面、成员卡或支援卡能力，只向模型披露该能力的字段规则；本地无法判断能力时，才额外调用一次轻量路由。只有结构化参数可修复时允许再规划一次，单条查询硬限制为最多 3 次模型调用、2 次本地工具执行和 1 次修复；空结果、歧义、不支持、未知实体、数据不可用、超时和提供方故障都会立即终止，不会自动删减条件、改换实体或重试网络请求。

每日额度按北京时间自然日持久保存，重启不清零；**每次真正发起模型请求前分别计数**，所以“模型路由＋专项解析”计 2 次，发生一次参数修复再计 1 次，提供方失败也计入。成功结果和确定性失败会在当前进程内缓存；确定性失败使用短期缓存，数据或昵称版本变化后失效，网络、额度和统计故障不会缓存为业务结论。无密钥、额度用尽或额度记录不可用时，普通查询与本地可解析的 `/问` 仍可用。

复杂问题的文本会发给所配置的 AI 服务，请勿包含私人信息。机器人日志不记录 `/问` 正文；独立的 `ai-metrics.json` 只按北京时间日期累计分路结果和提供方实际返回的 Token 用量，不写入问题正文、用户／群标识、模型完整响应或数据库内容。统计文件损坏或不可写时只停用统计，不影响查询。

`/调试数据` 显示本次进程启动后的两个内存计数：模型服务成功返回 JSON 对象时，“成功 API 调用”加 1；一条使用了模型且最终实际输出检索记录的 `/问` 完成时，“产生实际检索内容的 AI 查询”加 1。路由和解析分别调用模型时，前者可增加多次而后者只增加一次；空结果、请求澄清、未知对象、不支持、数据不可用、页码越界、提供方失败和缓存命中都不会增加有效检索数。重启机器人会清零，不写入统计文件。

### 缓存与昵称

`sync` 按所选来源同步歌曲、角色、成员卡、SNAP及技能资料。默认 Haneoka 使用主缓存旁独立的 `haneoka-catalog-jp-v1.json`，不覆盖 Yume 旧缓存。运行中的机器人在香港时间每个整点和半点尝试刷新；就绪后等待下一个时点，刷新结束后重新对齐，耗时跨过的时点不补跑。失败只回退通过校验的同源资料，分类或字段不完整时明确提示，不跨源补造。

`/数据状态` 显示的是**本机最近一次成功保存资料的时间和状态**，不是上游更新时刻，也不是持续在线证明。

人工确认的昵称维护在 [query_aliases.json](query_aliases.json)，支持歌曲、乐队、角色和成员卡别名；角色昵称也可用于支援卡。未核实、歧义或目标不存在的昵称不会随意映射。新增别名时参考[昵称词表维护规范](昵称词表维护规范.md)。

### 常用配置

完整模板见 [.env.example](.env.example)。修改设置后需重启生效。

| 配置 | 默认或用途 |
|---|---|
| `OURNOTES_CACHE_FILE` | 源码运行时默认 `data/ournotes-cache.json` |
| `OURNOTES_CACHE_TTL_HOURS` | 主缓存有效期，默认 0.5 小时 |
| `OURNOTES_DATA_SOURCE` | 主资料默认 `haneoka`，旧来源可显式设为 `yume` |
| `OURNOTES_CHART_SOURCE` | 完整谱面默认 `haneoka`，独立于其他来源开关 |
| `OURNOTES_CUTOFF_SOURCE` | 活动／榜线默认 `haneoka`；旧 `tracker` 与待认证验收的 `open` 保留 |
| `OURNOTES_ALIAS_FILE` | 可选自定义昵称表路径 |
| `OURNOTES_AI_QUOTA_FILE` | 默认在缓存旁保存 `ai-quota.json` |
| `OURNOTES_AI_METRICS_FILE` | 默认在缓存旁保存匿名分类统计 `ai-metrics.json` |
| `OURNOTES_QUERY_CONCURRENCY` / `OURNOTES_QUERY_QUEUE_LIMIT` | 默认同时准备 2 条回复，另有 4 条等待；满额时提示稍后重试 |
| `OURNOTES_MULTI_COMMAND_LIMIT` | 每条消息默认最多执行 4 条指令，保留超限提示的位置 |
| `OURNOTES_REPLY_ORDER` | 默认开启，按消息到达顺序发送；等候超过 60 秒会允许先行发送 |
| `OURNOTES_QQ_GATEWAY_HOST` | 默认 `api.bot.qq.com`，用于替换服务端下发的旧网关域名；置空关闭改写 |
| `OURNOTES_UPDATE_NOTICES` | 默认开启更新群通知；设为 `0` 可关闭 |

无论回复顺序开关如何，同一条消息内的多条指令始终按书写顺序回复。日志记录耗时、回复大小及发送结果；直接命令正文最多记录 60 字，`/问` 只记录字数，群发现逻辑不保存聊天正文。

源码运行时配置和数据放在项目根目录。普通 Python 包安装从启动目录读取 `.env`，默认数据目录为 Windows 的 `%LOCALAPPDATA%\ournotes-qq-bot` 或 Linux/macOS 的用户数据目录。相对缓存、额度和统计路径按配置目录解析，避免把运行数据写进 Python 安装目录。

## 自动更新与群通知

Windows 单实例可启用[五分钟自动更新](自动更新说明.md)：功能分支／PR → CI → 合并 main → 主分支 CI → 独立环境验证 → 切换运行版本。首次需单独初始化并安装任务，安装 Python 包不会自动开启部署。

Linux（Ubuntu 24.04、x86_64、Python 3.12）另有[离线发布与更新协议](deploy/LINUX_OFFLINE.md)：CI 从同一 Git 提交归档构建源码和安装包，固定依赖与哈希，在断网环境验证全新安装及回归；main 全部检查成功后发布提交专属 Release。服务器在停旧服务前下载、校验和离线准备候选版本；下载线路故障会切换官方资产 API，保留断点并按有界退避继续自动尝试，提供只读中文进度。校验、安装、兼容或启动失败仍阻止更新，保留备份、健康检查与回退。独立控制器须单独审核、安装；合并代码或发布 Release 不代表控制器已替换、服务器已上线或采样已启用。

更新前旧版继续运行；确认新实例连接 QQ 后才完成切换。失败时按原流程恢复上一运行版本，本地有未提交修改时暂停更新。运行版本共享配置、缓存和 AI 额度，回退代码不回退这些数据。

**群通知仅在版本切换完成后生成并发送。**机器人读取这次发布的公开提交标题、变动文件和[更新日志](更新日志.md)新增内容，使用 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 配置的 DeepSeek 接口生成最多 120 字、面向群友的简短说明。只有内部维护而没有群友可感知的变化时跳过公告；技术细节和过长内容也不会发到群里。每个版本只调用模型一次，报告保存后供各群共用；没有密钥、生成失败或缺少可靠变更资料时跳过本次通知，不发送旧内容。每个群每个版本只尝试发送一次；发送失败或回执不明确时不自动重发，可能漏掉当次通知。成功以 QQ 返回的有效消息 ID 为准。

群标识通过实际收到的群消息及入群事件自动登记。首次启用前未记录过的旧群，先 **@Taki 发送一次 `/数据状态`** 即可登记，之后无需每次触发。关闭群内主动消息权限即可停止接收；接收范围为已记录且允许主动消息的群，接口权限和发送结果仍由 QQ 校验。

发送记录保存在缓存旁的 `update-notices.sqlite3`，仅在本机使用，不进仓库。不要删除记录来补发通知。普通本地查询或未经过更新器的启动不会仅因启动而广播。

组队／约练留言、用户自报练习记录等保留为后续候选，先看实际需求与维护成本。现阶段提供有上游依据的歌曲效率排序与活动挑战歌曲 Top 100 观测，继续不支持泛攻略、配队推荐、其他排名分析、预测、积分档线、账号操作和代练；列入展望不改变这些边界。

建议下一批先处理**同义问法、缺失值与简洁回复**，同时整理 ON 新字段的可得性表；再按真实群使用反馈选择局部谱面或卡牌对比。每批单独交付，数据调查没有结论时明确留空，不拖住已经可以完成的小改进。

## 验证与贡献

提交和发布以完整离线测试及 Python 3.10／3.12 的测试、打包 CI 为自动门槛。测试数量会随合并和拆分变化，不在文档中手工维护固定数字。自动测试不连接真实 QQ，也不调用收费模型。

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

CI 在没有真实凭据的环境运行测试、构建 wheel 和源码包，并检查昵称表、更新文案及文档随包提供，排除运行缓存和私有数据。另有 Linux 离线包构建与断网安装检查；main 的发布步骤须等所有验证成功。已有发布产物可用 `python scripts/check_release_artifact.py dist` 检查。

人工只确认自动测试无法证明的真实链路：QQ `@` 触发、消息和图片送达、手机端可读性、同步后的数据完整度，以及本次确实改到的模型或更新通知链路。固定冒烟和按改动范围追加的专项步骤统一维护在 [QQ 接入与验收](LOCAL_QQ_TEST.md#4-在-qq-中验收)，其他文档不再复制命令清单。

Taki 与独立的 X 推文翻译机器人是两个项目，维护时不要混用目录或停止另一方进程。本项目代码沿用原仓库的 [MIT License](LICENSE)，游戏和第三方数据、素材不在此许可范围内。

图片输出统一按体积与尺寸预算编码，必要时等比缩小，保留整张内容；图片上传等待为30秒，上传失败退文字，消息发送结果不确定时不自动重发。本次卡牌大更新的来源、维护边界和验收记录见 [2026-09-28 更新报告](docs/RELEASE_2026-09-28.md)。


### 图片输出

QQ 查询尽量以一张原字号图片展示完整结果，超出图片预算才按完整内容分图；单次发送不完时使用 `/继续`，按图片中的 ID 查询详情。角色卡和留影卡列表保留技能摘要，详情、谱面与榜线采用统一样式。`/查留影卡` 兼容原 `/查支援卡`；群聊文字、图文及失败回退会 @ 指令发出用户；单聊不加 @。规则、素材缓存与性能口径见 [图片输出说明](docs/IMAGE_OUTPUT.md)。
