# Taki · Our Notes QQ 查询机器人

Taki 是《BanG Dream! Our Notes》日服的非官方社区 QQ 机器人，提供歌曲、谱面、歌曲效率、成员卡和支援卡查询。普通指令直接查询资料；自然语言 `/问` 优先在本地解析，需要模型辅助时也只让模型提取条件，实际结果由程序检索数据生成。

本项目基于 [NeriWST/ournotes-qq-bot](https://github.com/NeriWST/ournotes-qq-bot) 开发。歌曲和卡牌资料来自 [Project Yume](https://bdon.yatta.moe/)，完整音符谱面按需读取 [MoeNotes](https://github.com/StarMoe-org/moenotes) 的公共资源。第三方资料的完整性和更新时效不等于官方保证；仓库不包含 QQ 凭据或游戏素材。

## 现在能做什么

以下是已实现的功能；后文“后续开发方向”单独列出尚未开放的内容。

| 功能 | 当前能力 | 示例 |
|---|---|---|
| 歌曲查询 | 按名称、昵称、乐队、ID、等级条件搜索，支持指定难度和分页 | `/查曲 迷星叫`、`/问 MyGO的EXPERT 25级以下歌曲` |
| 谱面查询 | 显示各难度等级、Note 数，以及可获取的完整音符静态图 | `/查谱面 100001 EX` |
| 歌曲分数表 | 全难度每分钟得分效率前 30 条，逐行数据表；支持乐队、难度、等级与单曲查询 | `/查分数表`、`/查分数表 MyGO EX` |
| 成员卡查询 | 多维条件网格列表、精确ID详情、独立卡面；保留完整技能与有依据的属性状态 | `/查卡 mygo SSR`、`/查卡 1` |
| 成员技能反查 | 按技能名、效果关键词、队长／Live／激奏类型筛卡，可组合角色和稀有度 | `/问 SSR得分提升技能的成员卡` |
| 支援卡查询 | SNAP多维条件列表、精确ID详情与独立卡面，保留多人关联和两套支援分类 | `/问 tmr的SR支援卡有哪些`、`/查支援卡 1` |
| 别名与状态 | 查已收录别名、缓存状态、技能索引完整度、同步时间和进程内 AI 调试计数 | `/查缩写 tmr`、`/数据状态`、`/调试数据`、`/帮助` |
| 多条指令 | 一条消息每行一条，默认最多执行 4 条，按书写顺序回复 | 将 `/查卡 1`、`/查支援卡 1` 分两行发送 |
| 自动更新通知 | Windows 自动更新成功后，使用已配置的 DeepSeek API 生成简短说明并发送到已记录、允许主动消息的群 | 需要 `AI_API_KEY`；每个版本生成一次，同一群同一版本只尝试发送一次 |

群聊查询需要先 **@Taki**；单聊直接发送指令。支持中、日、英名称及已收录昵称，部分命令可自动识别语言。普通群聊内容不会触发查询回复。

### 卡牌稀有度与技能

`/查卡` 查询角色卡，`/查支援卡`（别名 `/查SNAP`）查询 SNAP。条件查询始终返回卡框网格，即使只命中一张；明确 ID 才返回完整详情。每页16张，先匹配全部结果并按ID去重，再分页，显示总数、范围和保留条件的下一页命令。QQ当前每次回一张图，大列表需逐页查看。

```text
/查卡 SSR 颜色=黄色,蓝色 乐队=MyGO 角色=tmr
/查卡 LIVE=分数提升 击奏=JUST
/查卡 得意=MyGO
/查SNAP EX
/查支援卡 角色=tmr,skk 乐队=MyGO LIVE=技能延长
/查SNAP LIVE=LIFE回复 击奏=JUST
/查卡 51
/查SNAP 61
/查卡面 51
/查支援卡面 51
/问 MyGO的红色SSR角色卡有哪些
/问 角色=tmr LIVE=技能延长的SNAP有哪些
```

不同维度同时满足，同维度多选任意满足；多角色任意包含，得意乐曲标签要求全部包含且仅限角色卡。已核实角色卡 R/SR/SSR，SNAP另有EX；BD编码尚未核实，会明确提示不能筛选。二/三/四星旧输入只作为R/SR/SSR别名保留。颜色支持红、蓝、绿、黄、紫；这是图标颜色称呼，未宣称为正式属性名称。

LIVE分类与击奏JUST/COMBO/LUCK独立。当前真实成员卡均为分数提升；SNAP另外有技能延长、LIFE回复、判定强化，不能把技能延长冒充加分。EX的两项LIVE支援同时保留，击奏不适用。原成员技能关键词反查继续可用，例如 `/问 SSR得分提升技能的成员卡`。

角色卡列表使用原卡面与类型图标；SSR为渐变彩框、SR为金黄框、R为蓝框，不显示稀有度文字角标。三列网格仍每页16张，框内按队长/演出/激奏展示三项技能Lv.5数值与必要条件，框外保留ID。技能摘要读取 Haneoka 日服独立缓存，缺失或映射冲突不补造数值；SNAP列表采用同主题横向网格，稀有度框仅包卡面，独立技能区显示Lv.5基础技能类型、数值及必要触发/上限；成员条件加成在ID详情查看，外层蓝紫框统一卡面与技能，底部保留ID。框体是设计实现，并非已取得的官方卡框素材，不添加玩家等级/红点。成员ID详情以完整卡面配同款稀有度边框，并分区显示基本资料、属性条、队长/演出/激奏完整Lv.5技能、多语言标题与上游时间；SNAP详情独立展示完整横图、多人关联、百分比属性与全部演出/激奏支援技能（EX的两项演出支援均保留）。属性只展示已确认的Lv.1/Rank1（成员觉醒0次）资料状态，不冒称满级。独立卡面使用公开full版本，暂不选觉醒前后。缺资料、未知分类与不适用分别提示。见[字段、素材及缓存说明](更新说明-成员卡与支援卡查询.md)。

### 谱面怎么看

完整谱面从**左侧第一栏底部的“起点 ↑”向上读**，到顶后接右侧下一栏底部，各栏从左向右接续。图中带栏号和阅读说明；左右位置与划键方向保持原数据含义。

当前是静态音符预览，长条按节点连线，纵向音符间距已约加倍，图片也相应变长；手机查看密集段时可打开原图放大。尚无局部放大、播放或变速模拟。未指定难度时优先预览 EXPERT；音符文件不可获取时退回等级和 Note 信息。图片按查询生成，无需清空已有原始谱面缓存。

### 歌曲效率怎么看

`/查分数表` 直接展示**每分钟得分效率最高的前 30 条谱面**，默认 **全难度、eff 降序**。同一歌曲的 EASY、NORMAL、HARD、EXPERT 可分别出现在同一榜单；30 条不代表 30 首不同歌曲。图片使用逐行表格，列出名次、封面／歌名、难度及等级、时长、得分系数、每分钟得分效率。指定 `EX` 等难度时仅显示该难度，少于 30 条时展示全部有效结果。封面缺失使用占位图。

旧 `/查效率` 保留为兼容别名，帮助和翻页提示统一使用新命令。单曲详情不写难度时仍默认 EXPERT；也可用 `/查分数表 歌名 全难度` 查看该曲各难度的对照表。缺失时提示可用难度，不自动替换。同名或多候选需用 ID 明确选择。

```text
/查分数表
/查分数表 MyGO EX
/查分数表 暗黒天国
/查分数表 100043 EX
/查分数表 MyGO EX lv<=25 页2
/查分数表 EX 指标=score 排序=desc
/问 查一下分数表
/问 每分钟得分效率最高的前30首歌曲
/问 暗黒天国的效率怎么样
/问 查一下暗黒天国EX的meta
/问 哪些歌效率最高
/问 MyGO的EX效率前十有哪些
/问 EXPERT 25级以下的效率榜
```

这些问法本地解析，无 AI 配置或额度用尽仍可使用。默认每页 30 条，也支持明确指定 `前10`、`前20`、`前三十`；榜单翻页保留数量、筛选和排序条件。仅支持一个等级边界（`lv>=`、`lv>`、`lv<=`、`lv<`），指标为 `eff` 或 `score`，顺序为 `desc` 或 `asc`。其他条件明确拒绝，不静默忽略。

数据来自 [Haneoka 日服分析](https://haneoka.org/jp/zh-CN/song-meta/)，不是地址中 `intl` 对应的国际服。`eff` 是上游在参考条件下计算的每分钟相对分数系数，显示为百分数；`score` 是相对分数系数，**不是实际得分**。参考条件固定为全 PERFECT、Fever、技能倍率 2.5、持续 10 秒及曲间 30 秒。时长是同曲各难度最晚判定点时间的最大值，按分:秒显示（四舍五入到秒，不含曲间 30 秒）；难度等级优先取上游 `displayLevel`，缺失时依次取 `playLevel`、`sortLevel`，等级条件使用相同口径；`sr` 是技能覆盖贡献比。无法确认其他队伍、单人／协力等模式的口径，首版不开放这些条件。

排行榜只包含与本地歌曲 ID、名称核验一致且指标有效的记录，显示有效样本覆盖与筛选内排序，不能当作完整全曲榜或官方结论。全难度榜均为含 Fever 的同一参考条件，不混排不同模式或分析假设；不提供无 Fever 榜，不把第一名重新归一化成 100%。歌曲已收录但分析缺失、口径不符或映射冲突时，会明确提示，不把未知当作 0。

无需新增密钥或配置。首次效率查询获取独立的 `haneoka-meta-jp.json`（主缓存旁），24 小时后按需刷新；失败保留旧数据并标记，5 分钟内不重复尝试。保存上游版本和本机成功获取时间，后者不是上游更新时间。原歌曲／卡牌缓存不变。图片与文字使用同一结果，绘图失败回退文字。

## 快速开始

需要 **Python 3.10 以上**。图片绘制还需要可用的中日韩字体，例如 Windows 微软雅黑或 Noto Sans CJK；缺少字体时会记录原因并退回文字。本项目不附带字体文件。

以下命令适用于 Windows PowerShell，在项目根目录执行。发布包名为 `taki-ournotes-bot`，兼容命令名 `ournotes-bot` 和模块名 `ournotes_bot`。

### 先在本地查资料

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ournotes_bot.main --help
.\.venv\Scripts\python.exe -m ournotes_bot.main sync
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查曲 迷星叫
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查卡 SSR
.\.venv\Scripts\python.exe -m ournotes_bot.main repl
```

`--help` 不需要 QQ 凭据或缓存；`sync` 下载资料并构建技能索引，首次使用需要网络。`query` 和 `repl` 可在不连接 QQ 的情况下测试文字查询，输入 `exit` 退出交互台。图片及部分卡牌详情按需获取，不意味着所有查询都能完全离线运行。

### 再连接 QQ

首次配置可从模板建立 `.env`，保留已经存在的文件：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

填写 `QQ_APP_ID`、`QQ_APP_SECRET`；也可以使用已有的用户环境变量。不要公开 `.env` 或真实密钥。平台接入和测试步骤见 [LOCAL_QQ_TEST.md](LOCAL_QQ_TEST.md)。

```powershell
.\start-bot.ps1
```

`start-bot.ps1` 会识别已有自动更新管理状态，避免再启动一个实例。`setup-menu` 可单独安装单聊菜单和快捷指令面板，会修改 QQ 配置；基础查询无需先安装菜单。

## 自然语言、数据与运行设置

### `/问` 的工作方式

常见歌曲等级、实体列表、成员技能、支援卡和稀有度问法在本地解析，**不调用 AI、不消耗 AI 额度**。普通直接指令也不调用大模型。需要模型辅助的受支持问法，才使用可选 AI 配置：

```dotenv
AI_API_KEY=你的API密钥
AI_MODEL=deepseek-chat
AI_BASE_URL=https://api.deepseek.com
AI_DAILY_LIMIT=100
```

模型仅生成受限的结构化动作；实体和技能关键词必须能在用户原问题及本地资料中核对，程序再查询缓存并生成图文。文字和图片使用同一份 `QueryResult`，不会把模型自由文本当作答案。

需要模型时，程序先在本地判断歌曲、谱面、成员卡或支援卡能力，只向模型披露该能力的字段规则；本地无法判断能力时，才额外调用一次轻量路由。只有结构化参数可修复时允许再规划一次，单条查询硬限制为最多 3 次模型调用、2 次本地工具执行和 1 次修复；空结果、歧义、不支持、未知实体、数据不可用、超时和提供方故障都会立即终止，不会自动删减条件、改换实体或重试网络请求。

每日额度按北京时间自然日持久保存，重启不清零；**每次真正发起模型请求前分别计数**，所以“模型路由＋专项解析”计 2 次，发生一次参数修复再计 1 次，提供方失败也计入。成功结果和确定性失败会在当前进程内缓存；确定性失败使用短期缓存，数据或昵称版本变化后失效，网络、额度和统计故障不会缓存为业务结论。无密钥、额度用尽或额度记录不可用时，普通查询与本地可解析的 `/问` 仍可用。

复杂问题的文本会发给所配置的 AI 服务，请勿包含私人信息。机器人日志不记录 `/问` 正文；独立的 `ai-metrics.json` 只按北京时间日期累计分路结果和提供方实际返回的 Token 用量，不写入问题正文、用户／群标识、模型完整响应或数据库内容。统计文件损坏或不可写时只停用统计，不影响查询。

`/调试数据` 显示本次进程启动后的两个内存计数：模型服务成功返回 JSON 对象时，“成功 API 调用”加 1；一条使用了模型且最终实际输出检索记录的 `/问` 完成时，“产生实际检索内容的 AI 查询”加 1。路由和解析分别调用模型时，前者可增加多次而后者只增加一次；空结果、请求澄清、未知对象、不支持、数据不可用、页码越界、提供方失败和缓存命中都不会增加有效检索数。重启机器人会清零，不写入统计文件。

### 缓存与昵称

`sync` 同步歌曲、角色、成员卡、SNAP等基础资料，并并发获取两类卡的详情构建分类索引。运行中的机器人每六小时尝试刷新；旧缓存升级失败仍可查已有资料，分类索引不完整会提示暂不可筛选。无需新配置，新增信息保存在旧读者可忽略的顶层扩展中，详情失败保留上次有效数据。

`/数据状态` 显示的是**本机最近一次成功保存资料的时间和状态**，不是上游更新时刻，也不是持续在线证明。

人工确认的昵称维护在 [query_aliases.json](query_aliases.json)，支持歌曲、乐队、角色和成员卡别名；角色昵称也可用于支援卡。未核实、歧义或目标不存在的昵称不会随意映射。新增别名时参考[昵称词表维护规范](昵称词表维护规范.md)。

### 常用配置

完整模板见 [.env.example](.env.example)。修改设置后需重启生效。

| 配置 | 默认或用途 |
|---|---|
| `OURNOTES_CACHE_FILE` | 源码运行时默认 `data/ournotes-cache.json` |
| `OURNOTES_CACHE_TTL_HOURS` | 主缓存有效期，默认 6 小时 |
| `OURNOTES_ALIAS_FILE` | 可选自定义昵称表路径 |
| `OURNOTES_AI_QUOTA_FILE` | 默认在缓存旁保存 `ai-quota.json` |
| `OURNOTES_AI_METRICS_FILE` | 默认在缓存旁保存匿名分类统计 `ai-metrics.json` |
| `OURNOTES_QUERY_CONCURRENCY` / `OURNOTES_QUERY_QUEUE_LIMIT` | 默认同时准备 2 条回复，另有 4 条等待；满额时提示稍后重试 |
| `OURNOTES_MULTI_COMMAND_LIMIT` | 每条消息默认最多执行 4 条指令，保留超限提示的位置 |
| `OURNOTES_REPLY_ORDER` | 默认开启，按消息到达顺序发送；等候超过 60 秒会允许先行发送 |
| `OURNOTES_QQ_GATEWAY_HOST` | 默认 `api.bot.qq.com`，用于替换服务端下发的旧网关域名；置空关闭改写 |
| `OURNOTES_UPDATE_NOTICES` | 默认开启更新群通知；设为 `0` 可关闭 |

无论回复顺序开关如何，同一条消息内的多条指令始终按书写顺序回复。日志记录耗时、回复大小及发送结果；直接命令正文最多记录 60 字，`/问` 只记录字数，群发现逻辑不保存聊天正文。

源码运行时配置和数据放在项目根目录。普通 Python 包安装从启动目录读取 `.env`，默认数据目录为 Windows 的 `%LOCALAPPDATA%\ournotes-qq-bot` 或 Linux/macOS 的用户数据目录。相对缓存、额度和统计路径按配置目录解析，避免把运行数据写进 Python 安装目录。

## 自动更新与群通知

Windows 单实例可启用[五分钟自动更新](自动更新说明.md)：功能分支／PR → CI → 合并 main → 主分支 CI → 独立环境验证 → 切换运行版本。首次需单独初始化并安装任务，安装 Python 包不会自动开启部署。

更新前旧版继续运行；确认新实例连接 QQ 后才完成切换。失败时按原流程恢复上一运行版本，本地有未提交修改时暂停更新。运行版本共享配置、缓存和 AI 额度，回退代码不回退这些数据。

**群通知仅在版本切换完成后生成并发送。**机器人读取这次发布的公开提交标题、变动文件和[更新日志](更新日志.md)新增内容，使用 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 配置的 DeepSeek 接口生成最多 120 字、面向群友的简短说明。只有内部维护而没有群友可感知的变化时跳过公告；技术细节和过长内容也不会发到群里。每个版本只调用模型一次，报告保存后供各群共用；没有密钥、生成失败或缺少可靠变更资料时跳过本次通知，不发送旧内容。每个群每个版本只尝试发送一次；发送失败或回执不明确时不自动重发，可能漏掉当次通知。成功以 QQ 返回的有效消息 ID 为准。

群标识通过实际收到的群消息及入群事件自动登记。首次启用前未记录过的旧群，先 **@Taki 发送一次 `/数据状态`** 即可登记，之后无需每次触发。关闭群内主动消息权限即可停止接收；接收范围为已记录且允许主动消息的群，接口权限和发送结果仍由 QQ 校验。

发送记录保存在缓存旁的 `update-notices.sqlite3`，仅在本机使用，不进仓库。不要删除记录来补发通知。普通本地查询或未经过更新器的启动不会仅因启动而广播。

## 后续开发方向

这是基于当前实现整理的路线图，**不是已开放功能，也不是一次性开工承诺**。技能详情、成员技能反查、两类卡牌稀有度筛选、谱面方向修复、版本更新群通知已经完成，不再列作待开发。

### 优先做：现有功能的准确性与使用体验

| 工作 | 解决什么问题 | 完成标准 |
|---|---|---|
| 缺失数据与口径统一 | 缺失的 Note、数值或技能参数不能当作真实零值；资料最大值和玩家培养值要区分 | 确认字段和显示口径后，再开放依赖它们的排序／比较 |
| 同义问法覆盖 | 部分等价的中文等级描述仍会进入 AI 分支，增加配置依赖和调用成本 | 覆盖同义词、词序和难度表达，在已有测试中验证本地处理且筛选含义一致 |
| 查询结果更简洁 | 只问等级或 Note 数时给短回复；多候选便于选中，减少重复输入名称和 ID | 图文一致、歧义不盲选、继续保留完整指令入口 |
| 连续查询 | 在上一份列表上继续选项、翻页或换难度 | 按群＋用户隔离，列表快照和过期提示明确，不串别人结果；已有分页保留 |
| 谱面局部阅读 | 长图在手机上不易看清，希望按段查看或放大 | 局部和全谱方向一致，保留跨段长条上下文，不以绘图节点数冒充判定数 |
| 通知状态与维护诊断 | 方便知道群是否登记、通知是成功、拒绝还是结果不明 | 提供受控的维护入口和清晰状态，不向群友暴露内部标识，不盲目补发 |

### 接着做：有数据依据的查询扩展

| 候选方向 | 数据前提与边界 |
|---|---|
| ON 专属歌曲资料 | 先确认乐队／属性加成条件、激奏分段类型和坐标、适用模式与版本；现有演唱乐队标签不能直接当作加成条件，不能照搬 Garupa 机制 |
| 两张卡并排对比 | 使用同口径数值、技能和明确的缺失提示；不据此替玩家作培养或抽卡决定 |
| 支援效果关键词、更多排序 | 已有LIVE/击奏分类与组合筛选；任意效果关键词、等级区间和自定义排序仍需定义确定语义，不悄悄放宽条件 |
| 本地资料变化摘要 | 比较资料同步前后快照，列新增歌曲／卡牌或已确认字段变化；这是资料更新，区别于已经实现的程序版本通知，首次建立基准不把全库当新增 |
| 活动与卡池资料 | 先核实名称、时间、时区和来源，再考虑提醒；目前相关命令仍是未开放占位 |

### 先调查：长期方向与依赖

| 方向 | 当前缺口 | 推进顺序 |
|---|---|---|
| 当前档线与历史走势 | 尚未接入经核实的 ON 实况来源，不能把其他游戏或演示数据当作结果 | 先调查来源、授权和采样条件，再积累带活动、档位、时间和出处的样本 |
| 预测线 | 尚无可验证的历史样本和预测误差记录 | 实况与历史稳定后再评估；届时与当前线同屏但明确区分，不能承诺“安全线” |
| ON 限定短聊天／新手问答 | `/问` 目前是查询入口，尚无独立聊天和审核知识库 | 先积累有来源的机制资料，再设计独立入口、短回复、范围限制和费用上限 |
| 资料采集与攻略知识库 | 尚无来源白名单、审核流程或后台采集任务 | 由 Taki 获取允许来源，去重后进待审核池；确认版本、条件与证据后才能进入答案 |

组队／约练留言、用户自报练习记录等保留为后续候选，先看实际需求与维护成本。现阶段只开放有上游依据的歌曲效率排序，继续不支持泛攻略、配队推荐、其他排名分析、预测、实时档线、账号操作和代练；列入展望不改变这些边界。

建议下一批先处理**同义问法、缺失值与简洁回复**，同时整理 ON 新字段的可得性表；再按真实群使用反馈选择局部谱面或卡牌对比。每批单独交付，数据调查没有结论时明确留空，不拖住已经可以完成的小改进。

## 验证与贡献

提交和发布以完整离线测试及 Python 3.10／3.12 的测试、打包 CI 为自动门槛。测试数量会随合并和拆分变化，不在文档中手工维护固定数字。自动测试不连接真实 QQ，也不调用收费模型。

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

CI 在没有真实凭据的环境运行测试、构建 wheel 和源码包，并检查昵称表、更新文案及文档随包提供，排除运行缓存和私有数据。已有发布产物可用 `python scripts/check_release_artifact.py dist` 检查。

人工只确认自动测试无法证明的真实链路：QQ `@` 触发、消息和图片送达、手机端可读性、同步后的数据完整度，以及本次确实改到的模型或更新通知链路。固定冒烟和按改动范围追加的专项步骤统一维护在 [QQ 接入与验收](LOCAL_QQ_TEST.md#4-在-qq-中验收)，其他文档不再复制命令清单。

Taki 与独立的 X 推文翻译机器人是两个项目，维护时不要混用目录或停止另一方进程。本项目代码沿用原仓库的 [MIT License](LICENSE)，游戏和第三方数据、素材不在此许可范围内。
