# Taki · Our Notes QQ 查询机器人

激奏舞台查询默认日服，可指定 `jp/hk/kr/en` 和 `赛季=N`。

- `/查激奏舞台 [服] [乐队] [概览|规则|排期|乐曲|段位与奖励]`。空参看当前赛季五联赛概览，指定乐队看当前规则及接下来三次轮换。可单查 `段位` 或 `奖励`。概览只读赛季资料。
- `/查激奏榜线 [服] 乐队 [榜单|人数|人数明细] [排名条件] [仅数值]`。例如 `/查激奏榜线 hk MyGO T100` 或 `/问 hk MyGO激奏榜线 T100多少` 查询指定位置的舞台积分。省略排名默认列 T1、T2、T3、T10、T100，写 `榜单` 则列前 20。裸数字 `50` 查 T40–T60，`20-40` 查连续位置，`T1 T10 T100` 查离散位置。一次最多跨 100 个响应位置，离散最多五个。`人数` 显示联赛上榜总人数和各大段人数，`人数明细` 展开已开放的小段。积分为来源观测。
- 旧 `/查竞技场` 语法可继续使用。

`/查活动` 默认查看日服已收录活动列表，输入活动 ID 查看详情。加成档位、奖励、任务及关联卡池均在详情图内，长结果使用 `/继续`。实时活动使用 `/查活动 当前` 或指定区服，只有活动 ID 和起止时间与资料一致时才补充明细。

竞技场匿名读取 Haneoka 公开接口；资料使用 jp／intl 固定版本，实时区域独立为 jp／tw／en／kr（用户 hk 对应 tw）。来源待统计、限流和不可用分别提示，不回退到另一服。榜单内存缓存60秒，人数30分钟；来源失败不会更新成功时间，Retry-After 冷却期间不重复请求。

`/查 MyGO激奏舞台排期`、`/查 MyGO激奏榜线人数`、`/查 本期活动奖励` 使用本地固定语法并复用同一执行器，不调用模型。QQ 群面板将 `/介绍` 的快捷位用于新增激奏查询，群里仍可手动发 `/介绍`。已安装的 QQ 面板通过 `ournotes-bot setup-menu` 单独同步。

消息入口：`/查 内容` 进行自然语言资料查询（旧 `/问`、`/ask` 保留为查询别名）。启用 Koishi 聊天 Agent 后，`/聊 内容` 或正文提到“立希”／`taki` 可触发聊天，不必 @机器人；非 @触发需要平台实际下发群消息。明确查询命令优先。查询回复 @发送者，聊天回复不 @，整条聊天正文末尾省略句号。旧 bot／CLI 不提供聊天 Agent。


Taki 是《BanG Dream! Our Notes》日服的非官方社区 QQ 机器人，提供歌曲颜色／激奏组合、谱面、角色卡和 SNAP 查询，以及日服活动资料、卡池资料和人物档案；也支持四服当前／最近活动与挑战歌曲 Top 100 观测。普通指令直接查询资料；自然语言 `/问` 优先在本地解析，需要模型辅助时也只让模型提取条件，实际结果由程序检索数据生成。群内先 @Taki，发送 `/介绍` 了解机器人，`/帮助` 查看用法。

本项目基于 [NeriWST/ournotes-qq-bot](https://github.com/NeriWST/ournotes-qq-bot) 开发。当前默认通过 [Haneoka](https://haneoka.org/jp/zh-CN/songs/) 读取日服歌曲、卡牌、完整谱面、四服活动与挑战歌曲榜；榜单上游仍为 MoeNotes tracker。Project Yume、MoeNotes 等旧适配器保留供显式选择，失败时只使用有时限的同源已验证缓存。第三方资料的完整性和更新时效不等于官方保证；仓库不包含 QQ 凭据、全量上游数据或可再分发的游戏素材包。

### 活动、卡池与人物资料

- `/一图流` 读取日服当前或最近一期活动的单张图片。后台在活动开场后准备固定奖励、徽章兑换和挑战曲配队，成图保存到服务器。空缓存启动时也会补生成最近一期已结束的活动。
- 在群里引用 Taki 刚发的查询图并点名追问时，支持视觉的聊天模型可读取同群近期发送的原图。图片最多在进程内复用 5 分钟，重启或缓存淘汰后可直接重发原图。

三个入口使用与歌曲、卡牌相同的图片主题；图文来自同一份查询结果。完整列表和长详情超出图片预算时按完整内容分图，单次发不完用 `/继续`，按图片里的 ID 查询详情。
人物目录按乐队排成五人行，档案立绘与基本资料并排；关联留影卡保留横向比例。同一卡片在活动中的多种身份合并显示；奖励或 UP 关联尚不完整时，保留已确认内容并提示缺失。

- `/查活动 [jp/hk/kr/en] 当前` 显示当前／最近活动的时间、状态及挑战歌曲。确认有独立综合榜时附五档分数和观测时间。`/查活动` 与 `/查活动 列表` 等价，`/查活动 历史` 只列已结束的日服活动。`/查活动 ID或名称` 查询日服资料，历史详情包含静态明细。
- `/查活动 MyGO 红色` 直接筛选日服活动，也可以加 `高松灯`、`tmr` 或 `类型2`。可写 `乐队 MyGO` 或 `角色 高松灯` 消除歧义，旧写法 `属性=红色` 仍可用。回复会区分明确匹配和资料不足的期数。命中的加成、已知类型 ID 与详情指令显示在每期旁边。实时总览的榜线指令锁定图上的区服和活动，换期后查询该期已保存的观测。日服活动提供显式关联卡池的查询指令。
- `/查活动 ID 2到5 MyGO 红,蓝` 组合活动 ID 区间与加成条件。同类条件用逗号多选，命中任一项即可，不同类条件同时满足。ID 区间包含两端，支持 `2-5`、`2~5`、`ID>=2`、`5以下`。裸单个数字仍按 ID 查详情。`挑战演出`、`挑战Live` 对应已确认的类型 1，其他类型可继续用 ID。
- `/问 这期活动结束了吗`、`/问 下一次活动什么时候开始` 本地解析，直接回答北京时间及区服。空档期说明最近一期结束时间，不提醒清 CP；有下一期日程则给开始时间。没有下一期日程时有界读取 Haneoka 活动公告，只有正文明确给出可核验日期与时区才补充时间和原文链接；标题、公告发布时间、结算时间和未读图片不能代替活动开始时间。直达入口为 `/查活动 [jp/intl] 日程`、`/查活动 [jp/intl] 下期`。此处台服／国际服对应 intl 资料，不改变四区榜线身份。
- `/查卡池` 与 `/查卡池 列表` 都按开池时间倒序显示日服已收录资料。`当前` 只查已确认在开放时间窗内的卡池，`最近` 在空档期显示最近结束的卡池，`历史` 可加名称或 ID 筛选。例 `/查卡池 分类=星钻 ID 2到12` 可组合分类和包含两端的 ID 区间。分类写在名称或 ID 条件前。
- `/查卡池 12`、`/查卡池 名称` 查看详情，多条匹配时显示候选。详情合并分类、限定与展示条件、UP 成员卡、UP 留影卡、上游明确关联的活动。随图文字可复制查询入口，发不完用 `/继续`。日期缺失时标注未确认，概率、费用及保底暂未提供。
- `/查角色` 按乐队展示日服角色目录，支持中／日／英文姓名、昵称、角色 ID 和乐队名。可用 `/查角色 担当=吉他` 或 `/查角色 乐队=MyGO 担当=吉他` 筛选。档案展示来源提供的人物资料与可唯一命中的常用查名。成员卡与多人留影卡按角色 ID 关联并按卡片去重，随图命令可直接按该角色 ID 查询对应卡牌。

新卡池与人物入口使用中文命令和中文界面；人物／卡池名称保留可核对的来源译文，缺少中文时显示来源原文。资料来自同版本 Haneoka JP 主快照，intl 只提供身份核对后的文本，不表示已支持其他服卡池或人物资料。旧缓存未含对应资料时提示未获取，刷新失败沿用有效缓存并标注状态。

### 活动挑战歌曲榜线

榜线按活动查询，每次默认日服。`/查榜线` 展示全部课题曲，符合榜制和来源条件时附独立综合榜。参数组顺序不限。

```text
/查榜线 [jp/hk/kr/en] [id1或活动="完整名称"] [单曲或总榜] [排名或区间] [仅数值]
/查榜线 hk 100
/查榜线 kr 单曲 20-40
/查榜线 jp 总榜 T1,T10,T100
/查榜线 hk id1 50-50 仅数值
/查榜線 en 1-100
/问 查榜线 100 hk
```

- 日服（jp）、国服（hk）、韩服（kr）、英服（en）保留中文别名，国服内部仍用 `tw`。旧 `/榜线` 和繁体 `/查榜線` 可用。
- `单曲` 选全部课题曲榜，`总榜`（或 `综合榜`）选独立综合分数榜。按歌名、歌曲 ID 或序号选歌的入口已移除。
- `50`、`T50`、`t50` 查询 40–60，靠近 1 或 100 时裁切，目标行高亮。区间含两端，`50-50` 精确一行，`1-100` 查询整榜。多个 `T` 位置可用空格或逗号分隔，最多五个不同位置。
- 省略排名显示 T1／2／3／10／100 及采样趋势。有排名时出分数表，跳过曲线历史。加 `仅数值` 输出文字。榜线按响应位置，玩家名字和公开数字 ID 随同一条分数记录展示，缺项留空并标注。
- `id1`、`ID1`、`id 1`、`id=1`、`id:1`、`活动ID=1` 选择活动 1，也可用 `活动="完整活动名称"`。往期榜线读取本地最后有效观测，无历史时提示，各曲观测时间可能不同。
- 默认来源为 Haneoka Game Records。综合榜消费官方快照的 `scoreExact`，独立于单曲榜和活动积分榜。旧 `tracker` 保留原综合榜来源。结算、陈旧及往期观测均标明时间或状态。
- `/查活动` 为已确认有总榜的活动显示五档分数和观测时间。日服往期详情优先使用匹配的本地历史，缺少记录时可读 Haneoka 官方归档。已知旧榜制的活动省略此区块。
- 图片按内容分页，超出这一条 QQ 消息的回复额度时用 `/继续` 发送余下页面。图文和失败回退使用同一份捕获数据。

来源、时效和存储见[活动榜线规则](docs/EVENT_CUTOFFS.md)。

### 歌曲颜色与激奏组合

```text
/查曲 蓝色
/查曲 颜色=蓝/绿 激奏=JUST EX lv<=25 页2
/查曲 激奏=纯JUST
/查曲 激奏=混合
/查曲 激奏=JUST/JUST/COMBO
/查曲 激奏=包含全部JUST/COMBO
/问 MyGO有哪些带JUST激奏的歌
/问 找激奏顺序是combo/just/luck的歌曲
```

颜色支持红／蓝／绿／黄／紫，同维度任选，跨维度同时满足。单个激奏类型表示“包含”，纯类型表示所有段落同类，混合表示至少两类；斜杠序列精确匹配顺序与次数，`包含全部` 则不限制顺序。歌曲主表的激奏序列按原顺序显示，不从卡牌技能或谱面 Fever 区间推测。QQ 展示完整结果，超限分图并以 `/继续` 续发；文字 CLI 保留页码查询。歌曲列表与谱面详情在歌名前显示游戏内属性图标，歌名下方用紧凑小框显示激奏顺序及 JUST／COMBO／LUCK 三种游戏原生图标，ID／乐队位于左下角。属性图标暂缺时回退颜色文字；激奏图标暂缺时保留类型文字。数据未知明确提示。

默认颜色与激奏组合随 Haneoka 日服主快照一起捕获，并按整点／半点刷新。显式使用旧 Yume 主资料时，仍通过独立的 `haneoka-song-traits-jp.json` 补充已核实关联，有效期24小时、失败5分钟后重试。缺失记录显示未获取、不参与对应条件筛选，刷新失败保留并标记旧缓存；`/数据状态` 可查看覆盖数、版本和本机获取时间。无需 AI 密钥。

### 卡牌稀有度与技能

成员摘要在程序启动读取缓存、主资料同步成功时自动重建，与卡牌同版本发布。已识别的队长属性加成按技能、目标和乐队资料生成，新卡65、66无需逐张登记；数值和条件须与完整描述一致。无需模型或额外配置，刷新失败保留有效旧资料并标旧。未知机制或真正缺失的效果仍保留“未确认”，不会自动猜补。

`/查卡` 查询角色卡，`/查留影卡`（兼容 `/查支援卡`、`/查SNAP`）查询留影卡。条件查询始终返回卡框网格，即使只命中一张；明确 ID 才返回完整详情。先匹配全部结果并按ID去重。QQ 单图优先展示完整列表，超限按完整行分图，单次发不完时使用 `/继续`。

用 `/查卡 角色ID=2 SSR` 或 `/查留影卡 角色ID=2` 按日服人物 ID 筛卡。裸数字和 `ID=` 仍查询卡牌 ID。

```text
/查卡 朝着流星呐喊
/查卡 朝着流星 黄
/查卡 卡名:朝着流星呐喊
/查卡 颜色=黄 tmr SSR, SR just
/查卡 mygo 队长 异色
/查卡 mygo 155
/查卡 血量加分 140
/查卡 SSR 150以上
/查卡 演出120到155
/查卡 id 72 mygo
/查卡 SSR 颜色=黄色,蓝色 乐队=MyGO 角色=tmr
```

角色卡和留影卡直接命令可用完整卡名或一段连续卡名，并可和筛选条件混用。卡名与其他条件重名时，可用 `卡名=` 或 `卡名:` 指定。片段含空格且有与筛选词同名的部分时，可写成 `卡名="片段"`。QQ 随列表提供卡名、ID 和可复制的详情命令。显式字段与裸写条件可换序，多选分隔符两侧可留空格。

角色卡队长类型可筛 `同色`、`同技`、`同激`、`异色`，例如 `/查卡 队长 同色`、`/查卡 SSR 队长=同技/同激`。同技对应相同演出技能类型，同激对应相同激奏类型，异色对应按非指定属性成员人数叠加全员加成。

成员卡演出技能支持 `分卡`、`奶卡`、`判卡` 及 `血量加分`、`PERFECT加分`。`/查卡 150` 按 ID 查详情，`/查卡 mygo 150` 或 `/查卡 150 mygo` 查 Lv.5 演出得分 +150%。可用 `演出150` 或 `150%` 单独查得分，也可用 `120/150/155` 多选、`150以上`、`150以下` 或 `120到155`。显式 `id 150 mygo`、`ID=150 mygo` 按 ID 核对乐队。数值同时匹配已核实的通常档和条件档，候选文字标明命中值和完整条件。所需的同版日服技能字段未获取时，回复会提示索引不完整。

### 谱面怎么看

完整谱面默认 `OURNOTES_CHART_SOURCE=haneoka`，页脚标明 Haneoka JP。旧来源可人工选择，新旧缓存分别保留；这项开关独立于主资料和榜线。

难度可用 `EZ / NM / HD / EX` 或全称，也接受全角英文字母。省略难度时，文字列出各档等级与 Note 数，图片只绘制一档，优先 EXPERT，否则选资料中的最后一档。

可在歌曲名或 ID 后加 `镜像` 或 `反转`，也可同时指定难度，例如 `/查谱面 1 EX 镜像`。镜像会翻转每栏的音符左右位置和划键方向，栏的阅读顺序不变。

歌名或 ID 放在最前，难度、镜像和五段技能覆盖时间可以任意排列，例如 `/查谱面 1 镜像 5/6.5/8/5/5 EX`。五个秒数写成一组，也可写 `覆盖=5/6.5/8/5/5`，按触发时间从早到晚对应 S1～S5，填写最终覆盖时长。切换难度和查看详情保留此设置。不填写时每段仍为 5 秒。图中标明各段时长；Haneoka 参考覆盖率／倍率／效率不会因此重新计算。点位数并非五个时会明确提示，不套用五段参数。

完整谱面从**左侧第一栏底部向上读**，到顶后接右侧下一栏底部，各栏从左向右接续。图中带栏号和阅读说明；左右位置与划键方向保持原数据含义。

当前是静态完整谱面，使用游戏原生音符贴图，长条按节点连线。每列内部按 32 个四分音符拍组织，栏头只显示栏号；歌曲资料在最左侧竖列展示，右侧所有谱面栏横向连续排列，整首谱面合为一张图；保持轨道宽度、音符间距和文字大小。轨道外用纯文字标注 `0:00`、每隔 15 秒及谱面结束时间，位置按 BPM 变化换算，结束取谱面末节点而非音频长度；时间按整秒显示。技能在左侧以紫色 `S1` 编号牌表示，实心开始、空心结束，区间为 5 秒参考窗口；激奏在右侧以粉色三角开始、方块结束，`G1` 对应来源区间的顺序。跨栏双斜线表示延续，不代表真实起止，两类区间线同宽，起止图标移至侧线外并使用局部抗锯齿。谱面专用尺寸上限为 9600 万像素、最长边 30000 像素，单图仍不超过现有 3 MB 上传预算；超限时退文字，不拆成多张或省略谱面内容。手机查看密集段时可打开原图放大。尚无局部放大、播放或变速模拟。JUST／COMBO／LUCK 使用游戏原生轮廓图标、类型文字与顺序箭头；图标在本机按需缓存，缺图仍保留文字。未指定难度时优先预览 EXPERT；音符文件不可获取时保留等级和 Note 信息。图片按查询生成，无需清空已有原始谱面缓存。

歌曲详情的技能点位图显示触发时间、Note 密度、激奏区间，以及每个 5 秒技能窗口内的判定数量、占比和排序；这些统计来自同一份谱面，不能把原始节点数直接当作判定数。独立素材准备覆盖固定谱面贴图及角色、卡牌、封面、活动和卡池图片，受管 Linux 部署在停止旧实例前下载并校验，更新与重启复用本地缓存；控制器安装与失败行为见 [Linux 更新说明](deploy/LINUX_OFFLINE.md#查询素材准备)。首次获取谱面数据或实时活动／榜线仍可能请求公开接口，不代表所有资料都可永久离线使用。

## 快速开始

榜线历史与周期采样配置见 [历史采样运维说明](docs/CUTOFF_HISTORY.md)。默认开启查询历史写入，周期采样需显式启用；四服发布配置为每 300 秒采样、长期保留，磁盘可用空间低于 512 MiB 时暂停。数据从启用后积累，不补造过去。

需要 **Python 3.10 以上**。图片绘制还需要可用的中日韩字体，例如 Windows 微软雅黑或 Noto Sans CJK；缺少字体时会记录原因并退回文字。Noto Sans SC／Roboto 字体按 OFL 随包分发。

以下命令适用于 Windows PowerShell，在项目根目录执行。发布包名为 `taki-ournotes-bot`，兼容命令名 `ournotes-bot` 和模块名 `ournotes_bot`。

### 先在本地查资料

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ournotes_bot.main --help
.\.venv\Scripts\python.exe -m ournotes_bot.main sync
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查曲 迷星叫
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查卡 SSR
.\.venv\Scripts\python.exe -m ournotes_bot.main repl
```

`--help` 不需要 QQ 凭据或缓存；`sync` 下载资料并构建技能索引，首次使用需要网络。`query` 和 `repl` 可在不连接 QQ 的情况下测试文字查询，输入 `exit` 退出交互台。图片及部分卡牌详情按需获取，不意味着所有查询都能完全离线运行。

### 再连接 QQ

首次配置可从模板建立 `.env`，保留已经存在的文件：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

填写 `QQ_APP_ID`、`QQ_APP_SECRET`；也可以使用已有的用户环境变量。不要公开 `.env` 或真实密钥。平台接入和测试步骤见 [LOCAL_QQ_TEST.md](LOCAL_QQ_TEST.md)。

```powershell
.\deploy\start-bot.ps1
```

`start-bot.ps1` 会识别已有自动更新管理状态，避免再启动一个实例。`setup-menu` 可单独安装单聊菜单和单聊／群聊快捷指令面板，两个面板均提供 `/查榜线`；会修改 QQ 配置，内容一致时不重复写入。应在运行版本已支持新指令后更新面板；基础查询无需先安装菜单。

## 自然语言、数据与运行设置

### `/问` 的工作方式

本地新增 `/问 蓝色EX25级歌曲`、`/问 蓝色SSR或SR成员卡`、`/问 高松灯的生日卡`、`/问 LIVE技能延长的SNAP`，以及 `/问 当前的卡池有哪些`、`/问 历史活动有哪些`、`/问 高松灯的生日是什么`。整级 `25` 与小数 `25.0`、BD 成员卡与 EX SNAP 保持独立含义。常用繁体语法词与已有多语言实体名可用；完整说明及受限模型参数见 [ON 自然语言词法](docs/ON_LANGUAGE.md)。

单个字段直接给文字短答，例如 `/问 迷星叫 EX 多少 Note`、`/问 迷星叫是什么颜色`、`/问 迷星叫有哪些难度`、`/问 MyGO 有多少首歌`、`/问 角色卡 1 的 LIVE 技能`。数量按完整筛选集合计算，资料覆盖不足时说明已确认数量；Note 缺失显示暂无资料，源确认的零仍显示 0。成员卡和 SNAP 同号时必须说明类型。列表图文使用相同的页内编号。

旧版完整刷新曾重写的缓存，需要新版重新获取来源后才能确认 Note 的真实零值；来源未恢复时继续显示未知。

常见歌曲等级、实体列表、成员技能、支援卡和稀有度问法在本地解析，**不调用 AI、不消耗 AI 额度**。普通直接指令也不调用大模型。需要模型辅助的受支持问法，才使用可选 AI 配置：

```dotenv
AI_API_KEY=你的API密钥
AI_MODEL=deepseek-chat
AI_BASE_URL=https://api.deepseek.com
AI_DAILY_LIMIT=100
```

本节的本地优先流程与旧解析额度适用于 legacy 查询入口。Koishi 后端可显式配置 `OURNOTES_CHAT_ENGINE=agent`：被点名普通文本和 `/问` 进入统一聊天核心，普通聊天允许一次直接回答，需要资料时可连续调用现有只读工具。`/查曲`、`/查卡` 等直接指令仍零模型。新入口沿用已配置 Terra profile、身份、当前许可及加权用量账；默认关闭，不代表已上线。启用后，触发片段与可见回复在独立 `chat-v1.sqlite3` 保留最多 30 日，仅成功送达部分进入短期聊天历史；未参与的群消息不落库。详见 [操作与回退](docs/CHAT_AGENT_RUNBOOK.md) 和 [实际验收](docs/CHAT_AGENT_ACCEPTANCE.md)。

Agent 的组合入口、剧情场景、月度记忆、联网、看图与主动参与见 [F1 候选](docs/CHAT_AGENT_F1.md)。各项按模型能力证据及群服务批准分别开放；全系列剧情正文、真实 Terra／QQ 与生产上线仍有独立验收，不能将离线候选视为已上线。

Agent 聊天支持连续比较和资料补查。例如先问“比较这两张卡的技能”，再说“第二张换成这张，只看 LIVE 技能”，会沿用同一人的任务对象并重新读取所需字段。任务按群和用户隔离，保留 15 分钟；“不用了”“先这样”可结束任务。知识库材料不足时，Taki 可继续检索 Haneoka 目录、详情与关联资料，结合已审核规则作答。普通卡牌、歌曲和机制问题默认按日服资料回答；排行榜、当期活动等实际受区服影响的查询保留区服选择。

成功回应主动 @、点名或 `/聊` 后，同一用户可在默认 3 分钟内不 @ 接着说。Taki 根据对话判断是否仍在和她聊；其他群友插话不清除这段窗口。网页控制台的群详情「交流设置」可开关续聊、调整时长和短消息合并等待，并管理「不主动搭话的用户」。名单中的普通发言不会触发主动聊天，也不会进入主动观察材料；主动找 Taki 及后续交流照常可用。设置持久保存，续聊窗口和研究任务在重启后清空。

群详情同时展示任务状态和最近交流日志；请求详情可查看工具执行、资料补查、模型决定与发送结果。日志记录固定状态、计数和耗时，便于定位“为什么没回”，不额外保存聊天正文、工具参数或隐藏推理。

legacy 模型仅生成受限的结构化动作；实体和技能关键词必须能在用户原问题及本地资料中核对，程序再查询缓存并生成图文。文字和图片使用同一份 `QueryResult`，不会把该解析器的模型自由文本当作答案。

需要模型时，程序先在本地判断歌曲、谱面、成员卡或支援卡能力，只向模型披露该能力的字段规则；本地无法判断能力时，才额外调用一次轻量路由。只有结构化参数可修复时允许再规划一次，单条查询硬限制为最多 3 次模型调用、2 次本地工具执行和 1 次修复；空结果、歧义、不支持、未知实体、数据不可用、超时和提供方故障都会立即终止，不会自动删减条件、改换实体或重试网络请求。

每日额度按北京时间自然日持久保存，重启不清零；**每次真正发起模型请求前分别计数**，所以“模型路由＋专项解析”计 2 次，发生一次参数修复再计 1 次，提供方失败也计入。成功结果和确定性失败会在当前进程内缓存；确定性失败使用短期缓存，数据或昵称版本变化后失效，网络、额度和统计故障不会缓存为业务结论。无密钥、额度用尽或额度记录不可用时，普通查询与本地可解析的 `/问` 仍可用。

复杂问题的文本会发给所配置的 AI 服务，请勿包含私人信息。机器人日志不记录 `/问` 正文；独立的 `ai-metrics.v2.json`（schema 2）按北京时间日期累计处理路径、解析与最终结果，以及提供方实际返回的 Token 用量，不写入问题正文、用户／群标识、模型完整响应或数据库内容。合法空结果与解析失败分开计数；缓存重执行以本次结果为准。旧 `ai-metrics.json` 保留供旧版回退，新口径从启用时起累计，不合并旧计数。统计文件损坏或不可写时只停用统计，不影响查询。

`/调试数据` 显示本次进程启动后的两个内存计数：模型服务成功返回 JSON 对象时，“成功 API 调用”加 1；一条使用了模型且最终实际输出检索记录的 `/问` 完成时，“产生实际检索内容的 AI 查询”加 1。路由和解析分别调用模型时，前者可增加多次而后者只增加一次；空结果、请求澄清、未知对象、不支持、数据不可用、页码越界、提供方失败和缓存命中都不会增加有效检索数。重启机器人会清零，不写入统计文件。

### 缓存与昵称

`sync` 按所选来源同步歌曲、角色、成员卡、SNAP及技能资料。默认 Haneoka 使用主缓存旁独立的 `haneoka-catalog-jp-v1.json`，不覆盖 Yume 旧缓存。运行中的机器人在香港时间每个整点和半点尝试刷新；就绪后等待下一个时点，刷新结束后重新对齐，耗时跨过的时点不补跑。失败只回退通过校验的同源资料，分类或字段不完整时明确提示，不跨源补造。

卡牌技能摘要随主资料同步自动重建并用于正式卡图，包括新增技能和同ID技能变更。已有精修摘要仅在完整机制指纹一致时复用；其它技能根据同版本完整说明逐级生成简写，保留条件、目标、概率、次数和持续时间，不调用大模型。新措辞保留原文，缺中文时沿用日文／英文回退，参数缺失仍显示未确认。详情继续展示完整技能说明。

`/数据状态` 显示本机最近成功同步时间、缓存状态，以及主资料中可明确判定的未确认项（按类别计项，同一资料可重复；含谱面 Note、歌曲属性／激奏、技能、摘要、得意标签与活动／卡池时间）。昵称目标的未确认数仍单独显示。Haneoka 主资料每次成功刷新会和上一份已验证快照比较 ID；最近一次有新增时列出歌曲、成员卡、留影卡、人物、卡池、活动的数量及部分名称，并保留该次记录直到下一次出现新增。首次没有可比快照时显示未知；刷新失败沿用最后的可信记录。这里的时间是**本机取得资料的时间**，不代表上游发布时间或持续在线证明；同 ID 的内容修改不计作新增。

人工确认的昵称维护在 [query_aliases.json](query_aliases.json)，支持歌曲、乐队、角色和成员卡别名；角色昵称也可用于支援卡。未核实、歧义或目标不存在的昵称不会随意映射。新增别名时参考[昵称词表维护规范](昵称词表维护规范.md)。

### 常用配置

完整模板见 [.env.example](.env.example)。修改设置后需重启生效。

| 配置 | 默认或用途 |
|---|---|
| `OURNOTES_CACHE_FILE` | 源码运行时默认 `data/ournotes-cache.json` |
| `OURNOTES_CACHE_TTL_HOURS` | 主缓存有效期，默认 0.5 小时 |
| `OURNOTES_DATA_SOURCE` | 主资料默认 `haneoka`，旧来源可显式设为 `yume` |
| `OURNOTES_CHART_SOURCE` | 完整谱面默认 `haneoka`，独立于其他来源开关 |
| `OURNOTES_CUTOFF_SOURCE` | 活动／榜线默认 `haneoka`；旧 `tracker` 与待认证验收的 `open` 保留 |
| `OURNOTES_ALIAS_FILE` | 可选自定义昵称表路径 |
| `OURNOTES_AI_QUOTA_FILE` | 默认在缓存旁保存 `ai-quota.json` |
| `OURNOTES_AI_METRICS_FILE` | 匿名统计基础路径，默认缓存旁的 `ai-metrics.json`；实际新版写入同目录 `ai-metrics.v2.json`，旧文件保持不变 |
| `OURNOTES_QUERY_CONCURRENCY` / `OURNOTES_QUERY_QUEUE_LIMIT` | 默认同时准备 2 条回复，另有 4 条等待；满额时提示稍后重试 |
| `OURNOTES_MULTI_COMMAND_LIMIT` | 每条消息默认最多执行 4 条指令，保留超限提示的位置 |
| `OURNOTES_REPLY_ORDER` | 默认开启，按消息到达顺序发送；等候超过 60 秒会允许先行发送 |
| `OURNOTES_QQ_GATEWAY_HOST` | 默认 `api.bot.qq.com`，用于替换服务端下发的旧网关域名；置空关闭改写 |
| `OURNOTES_UPDATE_NOTICES` | 默认开启更新群通知；设为 `0` 可关闭 |

无论回复顺序开关如何，同一条消息内的多条指令始终按书写顺序回复。日志记录耗时、回复大小及发送结果；直接命令正文最多记录 60 字，`/问` 只记录字数，群发现逻辑不保存聊天正文。

源码运行时配置和数据放在项目根目录。普通 Python 包安装从启动目录读取 `.env`，默认数据目录为 Windows 的 `%LOCALAPPDATA%\ournotes-qq-bot` 或 Linux/macOS 的用户数据目录。相对缓存、额度和统计路径按配置目录解析，避免把运行数据写进 Python 安装目录。

## 自动更新与群通知

Windows 单实例可启用[五分钟自动更新](自动更新说明.md)：功能分支／PR → CI → 合并 main → 主分支 CI → 独立环境验证 → 切换运行版本。首次需单独初始化并安装任务，安装 Python 包不会自动开启部署。

Linux（Ubuntu 24.04、x86_64、Python 3.12）另有[离线发布与更新协议](deploy/LINUX_OFFLINE.md)：CI 从同一 Git 提交归档构建源码和安装包，固定依赖与哈希，在断网环境验证全新安装及回归；main 全部检查成功后发布提交专属 Release。服务器在停旧服务前下载、校验和离线准备候选版本；下载线路故障会切换官方资产 API，保留断点并按有界退避继续自动尝试，提供只读中文进度。校验、安装、兼容或启动失败仍阻止更新，保留备份、健康检查与回退。独立控制器须单独审核、安装；合并代码或发布 Release 不代表控制器已替换、服务器已上线或采样已启用。

更新前旧版继续运行；确认新实例连接 QQ 后才完成切换。失败时按原流程恢复上一运行版本，本地有未提交修改时暂停更新。运行版本共享配置、缓存和 AI 额度，回退代码不回退这些数据。

**群通知仅在版本切换完成后生成并发送。**机器人读取这次发布的公开提交标题、变动文件和[更新日志](更新日志.md)新增内容，使用 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 配置的 DeepSeek 接口生成最多 120 字、面向群友的简短说明。只有内部维护而没有群友可感知的变化时跳过公告；技术细节和过长内容也不会发到群里。每个版本只调用模型一次，报告保存后供各群共用；没有密钥、生成失败或缺少可靠变更资料时跳过本次通知，不发送旧内容。每个群每个版本只尝试发送一次；发送失败或回执不明确时不自动重发，可能漏掉当次通知。成功以 QQ 返回的有效消息 ID 为准。

群标识通过实际收到的群消息及入群事件自动登记。首次启用前未记录过的旧群，先 **@Taki 发送一次 `/数据状态`** 即可登记，之后无需每次触发。关闭群内主动消息权限即可停止接收；接收范围为已记录且允许主动消息的群，接口权限和发送结果仍由 QQ 校验。

发送记录保存在缓存旁的 `update-notices.sqlite3`，仅在本机使用，不进仓库。不要删除记录来补发通知。普通本地查询或未经过更新器的启动不会仅因启动而广播。

## 后续开发方向

这是基于当前实现整理的路线图，**不是已开放功能，也不是一次性开工承诺**。技能详情、成员技能反查、两类卡牌稀有度筛选、谱面方向修复、版本更新群通知已经完成，不再列作待开发。

### 优先做：现有功能的准确性与使用体验

| 工作 | 解决什么问题 | 完成标准 |
|---|---|---|
| 数值口径扩展 | 在已区分 Note 缺失与零的基础上继续核实其他数值、资料最大值和玩家培养值 | 确认字段和显示口径后，再开放依赖它们的排序／比较 |
| 同义问法覆盖 | 部分等价的中文等级描述仍会进入 AI 分支，增加配置依赖和调用成本 | 覆盖同义词、词序和难度表达，在已有测试中验证本地处理且筛选含义一致 |
| 谱面局部阅读 | 长图在手机上不易看清，希望按段查看或放大 | 局部和全谱方向一致，保留跨段长条上下文，不以绘图节点数冒充判定数 |
| 通知状态与维护诊断 | 方便知道群是否登记、通知是成功、拒绝还是结果不明 | 提供受控的维护入口和清晰状态，不向群友暴露内部标识，不盲目补发 |

### 接着做：有数据依据的查询扩展

| 候选方向 | 数据前提与边界 |
|---|---|
| ON 专属歌曲资料 | 先确认乐队／属性加成条件、激奏分段类型和坐标、适用模式与版本；现有演唱乐队标签不能直接当作加成条件，不能照搬 Garupa 机制 |
| 两张卡并排对比 | 使用同口径数值、技能和明确的缺失提示；不据此替玩家作培养或抽卡决定 |
| 支援效果关键词、更多排序 | 已有LIVE/击奏分类与组合筛选；任意效果关键词、等级区间和自定义排序仍需定义确定语义，不悄悄放宽条件 |
| 本地资料变化摘要 | 比较资料同步前后快照，列新增歌曲／卡牌或已确认字段变化；这是资料更新，区别于已经实现的程序版本通知，首次建立基准不把全库当新增 |
| 活动与卡池规则扩展 | 已有活动详情、日服卡池与人物查询；完整奖励／加成表、卡池概率／费用／保底及主动提醒仍须单独核实字段含义和规则 |

### 先调查：长期方向与依赖

| 方向 | 当前缺口 | 推进顺序 |
|---|---|---|
| 积分档线与历史走势 | 已接入活动歌曲 Top 100 观测；活动积分档线及历史走势未实现 | 继续单独核实来源、授权和采样条件，不从歌曲分数推导积分线 |
| 预测线 | 尚无可验证的历史样本和预测误差记录 | 实况与历史稳定后再评估；届时与当前线同屏但明确区分，不能承诺“安全线” |
| ON 限定短聊天／新手问答 | `/问` 目前是查询入口，尚无独立聊天和审核知识库 | 先积累有来源的机制资料，再设计独立入口、短回复、范围限制和费用上限 |
| 资料采集与攻略知识库 | 尚无来源白名单、审核流程或后台采集任务 | 由 Taki 获取允许来源，去重后进待审核池；确认版本、条件与证据后才能进入答案 |

组队／约练留言、用户自报练习记录等保留为后续候选，先看实际需求与维护成本。现阶段提供有上游依据的歌曲效率排序、活动挑战歌曲 Top 100 观测和固定基准的日服活动挑战曲配队模拟。个人库存配队、泛攻略、其他排名分析、预测、积分档线、账号操作和代练超出当前范围。

建议下一批先处理**同义问法、缺失值与简洁回复**，同时整理 ON 新字段的可得性表；再按真实群使用反馈选择局部谱面或卡牌对比。每批单独交付，数据调查没有结论时明确留空，不拖住已经可以完成的小改进。

## 验证与贡献

提交和发布以完整离线测试及 Python 3.10／3.12 的测试、打包 CI 为自动门槛。测试数量会随合并和拆分变化，不在文档中手工维护固定数字。自动测试不连接真实 QQ，也不调用收费模型。

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

CI 在没有真实凭据的环境运行测试、构建 wheel 和源码包，并检查昵称表、更新文案及文档随包提供，排除运行缓存和私有数据。另有 Linux 离线包构建与断网安装检查；main 的发布步骤须等所有验证成功。已有发布产物可用 `python scripts/check_release_artifact.py dist` 检查。

人工只确认自动测试无法证明的真实链路：QQ `@` 触发、消息和图片送达、手机端可读性、同步后的数据完整度，以及本次确实改到的模型或更新通知链路。固定冒烟和按改动范围追加的专项步骤统一维护在 [QQ 接入与验收](LOCAL_QQ_TEST.md#4-在-qq-中验收)，其他文档不再复制命令清单。

Taki 与独立的 X 推文翻译机器人是两个项目，维护时不要混用目录或停止另一方进程。本项目代码沿用原仓库的 [MIT License](LICENSE)，游戏和第三方数据、素材不在此许可范围内。

图片输出统一按体积与尺寸预算编码，必要时等比缩小，保留整张内容；图片上传等待为30秒，上传失败退文字，消息发送结果不确定时不自动重发。本次卡牌大更新的来源、维护边界和验收记录见 [2026-09-28 更新报告](docs/RELEASE_2026-09-28.md)。


### 图片输出

QQ 查询尽量以一张原字号图片展示完整结果，超出图片预算才按完整内容分图；单次发送不完时使用 `/继续`，按图片中的 ID 查询详情。角色卡和留影卡列表保留技能摘要，详情、谱面与榜线采用统一样式。`/查留影卡` 兼容原 `/查支援卡`；群聊文字、图文及失败回退会 @ 指令发出用户；单聊不加 @。规则、素材缓存与性能口径见 [图片输出说明](docs/IMAGE_OUTPUT.md)。

### 人工别名词库

`query_aliases.json`（可用 `OURNOTES_ALIAS_FILE` 指定路径）支持 `song`、`band`、`character`、`card`、`support_card` 字典和 `outside_catalog` 名称列表。普通字典值为正式名称或 ID 字符串；`support_card` 指向 SNAP，`card` 指向成员卡，两类 ID 分开核实。现有多服 `song` 整数/ID 列表格式仍仅由服别歌曲目录解析。收录的昵称可直接用于对应的查询，例如 `/查曲 茉团`、`/查卡 tmr`。留影卡昵称使用 `/查留影卡`。

词库读取或结构校验失败时保留本进程最后有效版本，修复后自动加载；`/数据状态` 显示词库状态及当前资料未确认的目标数量。最后有效版本仅存在内存，重启前应修复坏文件。空目标、重复键、未知分类和同分类规范化名称冲突会拒绝整次更新；跨分类同名留给查询入口消歧。未收录的目标不会成为有效匹配，也不因资料不完整导致整份词库被拒绝。有效内容更新会失效旧查询缓存及续查上下文。

人工词库收录与证据见 [别名来源](docs/ALIAS_SOURCES.md)。
