# Taki · Our Notes QQ 查询机器人

Taki 是《BanG Dream! Our Notes》日服的非官方社区 QQ 机器人，提供歌曲颜色／激奏组合、谱面、分数表、角色卡和 SNAP 查询。普通指令直接查询资料；自然语言 `/问` 优先在本地解析，需要模型辅助时也只让模型提取条件，实际结果由程序检索数据生成。群内先 @Taki，发送 `/介绍` 了解机器人，`/帮助` 查看用法。

本项目基于 [NeriWST/ournotes-qq-bot](https://github.com/NeriWST/ournotes-qq-bot) 开发。歌曲和卡牌基础资料来自 [Project Yume](https://bdon.yatta.moe/)，普通查曲的颜色和激奏顺序采用 [Haneoka 日服数据](https://haneoka.org/jp/zh-CN/songs/)；分数表独立采用 [Moenotes公开统计快照](https://storage.bdon.moe/moenotes/music-data/music-data.json)，完整音符谱面按需读取 [MoeNotes](https://github.com/StarMoe-org/moenotes) 的公共资源。第三方资料的完整性和更新时效不等于官方保证；仓库不包含 QQ 凭据或游戏素材。

分数表当前接口：**筛选词精简与自由／激奏同图双榜**。保留四难度混合、八类排行、单局兼容及既有美工；任务词默认激奏，单人／多人可指定一榜，移除等级边界和可调计算参数。来源及参数见[分数表与开放平台](docs/META_OPEN.md)，提交／合并与生产运行证据分别见[交接文档](交接文档.md)。合并代码不代表生产已更新；正式榜线仍待时间合同验收。

故障恢复：Project Yume 响应读取中断可使用有效旧缓存，冷启动详情获取失败保留旧技能；坏素材缓存会有限重取，确定不匹配的卡牌不会以缺分类阻断其他对象筛选。Linux CI 的临时 HTTP 中断延期检查，不永久阻止提交；独立控制器的安装及服务器验收见 [Linux 更新说明](deploy/LINUX_OFFLINE.md)。

此前榜线玩家身份显示与自动更新下载恢复继续保留。当前排名／分数同时显示数字 ID 和用户名；Linux 更新器支持官方备用下载线路、断点续传、临时网络故障自动退避恢复及只读中文进度。服务器的独立控制器须单独审核、安装，合并源码不代表线上已经生效，见[榜线规则](docs/EVENT_CUTOFFS.md)和 [Linux 更新说明](deploy/LINUX_OFFLINE.md)。成员卡 61、62、64 技能摘要与 BD 粉紫至珊瑚红边框见[卡牌说明](docs/更新说明-成员卡与支援卡查询.md)。

已实现的**查询升级 v1**继续提供分数表组合筛选、四服挑战歌曲榜线历史趋势、等级／Note 短答和列表续查。历史从启用采集后积累，四服周期采样需显式启用。见[查询升级说明](docs/QUERY_UPGRADE_V1.md)与[历史采样配置](docs/CUTOFF_HISTORY.md)。

## 现在能做什么

以下是已实现的功能；后文“后续开发方向”单独列出尚未开放的内容。

| 功能 | 当前能力 | 示例 |
|---|---|---|
| 歌曲查询 | 按名称、昵称、乐队、ID、颜色、激奏组合和等级条件搜索，支持指定难度和分页 | `/查曲 蓝色 MyGO EX 激奏=JUST`、`/问 哪些歌是纯COMBO` |
| 谱面查询 | 显示各难度等级、Note 数，以及可获取的完整音符静态图 | `/查谱面 100001 EX` |
| 歌曲分数表 | 默认全难度效率前 30 条；组合乐队、颜色、激奏、难度及等级，先筛选后排序 | `/查分数表 MyGO 颜色=蓝 EX 激奏=JUST 前10` |
| 活动歌曲榜线 | 日服（jp）／国服（hk）／韩服（kr）／英服（en）挑战歌曲 Top 100；三曲横排五档趋势、附近排名与完整区间分数表 | `/查榜线`、`/查榜线 100 hk 歌曲一`、`/查榜线 歌曲2 20-40` |
| 本地字段短答 | 等级、Note、颜色、激奏、难度、完整匹配数量与明确卡牌类型／ID的技能 | `/问 迷星叫 EX 多少 Note`、`/问 迷星叫是什么颜色` |
| 成员卡查询 | 多维条件网格列表、精确ID详情、独立卡面；支持 BD 生日卡，保留完整技能与有依据的属性状态 | `/查卡 mygo SSR`、`/查卡 BD`、`/查卡 1` |
| 成员技能反查 | 按技能名、效果关键词、队长／Live／激奏类型筛卡，可组合角色和稀有度 | `/问 SSR得分提升技能的成员卡` |
| 支援卡查询 | SNAP多维条件列表、精确ID详情与独立卡面，保留多人关联和两套支援分类 | `/问 tmr的SR支援卡有哪些`、`/查支援卡 1` |
| 别名与状态 | 查已收录别名、缓存状态、技能索引完整度、同步时间和进程内 AI 调试计数 | `/查缩写 tmr`、`/数据状态`、`/调试数据`、`/帮助` |
| 多条指令 | 一条消息每行一条，默认最多执行 4 条，按书写顺序回复 | 将 `/查卡 1`、`/查支援卡 1` 分两行发送 |
| 有限连续查询 | 在已确认发送的列表上翻页、选择或切换难度 | `/下一页`、`/选 2`、`/难度 EX` |
| 自动更新通知 | Windows 自动更新成功后，使用已配置的 DeepSeek API 生成简短说明并发送到已记录、允许主动消息的群 | 需要 `AI_API_KEY`；每个版本生成一次，同一群同一版本只尝试发送一次 |

群聊查询需要先 **@Taki**；单聊直接发送指令。支持中、日、英名称及已收录昵称，部分命令可自动识别语言。普通群聊内容不会触发查询回复。

QQ 彩蛋：发送 `/查卡 947` 会直接回复维护者提供的固定图片，独立于普通卡牌查询；其他 ID、筛选条件、`/查卡面` 和自然语言查询沿用正常流程。

### 活动挑战歌曲榜线

活动歌曲榜线用 `/查榜线 [jp/hk/kr/en] [歌曲1或歌名] [50或20-40] [仅数值]`，参数组顺序不限。四服名称为日服（jp）、国服（hk）、韩服（kr）、英服（en），也支持既有中文服名；每次省略均为日服，显式服务器失败不会改查日服。

不指定歌曲查本期全部挑战歌曲。`歌曲N` 按选定服本期活动的原始歌曲顺序编号，也接受 `歌曲一`、`歌1`、`第一首`；筛选或缺数据不重新编号，图文同时显示编号和真实歌名。裸数字始终是排名：`50`、`T50`、`t50` 都查询 T40～T60，并高亮 T50；靠近1或100时直接裁切。`20-40`、`20—40` 查询区间每一行，不扩展端点；`50-50` 精确一名，`1-100` 完整100名。越界、倒序或冲突条件明确报错。

```text
/查榜线
/查榜线 hk
/查榜线 歌曲2
/查榜线 100 hk 歌曲一
/查榜线 歌曲2 50
/查榜线 20—40 歌曲三 hk
/查榜线 50-50
/查榜线 1-100
/查榜线 hk 夢我夢中 T1,T10,T37
/查榜线 歌名="长歌名 37" 50
/查榜线 歌曲ID=100109 50-50
/查榜线 100 仅数值
/问 查榜线 100 hk 歌曲一
```

完整名称与收录别名仍可查询，名称歧义会澄清，非本期歌曲明确拒绝。歌名含参数词、服务器缩写或纯数字时使用 `歌名="完整名称"`；曲目 ID 使用 `歌曲ID=完整ID`。重复一致参数去重，不同服务器、歌曲或排名条件冲突不按先后猜测。旧 `T1 T10 T37`／逗号写法保留，只列指定点、最多五个；多个裸数字不作为排名列表。

**无排名才画趋势**：默认当前三曲横排成一张图，保留 T1／2／3／10／100 当前值与各曲历史；选一曲时用单曲视图。零点、单点、缺采、持平、下降及同值重叠均如实标明，不虚构曲线。非常规曲目数量按原序号完整分页。

**有排名生成分数表图片**：共用排名列、各歌曲对齐，每个当前分数同时显示对应玩家的**数字ID和用户名**；趋势图上方的五档当前值也显示两者。ID和用户名来自同一条上游榜单记录，不按分数排序或挪动名次；缺失字段或旧缓存尚未取得时分别显示“未获取”，缺分数时不展示玩家身份。真实0保留，数字不缩写，用户名完整换行。附近表和长区间按排名连续分页，每页最多25行，各页保留所有歌曲和完整请求区间；名称／整数／ID／备注可能减少每页行数，不丢行。文字分数表按列显示“分数/数字ID/用户名”，列顺序与上方歌曲编号一致，含分隔符的用户名用引号包围。三曲完整100名含较多用户名时可能超出五条QQ回复预算，会改用完整文字；文字仍超限时请指定一首歌曲或缩小区间。历史曲线仍只记录分数。

`仅数值` 是主动选择纯文字；它和显式排名表都跳过本次曲线历史读取，正常查询观测写入与后台采样保持原契约。图文与失败回退使用同份捕获结果，不重新查上游。QQ整批先预算，容量不足改用完整且有界的文字；完整结果仍放不下时明确提示拆开命令、指定歌曲或缩小区间，不发送貌似完整的半张表。发送结果不明不自动重发。

来源是 MoeNotes 活动挑战歌曲榜，不是活动积分榜或预测。各曲源采集时间独立；活动与单曲有效期、时间冲突、陈旧和最后观测状态保留，不声称同步采集或确认终榜。源码、本地测试、CI和实际QQ送达分别验收；当前改动与验收边界见[交接文档](交接文档.md)，来源与缓存契约见[活动歌曲榜线](docs/EVENT_CUTOFFS.md)。

### 歌曲颜色与激奏组合

```text
/查曲 蓝色
/查曲 颜色=蓝/绿 激奏=JUST EX lv<=25 页2
/查曲 激奏=纯JUST
/查曲 激奏=混合
/查曲 激奏=JUST/JUST/COMBO
/查曲 激奏=包含全部JUST/COMBO
/问 MyGO有哪些带JUST激奏的歌
/问 找激奏顺序是combo/just/luck的歌曲
```

颜色支持红／蓝／绿／黄／紫，同维度任选，跨维度同时满足。单个激奏类型表示“包含”，纯类型表示所有段落同类，混合表示至少两类；斜杠序列精确匹配顺序与次数，`包含全部` 则不限制顺序。歌曲主表的激奏序列按原顺序显示，不从卡牌技能或谱面 Fever 区间推测。每页16首，下一页命令保留全部条件。歌曲列表与谱面详情在歌名前显示游戏内属性图标，歌名下方用紧凑小框显示激奏顺序及 JUST／COMBO／LUCK 三种游戏原生图标，ID／乐队位于左下角。属性图标暂缺时回退颜色文字；激奏图标暂缺时保留类型文字。数据未知明确提示。分数表同步展示属性图标与激奏顺序，但其筛选范围仍以分数表帮助为准。

数据来自 Haneoka 日服歌曲列表／详情与激奏枚举；启动后后台首次获取，此后24小时有效期、失败5分钟后重试，查询不触发全量下载。独立文件 `haneoka-song-traits-jp.json` 位于主缓存旁；不写入旧主缓存的歌曲行。缺失记录显示未获取、不参与对应条件筛选，刷新失败保留并标记旧缓存；`/数据状态` 可查看覆盖数、版本和本机获取时间。无需新增配置或 AI 密钥。

### 卡牌稀有度与技能

`/查卡` 查询角色卡，`/查支援卡`（别名 `/查SNAP`）查询 SNAP。条件查询始终返回卡框网格，即使只命中一张；明确 ID 才返回完整详情。每页16张，先匹配全部结果并按ID去重，再分页，显示总数、范围和保留条件的下一页命令。QQ当前每次回一张图，大列表需逐页查看。

```text
/查卡 SSR 颜色=黄色,蓝色 乐队=MyGO 角色=tmr
/查卡 BD
/查卡 LIVE=分数提升 击奏=JUST
/查卡 得意=MyGO
/查SNAP EX
/查支援卡 角色=tmr,skk 乐队=MyGO LIVE=技能延长
/查SNAP LIVE=LIFE回复 击奏=JUST
/查卡 51
/查SNAP 61
/查卡面 51
/查支援卡面 51
/问 MyGO的红色SSR角色卡有哪些
/问 角色=tmr LIVE=技能延长的SNAP有哪些
```

不同维度同时满足，同维度多选任意满足；多角色任意包含，得意乐曲标签要求全部包含且仅限角色卡。已核实角色卡 R/SR/SSR/BD（生日卡），SNAP另有EX；BD仅适用于角色卡。二/三/四星旧输入只作为R/SR/SSR别名保留。颜色支持红、蓝、绿、黄、紫；这是图标颜色称呼，未宣称为正式属性名称。

LIVE分类与击奏JUST/COMBO/LUCK独立。当前真实成员卡均为分数提升；SNAP另外有技能延长、LIFE回复、判定强化，不能把技能延长冒充加分。EX的两项LIVE支援同时保留，击奏不适用。原成员技能关键词反查继续可用，例如 `/问 SSR得分提升技能的成员卡`。

角色卡列表使用原卡面与类型图标；BD为粉紫至珊瑚红渐变框、SSR为渐变彩框、SR为金黄框、R为蓝框，不显示稀有度文字角标。三列网格仍每页16张，框内按队长/演出/激奏展示三项技能Lv.5数值与必要条件，框外保留ID。技能摘要读取 Haneoka 日服独立缓存，缺失或映射冲突不补造数值；SNAP列表采用同主题横向网格，稀有度框仅包卡面，独立技能区显示Lv.5基础技能类型、数值及必要触发/上限；成员条件加成在ID详情查看，外层蓝紫框统一卡面与技能，底部保留ID。框体是设计实现，并非已取得的官方卡框素材，不添加玩家等级/红点。成员ID详情以完整卡面配同款稀有度边框，并分区显示基本资料、属性条、队长/演出/激奏完整Lv.5技能、多语言标题与上游时间；SNAP详情独立展示完整横图、多人关联、百分比属性与全部演出/激奏支援技能（EX的两项演出支援均保留）。属性只展示已确认的Lv.1/Rank1（成员觉醒0次）资料状态，不冒称满级。独立卡面使用公开full版本，暂不选觉醒前后。缺资料、未知分类与不适用分别提示。见[字段、素材及缓存说明](docs/更新说明-成员卡与支援卡查询.md)。

已核实的新队长技能逐项标明加成对象，生日卡双效果激奏摘要保留增量和减伤条件，不把不同对象的加成合成无条件总值。列表遇到摘要缓存尚未覆盖的新卡时，会提前尝试刷新；来源失败后至少等待5分钟再试，保留旧资料。未知机制或两来源身份不一致时仍提示未确认，按ID查看完整技能。

### 谱面怎么看

主资料与图片独立选择：`OURNOTES_DATA_SOURCE` 默认 `yume`，可选 `haneoka` 使用固定 JP 数值及核对一致的中文。失败只用本来源已验证缓存。新模式暂缺得意乐曲标签的正式名称关联，相关筛选提示不完整，尚不建议切换生产；详情见 [Haneoka 主资料说明](docs/HANEOKA_CATALOG.md)。

榜线另可显式预览 `OURNOTES_CUTOFF_SOURCE=haneoka`，独立缓存与历史，不自动访问旧源。完整挑战序号和四服静态关联尚待核实，歌名／素材／歌曲 N 功能未通过切换验收，默认继续 `tracker`；见 [Haneoka 榜线说明](docs/HANEOKA_CUTOFFS.md)。

五批迁移尚未全部完成，旧分数表、装饰图标及未切换模块仍需原来源。各批状态与最终退役条件见 [迁移总结和网络出口](docs/HANEOKA_RETIREMENT.md)；草稿 PR／CI 通过不代表生产已换源。

完整谱面来源单独由 `.env` 的 `OURNOTES_CHART_SOURCE` 选择：默认 `moenotes`，设为 `haneoka` 后按固定日服版本读取，图片页脚显示 Haneoka JP。新旧缓存各自保留；Haneoka 请求失败只使用其已验证缓存并标注“旧缓存”，切回旧联网来源需人工改回配置。该项不改变主资料、分数表或榜线来源，现有指令用法保持。

完整谱面从**左侧第一栏底部的“起点 ↑”向上读**，到顶后接右侧下一栏底部，各栏从左向右接续。图中带栏号和阅读说明；左右位置与划键方向保持原数据含义。

当前是静态音符预览，长条按节点连线。纵向目标密度由每拍52逻辑像素提高到78；较长歌曲拆为六栏、短曲保留最多四栏，减轻长边缩放抵消间距的影响。实际像素增幅取决于曲长和统一图片预算，不保证所有歌曲固定增加50%；手机查看密集段时可打开原图放大。尚无局部放大、播放或变速模拟。JUST／COMBO／LUCK 使用游戏原生轮廓图标、类型文字与顺序箭头；图标在本机按需缓存，缺图仍保留文字。未指定难度时优先预览 EXPERT；音符文件不可获取时退回等级和 Note 信息。图片按查询生成，无需清空已有原始谱面缓存。

### 歌曲效率怎么看

`/查分数表` 默认在**同一张图左右并列自由和激奏两张效率榜**，每榜四难度混合、独立按每分钟单位综合力得分降序排列，每页各30条。同曲 EASY、NORMAL、HARD、EXPERT 独立计数；30条不代表30首。沿用现有配色、字体、封面、难度标识及三个数值区域。每行保留榜内序号，并标注跨两榜的页内选择号。

默认 Moenotes 来源在机器人上线时自动获取分数表数据，此后每300秒检查更新，查询也复用同一缓存。已验证计算源码指纹相同的上游发布自动接入，不再因提交编号变化停用。未知计算模型仍刷新基础事实；计算榜暂用最长24小时的完整兼容快照并注明旧数据，无有效兼容快照时明确提示暂不可用。新计算规则需验证后支持，不自动执行上游代码。显式 Haneoka 来源不启动该后台任务，无需新增密钥或配置。

输入`单人`／`自由`只显示自由榜，`多人`／`激奏`只显示激奏榜，也支持`场景=单人`等字段写法。任务词可直接输入`JUST`、`纯COMBO`、`混合`、`JUST/JUST/COMBO`、`包含全部JUST/COMBO`，不区分大小写，旧`激奏=`／`击奏=`兼容；有任务条件且未指定场景时只显示激奏榜，显式单人可覆盖。颜色可直接写`红 蓝 绿 黄 紫`，也保留`颜色=`／`属性=`，多选取并集。难度不限制大小写，如`hd,eX`。

分数表不再接受等级边界、Great／Just比例、三段名次、技能、时长口径、曲外耗时、前沿、目标评级、综合力或人数参数；提供这些条件会明确报错，不静默忽略。等级排行和普通`/查曲`的等级筛选仍保留。基本事实排行（Notes、等级、速度、长度、跳过得分）保持单表。

旧 `/查效率` 保留为兼容别名，帮助和翻页提示统一使用新命令。单曲详情不写难度时仍默认 EXPERT；也可用 `/查分数表 歌名 全难度` 查看该曲各难度的对照表。缺失时提示可用难度，不自动替换。同名或多候选需用 ID 明确选择。

```text
/查分数表
/查分数表 MyGO EX
/查分数表 暗黒天国
/查分数表 100043 EX
/查分数表 MyGO ex 页2
/查分数表 乐队=Ave Mujica 颜色=蓝 前10
/查分数表 乐队=MyGO 蓝 EX just 指标=score 排序=desc 前10
/查分数表 蓝/绿 纯combo
/查分数表 just/just/combo ex
/查分数表 EX 指标=score 排序=desc
/查分数表 前10 单人 hD,eX MyGO
/查分数表 多人 包含全部just/combo EX 前10
/查分数表 活动 前10
/查分数表 速度=最大BPM 前10
/查分数表 最短
/问 查一下分数表
/问 每分钟得分效率最高的前30首歌曲
/问 暗黒天国的效率怎么样
/问 查一下暗黒天国EX的meta
/问 哪些歌效率最高
/问 MyGO的EX效率前十有哪些
/问 just hd,ex 的分数表前十
```

这些问法本地解析，无 AI 配置或额度用尽仍可使用。完整参数组可任意移动；支持前10／20／30和页1～100，分页及续查保留全部条件。八类排行为效率、活动、速度、等级、Notes、最长、最短、跳过得分；`指标=score`保留单局单位分数排序，`eff`仍是效率。等级边界保持`lv>=、>、<=、<`及小数，不接受`lv=25`；未知或不适用条件明确拒绝。完整参数见[分数表合同](docs/META_OPEN.md#参数合同)。

分数表与查曲共用乐队、颜色／属性及五种激奏规则：包含、纯类型、混合、按顺序及重复次数精确匹配、包含全部类型。颜色多选为 OR，不同维度为 AND。先按歌曲属性筛选，再逐条检查谱面难度和等级，最后排序分页；指定单曲也执行全部条件。只有当前筛选需要的资料缺失才排除，并分别说明缺少资料的歌曲数和谱面数。完整名称和 ID 优先于条件解释；未知 Note 显示“暂无资料”。

事实和统计来自[Moenotes公开快照](https://storage.bdon.moe/moenotes/music-data/music-data.json)，标明**TW共通参考**。台日基本共通按维护者确认采用，尚未逐字段证明日服一致。两个计算场景共用一份快照，分别取对应统计，固定普通全队5秒加分技能各100%、Great=0、BGM长度＋曲外30秒；激奏固定全Just、三段第1。幸运取已发布seed均值，**不保证玩家游戏实际得分**。单位是分／综合力、分／综合力／分钟，原始值排序；详情相对效率以各自完整比较池最高效率为基准。

活动排行固定SS目标，显示均值估算所需综合力；激奏按5人同分房间，自由用单人阈值，不显示可调综合力的达标概率。长度默认BGM，缺失时回退谱面并注明；N/s单独使用第一Note到最后判定Note跨度。未知数值不补0，基础事实不依赖统计齐全，新源独有歌曲可直接选择。具体固定模型与内部对拍见[计算说明](docs/META_OPEN.md#计算与排序)。双榜可用`/下一页`同步翻页，`/选 数字`按图片上的选择号进入相应场景详情，后续`/详情`、`/难度 EX`保留该场景。

公开分数表无需密钥，独立缓存`moenotes-music-data-v1.json`，每300秒按需条件重验证，故障旧缓存最多24小时并标记；HTTP发布头、本机获取及验证时间分别记录，不冒称统计生成时间。`OURNOTES_META_SOURCE=haneoka`可显式恢复旧实现，旧缓存保留。图片、完整文字及失败回退消费同份捕获结果；QQ最多五条预算，仍超限明确要求前10／拆开，不截数据。

`/查榜线`另有正式开放平台适配，默认来源仍`tracker`。维护者在安全配置提供最低rankings权限Secret，完成四服覆盖、Top100、时间头和故障恢复认证验收后才切`OURNOTES_CUTOFF_SOURCE=open`；活动发现／素材与本地历史继续必要例外。正式历史使用独立v2库，来源切换处断线，旧库可回退。日调用数字不作为拒绝或降低现有采样频率的理由；目前尚未认证启用或部署。见[启用与回退](docs/META_OPEN.md#配置启用与回退)。

### 连续查询

先查询歌曲、成员卡、SNAP 或分数表列表，再单独发送 `/下一页`、`/上一页`、`/选 2`、`/详情` 或 `/难度 EX`。编号对应当前页，分数表每项同时记录歌曲、scoreId和难度；续查保留全部计算、筛选和排序条件。`/问 下一页`、`/问 第三个`、`/问 选二`、`/问 看详情`、`/问 换成 HARD` 使用同一套本地操作，不调用模型。多项列表须先选择再看详情或切难度。

上下文按平台、群／单聊、会话和用户隔离；10 分钟没有成功续查或机器人重启后失效。资料或昵称版本更新后需重新查询。只有 QQ 接口确认发送成功才建立或推进上下文；发送失败、不明或请求取消不会推进。同消息多个列表没有默认上下文，“查列表＋下一页”须分开发送。完整新查询使用自己写明的条件；榜线省略服务器始终为日服。

## 快速开始

榜线历史与周期采样配置见 [历史采样运维说明](docs/CUTOFF_HISTORY.md)。默认开启查询历史写入，周期采样需显式启用；四服发布配置为每 300 秒采样、长期保留，磁盘可用空间低于 512 MiB 时暂停。数据从启用后积累，不补造过去。

需要 **Python 3.10 以上**。图片绘制还需要可用的中日韩字体，例如 Windows 微软雅黑或 Noto Sans CJK；缺少字体时会记录原因并退回文字。本项目不附带字体文件。

以下命令适用于 Windows PowerShell，在项目根目录执行。发布包名为 `taki-ournotes-bot`，兼容命令名 `ournotes-bot` 和模块名 `ournotes_bot`。

### 先在本地查资料

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ournotes_bot.main --help
.\.venv\Scripts\python.exe -m ournotes_bot.main sync
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查曲 迷星叫
.\.venv\Scripts\python.exe -m ournotes_bot.main query 查卡 SSR
.\.venv\Scripts\python.exe -m ournotes_bot.main repl
```

`--help` 不需要 QQ 凭据或缓存；`sync` 下载资料并构建技能索引，首次使用需要网络。`query` 和 `repl` 可在不连接 QQ 的情况下测试文字查询，输入 `exit` 退出交互台。图片及部分卡牌详情按需获取，不意味着所有查询都能完全离线运行。

### 再连接 QQ

首次配置可从模板建立 `.env`，保留已经存在的文件：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

填写 `QQ_APP_ID`、`QQ_APP_SECRET`；也可以使用已有的用户环境变量。不要公开 `.env` 或真实密钥。平台接入和测试步骤见 [LOCAL_QQ_TEST.md](LOCAL_QQ_TEST.md)。

```powershell
.\deploy\start-bot.ps1
```

`start-bot.ps1` 会识别已有自动更新管理状态，避免再启动一个实例。`setup-menu` 可单独安装单聊菜单和单聊／群聊快捷指令面板，两个面板均提供 `/查榜线`；会修改 QQ 配置，内容一致时不重复写入。应在运行版本已支持新指令后更新面板；基础查询无需先安装菜单。

## 自然语言、数据与运行设置

### `/问` 的工作方式

单个字段直接给文字短答，例如 `/问 迷星叫 EX 多少 Note`、`/问 迷星叫是什么颜色`、`/问 迷星叫有哪些难度`、`/问 MyGO 有多少首歌`、`/问 角色卡 1 的 LIVE 技能`。数量按完整筛选集合计算，资料覆盖不足时说明已确认数量；Note 缺失显示暂无资料，源确认的零仍显示 0。成员卡和 SNAP 同号时必须说明类型。列表图文使用相同的页内编号。

旧版完整刷新曾重写的缓存，需要新版重新获取来源后才能确认 Note 的真实零值；来源未恢复时继续显示未知。

常见歌曲等级、实体列表、成员技能、支援卡和稀有度问法在本地解析，**不调用 AI、不消耗 AI 额度**。普通直接指令也不调用大模型。需要模型辅助的受支持问法，才使用可选 AI 配置：

```dotenv
AI_API_KEY=你的API密钥
AI_MODEL=deepseek-chat
AI_BASE_URL=https://api.deepseek.com
AI_DAILY_LIMIT=100
```

模型仅生成受限的结构化动作；实体和技能关键词必须能在用户原问题及本地资料中核对，程序再查询缓存并生成图文。文字和图片使用同一份 `QueryResult`，不会把模型自由文本当作答案。

需要模型时，程序先在本地判断歌曲、谱面、成员卡或支援卡能力，只向模型披露该能力的字段规则；本地无法判断能力时，才额外调用一次轻量路由。只有结构化参数可修复时允许再规划一次，单条查询硬限制为最多 3 次模型调用、2 次本地工具执行和 1 次修复；空结果、歧义、不支持、未知实体、数据不可用、超时和提供方故障都会立即终止，不会自动删减条件、改换实体或重试网络请求。

每日额度按北京时间自然日持久保存，重启不清零；**每次真正发起模型请求前分别计数**，所以“模型路由＋专项解析”计 2 次，发生一次参数修复再计 1 次，提供方失败也计入。成功结果和确定性失败会在当前进程内缓存；确定性失败使用短期缓存，数据或昵称版本变化后失效，网络、额度和统计故障不会缓存为业务结论。无密钥、额度用尽或额度记录不可用时，普通查询与本地可解析的 `/问` 仍可用。

复杂问题的文本会发给所配置的 AI 服务，请勿包含私人信息。机器人日志不记录 `/问` 正文；独立的 `ai-metrics.json` 只按北京时间日期累计分路结果和提供方实际返回的 Token 用量，不写入问题正文、用户／群标识、模型完整响应或数据库内容。统计文件损坏或不可写时只停用统计，不影响查询。

`/调试数据` 显示本次进程启动后的两个内存计数：模型服务成功返回 JSON 对象时，“成功 API 调用”加 1；一条使用了模型且最终实际输出检索记录的 `/问` 完成时，“产生实际检索内容的 AI 查询”加 1。路由和解析分别调用模型时，前者可增加多次而后者只增加一次；空结果、请求澄清、未知对象、不支持、数据不可用、页码越界、提供方失败和缓存命中都不会增加有效检索数。重启机器人会清零，不写入统计文件。

### 缓存与昵称

`sync` 同步歌曲、角色、成员卡、SNAP等基础资料，并并发获取两类卡的详情构建分类索引。运行中的机器人每六小时尝试刷新；旧缓存升级失败仍可查已有资料，分类索引不完整会提示暂不可筛选。无需新配置，新增信息保存在旧读者可忽略的顶层扩展中，详情失败保留上次有效数据。

`/数据状态` 显示的是**本机最近一次成功保存资料的时间和状态**，不是上游更新时刻，也不是持续在线证明。

人工确认的昵称维护在 [query_aliases.json](query_aliases.json)，支持歌曲、乐队、角色和成员卡别名；角色昵称也可用于支援卡。未核实、歧义或目标不存在的昵称不会随意映射。新增别名时参考[昵称词表维护规范](昵称词表维护规范.md)。

### 常用配置

完整模板见 [.env.example](.env.example)。修改设置后需重启生效。

| 配置 | 默认或用途 |
|---|---|
| `OURNOTES_CACHE_FILE` | 源码运行时默认 `data/ournotes-cache.json` |
| `OURNOTES_CACHE_TTL_HOURS` | 主缓存有效期，默认 6 小时 |
| `OURNOTES_ALIAS_FILE` | 可选自定义昵称表路径 |
| `OURNOTES_AI_QUOTA_FILE` | 默认在缓存旁保存 `ai-quota.json` |
| `OURNOTES_AI_METRICS_FILE` | 默认在缓存旁保存匿名分类统计 `ai-metrics.json` |
| `OURNOTES_QUERY_CONCURRENCY` / `OURNOTES_QUERY_QUEUE_LIMIT` | 默认同时准备 2 条回复，另有 4 条等待；满额时提示稍后重试 |
| `OURNOTES_MULTI_COMMAND_LIMIT` | 每条消息默认最多执行 4 条指令，保留超限提示的位置 |
| `OURNOTES_REPLY_ORDER` | 默认开启，按消息到达顺序发送；等候超过 60 秒会允许先行发送 |
| `OURNOTES_QQ_GATEWAY_HOST` | 默认 `api.bot.qq.com`，用于替换服务端下发的旧网关域名；置空关闭改写 |
| `OURNOTES_UPDATE_NOTICES` | 默认开启更新群通知；设为 `0` 可关闭 |

无论回复顺序开关如何，同一条消息内的多条指令始终按书写顺序回复。日志记录耗时、回复大小及发送结果；直接命令正文最多记录 60 字，`/问` 只记录字数，群发现逻辑不保存聊天正文。

源码运行时配置和数据放在项目根目录。普通 Python 包安装从启动目录读取 `.env`，默认数据目录为 Windows 的 `%LOCALAPPDATA%\ournotes-qq-bot` 或 Linux/macOS 的用户数据目录。相对缓存、额度和统计路径按配置目录解析，避免把运行数据写进 Python 安装目录。

## 自动更新与群通知

Windows 单实例可启用[五分钟自动更新](自动更新说明.md)：功能分支／PR → CI → 合并 main → 主分支 CI → 独立环境验证 → 切换运行版本。首次需单独初始化并安装任务，安装 Python 包不会自动开启部署。

Linux（Ubuntu 24.04、x86_64、Python 3.12）另有[离线发布与更新协议](deploy/LINUX_OFFLINE.md)：CI 从同一 Git 提交归档构建源码和安装包，固定依赖与哈希，在断网环境验证全新安装及回归；main 全部检查成功后发布提交专属 Release。服务器在停旧服务前下载、校验和离线准备候选版本；下载线路故障会切换官方资产 API，保留断点并按有界退避继续自动尝试，提供只读中文进度。校验、安装、兼容或启动失败仍阻止更新，保留备份、健康检查与回退。独立控制器须单独审核、安装；合并代码或发布 Release 不代表控制器已替换、服务器已上线或采样已启用。

更新前旧版继续运行；确认新实例连接 QQ 后才完成切换。失败时按原流程恢复上一运行版本，本地有未提交修改时暂停更新。运行版本共享配置、缓存和 AI 额度，回退代码不回退这些数据。

**群通知仅在版本切换完成后生成并发送。**机器人读取这次发布的公开提交标题、变动文件和[更新日志](更新日志.md)新增内容，使用 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 配置的 DeepSeek 接口生成最多 120 字、面向群友的简短说明。只有内部维护而没有群友可感知的变化时跳过公告；技术细节和过长内容也不会发到群里。每个版本只调用模型一次，报告保存后供各群共用；没有密钥、生成失败或缺少可靠变更资料时跳过本次通知，不发送旧内容。每个群每个版本只尝试发送一次；发送失败或回执不明确时不自动重发，可能漏掉当次通知。成功以 QQ 返回的有效消息 ID 为准。

群标识通过实际收到的群消息及入群事件自动登记。首次启用前未记录过的旧群，先 **@Taki 发送一次 `/数据状态`** 即可登记，之后无需每次触发。关闭群内主动消息权限即可停止接收；接收范围为已记录且允许主动消息的群，接口权限和发送结果仍由 QQ 校验。

发送记录保存在缓存旁的 `update-notices.sqlite3`，仅在本机使用，不进仓库。不要删除记录来补发通知。普通本地查询或未经过更新器的启动不会仅因启动而广播。

## 后续开发方向

这是基于当前实现整理的路线图，**不是已开放功能，也不是一次性开工承诺**。技能详情、成员技能反查、两类卡牌稀有度筛选、谱面方向修复、版本更新群通知已经完成，不再列作待开发。

### 优先做：现有功能的准确性与使用体验

| 工作 | 解决什么问题 | 完成标准 |
|---|---|---|
| 数值口径扩展 | 在已区分 Note 缺失与零的基础上继续核实其他数值、资料最大值和玩家培养值 | 确认字段和显示口径后，再开放依赖它们的排序／比较 |
| 同义问法覆盖 | 部分等价的中文等级描述仍会进入 AI 分支，增加配置依赖和调用成本 | 覆盖同义词、词序和难度表达，在已有测试中验证本地处理且筛选含义一致 |
| 谱面局部阅读 | 长图在手机上不易看清，希望按段查看或放大 | 局部和全谱方向一致，保留跨段长条上下文，不以绘图节点数冒充判定数 |
| 通知状态与维护诊断 | 方便知道群是否登记、通知是成功、拒绝还是结果不明 | 提供受控的维护入口和清晰状态，不向群友暴露内部标识，不盲目补发 |

### 接着做：有数据依据的查询扩展

| 候选方向 | 数据前提与边界 |
|---|---|
| ON 专属歌曲资料 | 先确认乐队／属性加成条件、激奏分段类型和坐标、适用模式与版本；现有演唱乐队标签不能直接当作加成条件，不能照搬 Garupa 机制 |
| 两张卡并排对比 | 使用同口径数值、技能和明确的缺失提示；不据此替玩家作培养或抽卡决定 |
| 支援效果关键词、更多排序 | 已有LIVE/击奏分类与组合筛选；任意效果关键词、等级区间和自定义排序仍需定义确定语义，不悄悄放宽条件 |
| 本地资料变化摘要 | 比较资料同步前后快照，列新增歌曲／卡牌或已确认字段变化；这是资料更新，区别于已经实现的程序版本通知，首次建立基准不把全库当新增 |
| 活动与卡池资料 | 先核实名称、时间、时区和来源，再考虑提醒；目前相关命令仍是未开放占位 |

### 先调查：长期方向与依赖

| 方向 | 当前缺口 | 推进顺序 |
|---|---|---|
| 积分档线与历史走势 | 已接入活动歌曲 Top 100 观测；活动积分档线及历史走势未实现 | 继续单独核实来源、授权和采样条件，不从歌曲分数推导积分线 |
| 预测线 | 尚无可验证的历史样本和预测误差记录 | 实况与历史稳定后再评估；届时与当前线同屏但明确区分，不能承诺“安全线” |
| ON 限定短聊天／新手问答 | `/问` 目前是查询入口，尚无独立聊天和审核知识库 | 先积累有来源的机制资料，再设计独立入口、短回复、范围限制和费用上限 |
| 资料采集与攻略知识库 | 尚无来源白名单、审核流程或后台采集任务 | 由 Taki 获取允许来源，去重后进待审核池；确认版本、条件与证据后才能进入答案 |

组队／约练留言、用户自报练习记录等保留为后续候选，先看实际需求与维护成本。现阶段提供有上游依据的歌曲效率排序与活动挑战歌曲 Top 100 观测，继续不支持泛攻略、配队推荐、其他排名分析、预测、积分档线、账号操作和代练；列入展望不改变这些边界。

建议下一批先处理**同义问法、缺失值与简洁回复**，同时整理 ON 新字段的可得性表；再按真实群使用反馈选择局部谱面或卡牌对比。每批单独交付，数据调查没有结论时明确留空，不拖住已经可以完成的小改进。

## 验证与贡献

提交和发布以完整离线测试及 Python 3.10／3.12 的测试、打包 CI 为自动门槛。测试数量会随合并和拆分变化，不在文档中手工维护固定数字。自动测试不连接真实 QQ，也不调用收费模型。

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

CI 在没有真实凭据的环境运行测试、构建 wheel 和源码包，并检查昵称表、更新文案及文档随包提供，排除运行缓存和私有数据。另有 Linux 离线包构建与断网安装检查；main 的发布步骤须等所有验证成功。已有发布产物可用 `python scripts/check_release_artifact.py dist` 检查。

人工只确认自动测试无法证明的真实链路：QQ `@` 触发、消息和图片送达、手机端可读性、同步后的数据完整度，以及本次确实改到的模型或更新通知链路。固定冒烟和按改动范围追加的专项步骤统一维护在 [QQ 接入与验收](LOCAL_QQ_TEST.md#4-在-qq-中验收)，其他文档不再复制命令清单。

Taki 与独立的 X 推文翻译机器人是两个项目，维护时不要混用目录或停止另一方进程。本项目代码沿用原仓库的 [MIT License](LICENSE)，游戏和第三方数据、素材不在此许可范围内。

图片输出统一按体积与尺寸预算编码，必要时等比缩小，保留整张内容；图片上传等待为30秒，上传失败退文字，消息发送结果不确定时不自动重发。本次卡牌大更新的来源、维护边界和验收记录见 [2026-09-28 更新报告](docs/RELEASE_2026-09-28.md)。
