# L2 Scripts — 仓库级执行工具

## Purpose

存放需要手动、CI 或 Windows 定时任务执行的仓库级工具。

这些工具位于机器人常规查询进程之外，负责版本更新、发布产物检查和开发验收。它们按执行方式集中在 `scripts/`，不代表内部工具属于同一个业务系统域。

## Responsibilities

- 检查候选版本、CI 状态和本地工作区条件。
- 准备、验证、切换及回退 Windows 运行版本。
- 安装或停用 Windows 自动更新定时任务。
- 检查 wheel 和源码包的必要内容及隐私边界。
- [verify_meta_reference.py](verify_meta_reference.py) 比较固定本地快照和独立上游环境生成的参考；不生成自己的oracle，不联网，版本／数值／顺序／前沿验收见[META_OPEN](../docs/META_OPEN.md)。
- [check_installed_query_upgrade.py](check_installed_query_upgrade.py) 在隔离安装中核对模块、彩蛋图片哈希与独立分发、默认别名、运维说明和临时历史库，阻断网络；CI 对 wheel 与 sdist 分别执行。
- 使用本地公开缓存离线生成图片预览，支持渲染人工验收。
- [preview_event_cutoffs.py](preview_event_cutoffs.py) 读取脱敏活动取样和本地素材，生成榜线趋势总览／单曲／附近名次表及合成压力图；输入格式与命令见 [功能说明](../docs/EVENT_CUTOFFS.md#离线验证)，不联网或发送 QQ。
- [preview_cutoff_trends.py](preview_cutoff_trends.py) 用固定合成数据生成趋势、附近／区间表、完整100名分页及430px预览；不联网，输出不提交。
- 为手动操作、CI 和计划任务提供稳定的命令行入口。

## Non-Responsibilities

不实现歌曲、卡牌、谱面和自然语言查询，不处理日常 QQ 消息，也不把测试通过等同于真实生产可用。

本目录不是通用脚本堆放区。仅服务单次临时排查、没有长期复用价值的脚本不应加入仓库。

`preview_visuals.py` 属于 Rendering 的验收工具；更新和发布相关脚本服务跨目录运维主题。Scripts 维护工具入口、内部协作、执行条件和共同边界，渲染语义与操作步骤由对应地图和专项说明维护。

## Inputs / Outputs

输入包括命令行参数、本地 Git 状态、GitHub CI 状态、发布包、公开缓存副本、项目配置及 Windows 任务状态。

输出因工具而异：

- 更新器输出候选版本环境、部署状态、事务记录和运行进程。
- 任务安装脚本创建或停用 Windows 计划任务。
- 发布检查器输出通过结果或明确失败。
- 图片预览工具输出样图、缩略图、概览和输入哈希清单。

## Core Contracts

- 更新器只部署指定仓库 `main` 上通过要求检查的提交。`Updater.once` 先检查分支、干净工作树、预期 origin 和 HEAD，再处理未结束事务；恢复优先于拉取候选，但不绕过工作区保护。
- 正常候选准备与验证阶段不停止当前运行版本；切换失败时尝试恢复上一版本，恢复自身也可能失败。
- `start` 根据 `ournotes_bot.qq` 的“已上线”日志生成 ready 标志，并检查进程仍存在。网关就绪不证明真实查询、图片上传或群消息送达。
- 发布包必须包含必要代码、别名和文档，并排除密钥、缓存、日志、数据库及媒体文件。
- 图片预览只读输入缓存，禁止联网、QQ、AI 和数据刷新；输出必须写到独立目录。
- 各工具的副作用不同，不能因为都位于 `scripts/` 就视为同等安全的只读命令。

## Internal Tools

### `update_bot.py`

Windows 单实例更新器。检查远端提交及对应 CI，在独立版本目录中安装和验证候选版本，管理运行进程、版本切换、事务恢复和失败回退。

更新主路径为：独占保护 → 工作区／仓库身份检查 → 若有未结束事务则恢复并结束本轮 → 校验已有活动版本，必要时启动它 → 拉取候选与检查快进关系 → 检查问题提交标记及对应 CI → 隔离安装和离线验证 → 再核对本地 HEAD → 写事务 → 停旧启新并确认网关 ready → 再核对工作区并快进 → 写部署状态 → 删除事务。不同模式只走其中一部分。

`ci_passed` 只接受目标 SHA 对应、来自 `main` push 的最新 Checks 运行及其尝试，要求完成且成功，并包含 Python 3.10／3.12 的成功任务；不以更早的成功运行代替最新失败。`prepare` 用 `git archive` 建立独立源码及虚拟环境，安装项目，执行离线测试和 CLI 帮助检查；`validation_env` 清空 QQ／AI 凭据并排除私人缓存配置。这是隔离验证环境，不是恶意代码安全沙箱。

| 模式 | 机制边界 |
|---|---|
| `--status` | 读取最近检查记录，不做在线诊断或工作区资格检查；构造更新器仍可能创建状态目录。 |
| `--check` | 通过工作区保护后检查候选与 CI，不启动、切换或恢复实例；遇未结束事务暂停。仍可能 fetch、创建目录、写锁、状态记录与日志。 |
| `--start` | 通过保护后复用已保存活动版本，拒绝重复实例；若有未结束事务，先尝试恢复。正常启动分支不 fetch 候选。 |
| `--once`／`--initialize` | 检查并按条件准备、切换版本；`--initialize` 允许在尚无状态时以当前 HEAD 快照作为前一版本，否则尚未初始化会暂停。 |
| `--retry` | 允许候选跳过此前的 `rejected` 拦截，其他身份、CI 和验证条件仍适用；通常与执行更新模式组合，不是通知重试开关。 |

命令和 Windows 任务操作见 [自动更新说明](../自动更新说明.md#日常操作)。内部运行子进程由 `run_bot` 覆写共享配置根、按版本 source 加载应用，并接入原 QQ 日志通道；共享配置根与代码快照位置是两个不同概念。

### `install-update-task.ps1`

Windows 计划任务安装入口。注册或停用自动更新任务，保存 Git 可执行文件位置，并调用 `update_bot.py` 定期检查版本。

### `check_release_artifact.py`

发布产物检查器。检查 wheel 和源码包是否包含必要代码、别名与文档，同时阻止私有配置、运行缓存、日志、数据库和未批准媒体进入发布包；唯一静态媒体例外为随包必需的 `ournotes_bot/platforms/qq/assets/card-947.jpg`。由 CI 和人工发布检查调用。

### `preview_visuals.py`

Rendering 的离线验收工具。读取公开缓存副本，生成歌曲、谱面、卡牌和分数表等图片样例，用于检查布局、长文本、缺图和手机尺寸效果。它不启动机器人或修改输入缓存。

## Dependencies

- 更新工具依赖 Git、GitHub、Windows 进程与计划任务、Python 环境以及应用启动和就绪协议。[Deploy 启动入口](../deploy/L2.md)是更新器的调用方，委托它执行受管启动。
- 发布检查依赖 `pyproject.toml`、`MANIFEST.in`、构建产物和 GitHub Actions。
- 图片预览依赖 Data、Query、Rendering 的现有代码、Pillow 和本地公开缓存。
- Scripts 可以调用仓库其他系统域；正常业务代码不应反向依赖这些命令行脚本。

## State / Side Effects

`update_bot.py` 会联网、创建版本环境、写入更新状态、停止或启动进程，并在成功后快进本地工作区。

### 部署状态协议

`Updater` 是部署状态与切换事务的写入／恢复方，实际规则见 [update_bot.py](update_bot.py) 的 `validate_release`、`deploy`、`restore`、`once`。

| 记录 | 关键身份与用途 |
|---|---|
| `data/updater/state.json` | `active` 为保存的活动版本，`previous` 为上一版本，`rejected` 为暂停自动重试的候选 SHA。 |
| 版本记录 | `sha` 标识提交，`source` 标识代码快照目录，`python` 标识运行解释器；不能仅凭本地 HEAD 推断运行版本。 |
| `transaction.json` | 保存切换前的 `previous`、`candidate` 和 `old_state`，在停旧实例之前写入，供中断恢复使用。 |
| `settings.json` | Git 可执行文件位置由任务安装脚本记录；更新器读取并可回退到 PATH，通知的事实读取要求有效的已保存 Git 路径。它不是 Updater 独占写入的文件。 |

`validate_release` 检查 SHA、source 位于本项目 releases 目录且存在，以及解释器路径有效；解释器须在 updater 目录内或为根目录 `.venv` 的解释器。正常切换先写事务，再启动候选、快进工作区，以 `active=candidate`、`previous=原活动版本`、清空 `rejected` 写状态，最后删除事务。

准备失败且已有状态时写入候选 `rejected`；旧实例不因此停止。`restore` 校验并启动事务中的前一版本，在 `old_state` 上恢复 `active`、标记失败候选，然后写状态并删除事务；它不倒退 Git 历史。恢复失败可能保留事务，不能承诺总能恢复成功。

JSON 文件各自用临时文件替换完成原子写入，但状态写入、事务删除和 Git 快进不是跨文件的同一次原子提交。中断时必须结合事务判断，不能把单独存在的状态或 ready 文件当作已完成部署。

Deploy 仅看状态文件存在性选择分流；通知是下游读者，读取条件见 [更新通知机制](../docs/更新通知机制.md#触发条件与处理流程)。更新器不直接调用公告发送，也不拥有通知账本。状态记录不证明进程在线或 QQ 消息已送达。

`install-update-task.ps1` 会修改 Windows 计划任务和本地更新器设置。

`check_release_artifact.py` 只读检查现有发布包。

`preview_visuals.py` 只读输入缓存，但会在指定输出目录生成图片与检查清单。

## Failure / Degradation Boundaries

发布包检查或图片预览失败时直接报告问题，不修改生产运行状态。

更新准备失败时保留当前运行版本；切换失败时尝试恢复上一版本。无法确认工作区、进程、事务或仓库身份时暂停，不通过重置、覆盖或重复启动绕过问题。

已标记的问题提交暂停自动重试；新候选或现有 `--retry` 可进入后续资格检查。恢复再次失败时保留事务等待处理，不伪报成功。成功快进后又在状态提交阶段中断，或恢复了旧运行快照时，工作区 HEAD 与活动版本可能不同；不能按 HEAD 覆盖运行状态。

代码回退不回退共享配置、游戏缓存、AI 额度或通知 SQLite；前一代码版本须能读取已写入的共享数据。版本快照不会自动清理。操作排查见 [自动更新说明](../自动更新说明.md#常见问题与排查)。

计划任务安装失败不应修改机器人源码或伪报自动更新已经启用。

## Relevant Tests

- [test_updater.py](../tests/test_updater.py) 验证更新资格、脏工作区保护、版本准备、切换、回退和事务恢复。
- 资格与准备：`test_dirty_worktree_never_fetches_or_stops`、`test_ci_requires_exact_sha_and_both_jobs`、`test_ci_latest_failed_run_blocks_older_success`、`test_validation_environment_drops_credentials`、`test_build_failure_does_not_stop_live_bot`。
- 切换与恢复：`test_success_only_fast_forwards_after_ready`、`test_start_failure_rolls_back_without_rewinding_git_or_data`、`test_interrupted_transaction_restores_before_fetch`、`test_changed_head_cancels_switch`、`test_rejected_commit_is_not_retried`。
- 模式与保护：`test_pending_ci_and_check_only_do_not_deploy`、`test_start_only_reuses_existing_instance`、`test_atomic_state_and_exclusive_lock`；通知测试按 [专题入口](../docs/更新通知机制.md#文件与测试导航)选择。
- [checks.yml](../.github/workflows/checks.yml) 构建发布包并调用 `check_release_artifact.py`。
- Rendering 相关测试验证绘图逻辑；`preview_visuals.py` 的最终结果仍需人工查看。
- 真实 Windows 定时任务、GitHub 网络、QQ 网关和生产切换不由普通离线测试证明。

## Current Implementation and Boundary

当前目录包含四个长期工具。更新、任务安装和发布检查主要服务跨目录运维主题；图片预览服务 Rendering。

Scripts 是仓库级执行入口。跨目录操作由运维指南串联，Rendering 地图维护绘图语义。新增工具时，应先确认其长期用途、调用者、副作用和所属职责，再决定是否放入本目录。

向上阅读：[仓库 L1](../L1.md)、[仓库开发规则](../AGENTS.md)、[开发导航](../docs/DEV_GUIDE.md)。

## Linux 离线发行工具

`build_offline_release.py` 从精确 Git 提交归档解包的源码和锁文件构建完整 wheelhouse，排除工作目录未跟踪源码和遗留产物；`check_offline_release.py` 在 Linux 隔离网络命名空间验收全新安装和回归；`publish_offline_release.py` 仅在 main 的成功 Checks 中发布提交专属 Release，拒绝覆盖不同资产。CI artifact 与 Release 是发布证据，不代表服务器验收。受信控制器及迁移契约见 [Linux 离线发布](../deploy/LINUX_OFFLINE.md)。
